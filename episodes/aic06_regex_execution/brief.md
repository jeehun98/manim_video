# AI 컴파일러 06 — 같은 정규식인데 왜 실행 속도는 다를까?

현재 단계: 사용자 확정 대본 30구간과 종료 시각을 반영한 154초 영상 제작. 실제 음원 파일 대조는 미실시. 아래 초기 검토·v2 기록은 제작 이력이다.

## 학습 목표와 중심 주장

수용 언어가 같아도 실행 알고리즘과 비용은 다를 수 있다. 경로의 반복 탐색→같은 위치의 도달 상태 병합→상태 집합 간 전이의 사전 계산 순으로 비용 배분의 차이를 설명한다. 이전 영상 복습과 다음 영상 예고 없이 독립적으로 완결한다.

## 장면 설계

| 장면 | 주장 | 화면 계획 |
|---|---|---|
| 01 | 같은 규칙도 계산량은 다르다 | `(a|aa)*b`, 동일 입력·세 실행 방식 |
| 02 | 실패 입력에서 중복 경로가 드러난다 | `aaaaac`, 1/2 분할 8개, 탐색 트리와 입력 위치 |
| 03 | 경로 수와 도달 상태 수는 다르다 | 같은 `(상태, 입력 위치)`로 합류하는 경로, 상태 집합 갱신 |
| 04 | 전이를 미리 준비할 수 있으나 공간 비용이 있다 | NFA 집합→DFA 상태, 전이표, 최악의 상태 증가 |
| 05 | 모델과 실행 알고리즘을 구분한다 | 경로 탐색·상태 병합·사전 계산 비교 |
| 06 | 계산 시점과 저장의 선택이 비용을 바꾼다 | 준비·저장·재계산 비용, AI 비용 모델 연결 |

## 수학적·구현 조건

- 고전적 정규식의 전체 문자열 수용 여부만 비교한다. 역참조·캡처 결과·매치 우선순위는 범위 밖이다. 수용 여부가 같다고 이 부가 결과까지 같다고 주장하지 않는다.
- `(a|aa)*b`와 `a*b`는 같은 언어이다. 입력 `aaaaac`는 a 5개와 c 한 개이며 모두 거부해야 한다. c를 입력 알파벳에서 제외해 오류 처리하는 대신 거부 전이로 처리한다.
- 분해 수 T(0)=1, T(1)=1, T(n)=T(n-1)+T(n-2); T(5)=8, T(9)=55. 이는 길이 n의 a 구간을 1/2로 완전히 나누는 방법의 수이며 엔진의 호출 횟수나 실행 시간 실측과 동일하지 않다. 화면에서 점화식을 보조로 제시하고 내레이션은 두 경우를 합하는 직관에 집중한다.
- 지수적 탐색은 메모이제이션·사전 실패 검사·식 단순화가 없는 경로 열거 방식의 최악 사례다. 특정 최신 엔진이 이 식에서 반드시 느리다고 일반화하지 않는다. 실제 시간 비교 그래프나 특정 언어 순위는 실측 없이 만들지 않는다.
- 상태 병합은 **같은 입력 위치의 같은 NFA 상태**가 기준이다. 서로 다른 입력 위치는 합치지 않는다. ε-closure는 최초 상태 집합과 매 문자 이동 직후 계산하며 중복 방문을 제거한다. 논리적으로 함께 유지하는 것이 하드웨어 병렬 실행을 뜻하지 않는다.
- Thompson NFA 크기를 m, 입력 길이를 n이라 하면 상태·전이 방문 중복 제거를 사용한 기본 시뮬레이션은 O(mn) 시간, 실행 상태 집합 O(m) 공간이다. 정규식 고정 시 입력 길이에 O(n)이며 모든 정규식 크기에 독립적인 상수 시간이라는 뜻이 아니다.
- DFA는 NFA 집합을 상태로 표현하는 부분집합 구성으로 얻는다. 전이표가 준비되고 고정 알파벳의 상수 시간 조회를 가정하면 매 문자 O(1), 전체 O(n). 준비 비용은 이 실행 시간에 포함하지 않는다. m개 NFA 상태의 부분집합은 최대 2^m개이며 일부 언어에서는 지수적 증가가 필요하다. 도달 불가능 집합은 생성할 필요가 없다.
- **현재 예시 자체의 큰 DFA를 그리지 않는다.** `a*b`의 완전 DFA는 {a,b,c}에서 시작/a루프, b뒤 수용, 거부의 3상태로 충분하다. 일반적인 최악의 증가와 이 예시를 명확히 구분한다. 부분집합 구성 직후 상태 수와 최소 DFA 상태 수 역시 다를 수 있다.
- lazy DFA/전이 캐시는 필요한 집합·전이를 실행 중 생성할 수 있다. DFA가 항상 모든 집합을 선행 생성한다거나 항상 가장 빠르다고 주장하지 않는다.
- NFA/DFA는 모델, 백트래킹/상태 집합 시뮬레이션은 실행 전략이다. 백트래킹을 NFA와 별개 표현력의 기계로 그리지 않는다.
- AI 연결은 사전 계산·중간 결과 저장·재계산·메모리 접근의 비용 선택이라는 공통 관점이다. NFA→DFA와 특정 AI 최적화를 일대일 대응시키지 않는다. 최적화의 합법성이 먼저 충족되어야 한다.

## v2 피드백 반영

- 엔진 구현이 다양함을 본문에서 명시한다. 모든 엔진이 백트래킹하거나 모든 백트래킹 구현이 이 입력에서 반드시 지수 시간을 쓰는 것으로 표현하지 않는다.
- 장면 02 화면에 5의 순서 있는 1/2 분해 여덟 가지를 표시한다: 1+1+1+1+1, 1+1+1+2, 1+1+2+1, 1+2+1+1, 2+1+1+1, 1+2+2, 2+1+2, 2+2+1. 첫 항이 1인 5가지와 2인 3가지로 묶어 T(5)=T(4)+T(3)=5+3을 보여준 뒤 일반 점화식으로 전환한다. 분해 수와 실제 탐색 호출 수를 구분한다.
- 장면 03 중심 문장: “지나온 경로는 달라도, 앞으로 남은 계산이 같다면 한 번만 처리하면 됩니다.” 바로 앞에서 같은 입력 위치·같은 상태 조건을 명시한다. ε-closure는 초기 집합부터 포함한다.
- DFA 후반에서 lazy 생성과 모델/알고리즘 분류의 발화를 덜어 핵심 비용 흐름을 압축한다. 해당 구분과 lazy 방식은 위 제작 조건에 유지한다. 화면 비교 표는 NFA/DFA를 백트래킹과 같은 범주의 세 기계로 표시하지 않고 세 실행 전략으로 표시한다.
- AI 연결은 조건부 중복 계산 재사용과 입력 독립 계산의 사전 계산 예시를 추가한다. 화면에서 상태 병합/계산 재사용, 전이 사전 계산/상수 계산, 전이표 저장/저장 비용을 비용 관점의 비교로 보여주며 같은 알고리즘이라는 대응 화살표는 사용하지 않는다.
- 이전 편 복습·다음 편 예고 없이 독립 결론을 유지한다. 시간은 아직 확정하지 않는다.


## 2026-10-16 사용자 종료 시각 반영 제작

- 30개 TTS 문장과 종료 시각을 그대로 보존했다. 전체 154초, 장면 경계 0/16/49/84/112/123/154초. TTS는 빈 줄로 분리하고 타임코드를 제외한다. 화면·자막은 원래 영문·수식 표기다.
- execution_model.py는 설명용 동등한 소형 ε-NFA의 실제 전이, ε-closure, 상태 집합 시뮬레이션, 도달 가능한 집합에 대한 DFA 전이표를 생성한다. Thompson 구성의 원래 상태 수와 동일하다고 하지 않는다.
- 소형 NFA: q0 ε→q1, q1 a→q1, q1 a→q2, q2 a→q1, q1 b→q3. q0 시작, q3 수용. 입력 aaaaac의 초기 집합은 {q0,q1}, a 이후 집합은 {q1,q2}, 마지막 c 이후 공집합이다.
- 입력 위치 2에서 1+1 경로와 2 경로가 동일한 q1에 도착한다. 이후 남은 입력 aaac는 같으므로 이 수용 여부 판정에서는 병합할 수 있다.
- 부분집합 구성으로 도달하는 집합은 Q0={q0,q1}, Q1={q1,q2}, Q2={q3}, Q3=∅이다. 화면 번호와 전이표는 이 생성 자료에서 참조한다. 최소 DFA는 시작/a 반복, b 뒤 수용, 거부의 3상태다.
- {a,b,c}의 길이 0–8 모든 입력 9,841개에서 NFA, DFA, Python fullmatch의 판정 일치를 확인했다. 이는 현재 엔진 속도 측정이 아니다. T(5)=8, T(10)=89, T(15)=987, T(20)=10946도 확인했다.
- 영상은 1080×1920·30fps 무음으로 제작하며 TTS 원고·SRT는 별도 제공한다. 준비·저장 비용과 실행 시간의 구분, 전이표가 준비되었다는 가정을 화면에 표시한다.
