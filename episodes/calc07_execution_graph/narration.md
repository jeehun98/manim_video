# 계산의 두 얼굴 07

## 같은 신경망인데 실행 그래프는 왜 다를까? — AI Framework와 GPU Execution

사용자 제공 23개 문장 종료 시각 기준 122초. 실제 음원 파일 대조는 미실시다.

### 0–10초 | 01  수식이 같으면 실행도 같을까?

같은 신경망을 같은 GPU에서 실행합니다. 수식도, 가중치도, 입력도 같습니다. 그렇다면 실행되는 커널의 구성과 순서도 항상 같을까요?

### 10–24초 | 02  연산 그래프는 무엇을 계산할까?

프레임워크는 연산들의 연결 관계를 그래프로 표현할 수 있습니다. 행렬곱의 결과가 바이어스 덧셈으로, 이어서 ReLU로 전달됩니다. 어떤 값이 어떤 계산에 필요한지는 알지만, 각 노드가 별도 GPU 커널인지는 아직 정하지 않았습니다.

### 24–38초 | 03  노드와 커널의 대응을 선택한다

각 연산을 따로 실행하거나, 여러 연산을 하나의 커널에 포함할 수 있습니다. 같은 연산 그래프가 세 커널이 될 수도, 하나의 Fused GEMM 커널이 될 수도 있습니다. 이것은 연산 노드와 하드웨어 커널의 대응 관계를 선택하는 문제입니다.

### 38–53초 | 04  실행 계획은 커널 수보다 넓다

중간값을 어느 메모리에 둘지, 어떤 배치와 순서로 전달할지도 선택해야 합니다. 하나의 행렬곱 노드도 타일과 메모리 배치가 다른 여러 커널 구현으로 이어질 수 있습니다. 이 선택들이 모여, 실제 GPU에서 어떻게 실행할지에 대한 계획이 됩니다.

### 53–67초 | 05  독립 분기는 겹칠 수도 있다

연산들이 서로 독립적이라면, 항상 같은 순서로 실행할 필요는 없습니다. 의존성이 없는 작업은 서로 다른 Stream에서 겹쳐 실행할 수도 있습니다. 하지만 Add는 두 결과를 모두 기다립니다. 다른 Stream이 실제 동시 실행을 보장하지는 않습니다.

### 67–84초 | 06  선택된 작업을 CUDA Graph로 구성

선택한 커널과 실행 의존성을 런타임 그래프로 구성할 수도 있습니다. CUDA Graph는 작업을 미리 정의하고 재사용해, 반복 실행의 호스트 요청 비용을 줄일 수 있습니다. CUDA Graph 자체가 신경망을 해석해 최적 커널을 고르는 컴파일러는 아닙니다.

### 84–109초 | 07  어떤 계획이 실제로 유리할까?

커널 수가 적은 경로가 항상 빠른 것은 아닙니다. 데이터 이동, 레지스터 사용, 의존성과 입력 크기가 전체 실행 비용을 바꿉니다. 프레임워크는 비용 모델이나 실제 측정으로 후보를 평가할 수 있습니다. 입력 크기나 조건이 바뀌면, 다른 계획을 선택하거나 새로 컴파일할 수도 있습니다.

### 109–122초 | 08  하나의 계산, 여러 실행 구조

연산 그래프는 무엇을 계산할지 나타냅니다. 실행 계획은 그것을 어떻게 구현할지 결정합니다. 성능은 커널, 메모리 배치와 실행 순서에 달려 있습니다. 같은 신경망의 실행 구조는 하나로 정해져 있지 않습니다.
