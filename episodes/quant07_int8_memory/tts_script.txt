같은 숫자를 하나는 삼십이 비트, 다른 하나는 팔 비트로 표현한다면 컴퓨터 안에서는 무엇이 달라질까요?

에프피 삼십이 값 하나는 사 바이트를 사용하고 인트 에잇 값 하나는 일 바이트를 사용합니다. 같은 개수의 값을 저장한다면 원시 데이터가 차지하는 공간은 이론적으로 사 분의 일입니다.

숫자 하나에서는 차이가 작아 보이지만 수백만 개, 수십억 개의 웨이트가 있는 모델에서는 이 차이가 그대로 누적됩니다. 같은 열여섯 개 값도 에프피 삼십이는 육십사 바이트, 인트 에잇은 십육 바이트를 사용합니다.

하지만 더 중요한 것은 저장 공간만이 아닙니다. 지피유는 계산에 필요한 값을 에이치비엠에서 연산 장치로 계속 가져와야 합니다. 같은 십육 바이트 크기의 데이터를 읽는다면 에프피 삼십이는 네 개, 인트 에잇은 열여섯 개의 값을 담을 수 있습니다.

즉 메모리 밴드위스가 같아도 작은 데이터 타입을 사용하면 같은 시간에 더 많은 값을 전달하고, 같은 계산에 필요한 메모리 트래픽을 줄일 수 있습니다.

많은 에이아이 작업은 계산 자체보다 데이터를 옮기는 비용이 병목일 때가 있습니다. 이런 메모리 바운드 작업에서는 메모리 트래픽이 줄어드는 것만으로도 연산 장치가 데이터를 기다리는 시간과 전체 실행 시간이 줄어들 수 있습니다.

물론 인트 에잇이라고 모든 연산이 자동으로 네 배 빨라지는 것은 아닙니다. 실제 속도는 메모리 이동과 연산의 비율, 데이터 타입 변환 비용, 그리고 하드웨어의 인트 에잇 지원에 따라 달라집니다.

그렇다면 더 작은 숫자는 저장과 이동뿐 아니라 실제 계산도 더 빠르게 만들 수 있을까요? 다음 영상에서는 낮은 프리시전이 연산 처리량에도 영향을 주는 이유를 살펴보겠습니다.
