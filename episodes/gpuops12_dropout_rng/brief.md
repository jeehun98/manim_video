# GPU 연산과 최적화 12 제작 기준 — Mask를 먼저 이해하는 개정본

## 제목과 형식

**Dropout — GPU가 기억해야 하는 선택표, Mask**

- 147초 (2:27), 세로 1080×1920, 30fps, 무음. 별도 대본, 발음용 TTS, SRT 제공.
- 핵심: Forward에서 결정한 mask를 Backward에서도 동일하게 사용해야 하므로, 병렬 난수 생성에 더해 mask 저장 또는 재현이라는 선택이 생긴다.
- 기존 11화의 목적 중심 과정 비교를 계승한다. 수식보다 선택표와 숫자를 담은 원의 이동으로 역할을 먼저 설명한다.

## 학습 목표와 시각 규칙

입력 `[2,5,3,8]`, 난수 예시 `[0.73,0.14,0.91,0.32]`, drop 확률 `p=0.5`, keep mask `[1,0,1,0]`를 일관되게 사용한다. 첫 원소를 노란색으로 끝까지 추적한다. 입력·gradient는 원으로, mask는 1/0과 남김/지움이 적힌 별도의 직사각 선택표로 표현한다. Mask의 남김은 초록색, 지움은 분홍색이며 원의 일반 입력은 파란색이다. 난수 생성 조건은 보라색 카드다.

초반은 입력 → 남김·지움 선택표 Mask → Forward 적용 → 같은 표로 Backward 순서다. 난수 숫자는 mask의 존재와 역할을 이해한 뒤에 등장한다. 0~43초에는 1/0과 남김/지움이 적힌 큰 직사각 선택표를 유지하고, 입력 원과 gradient 원만 그 표를 통과한다. 통과하는 원이 mask의 1/0 표기를 가리지 않도록 값은 표의 하단 영역에서 이동한다.

Backward에서 같은 mask가 필요하다는 질문을 먼저 제시한 뒤, 저장·읽기와 재생성을 위·아래 두 경로로 비교한다. 병렬 RNG는 102초 이후 선택표를 만드는 수단으로 설명한다. 마지막 화면도 RNG 대신 큰 Mask를 중심에 놓고 Forward와 Backward가 같은 선택표를 쓰는 관계를 강조한다.

- 위: mask 전체 → GPU Memory WRITE → Backward READ → 같은 mask.
- 아래: 생성 조건 보존 → RNG 재실행 → 같은 mask.
- 두 경로 모두 같은 Mask에 도착한다. 이 표로 같은 Backward gradient를 얻는 원리는 앞부분에서 보여준다. 마지막은 큰 Mask를 중심에 놓고 Forward와 Backward의 공유 관계를 회수한다.

메모리 영역은 별도 공간으로 표시하고 실제 mask 원들이 이동한다. 재생성 경로는 동일한 seed·offset과 원소 매핑으로 동일한 숫자를 다시 만드는 모습을 보여준다. 두 경로의 거리·애니메이션 시간은 실측 속도나 성능 배율을 뜻하지 않는다.

## 수학과 정확성

1. activation dropout이다. 가중치나 연결 자체를 물리적으로 삭제한다고 설명하지 않는다. 각 원소는 확률 p로 drop되며 정확히 p 비율이 지워진다는 뜻은 아니다.
2. 난수 예시는 설명용 숫자이며 특정 Philox seed의 실제 출력이라고 주장하지 않는다. `r∈[0,1)`, keep은 `r≥p`로 정의한다. API마다 범위·경계 비교가 다를 수 있으므로 특정 CUDA API 코드로 제시하지 않는다.
3. 초반 mask 적용 결과 `[2,0,3,0]`은 ‘mask만 적용 · 스케일 보정 전’이라는 중간 단계다. inverted dropout Forward는 `y=m*x/(1-p)`이므로 최종 `[4,0,6,0]`이다. 평균적 크기는 개별 표본의 합이 아니라 기대값이다. `0≤p<1` 예시를 사용한다.
4. upstream gradient를 `[1,2,3,4]`로 별도 표시한다. 같은 mask와 같은 스케일을 적용한 input gradient는 `[2,0,6,0]`이다. Forward 출력과 gradient를 동일한 데이터로 표현하지 않는다.
5. 하나의 공유 RNG 상태를 모든 Thread가 순차 갱신하는 그림은 병렬성 문제를 설명하는 가정이다. 실제 GPU RNG 전체가 이 방식이라고 주장하지 않는다.
6. counter 기반 병렬 PRNG가 대표적인 방법이다. 독립적 위치를 원소마다 할당하고 Thread는 하나 이상의 원소를 처리할 수 있다. 서로 다른 counter가 모든 출력값의 수치적 유일성을 보장하지 않는다.
7. 재현에는 RNG 알고리즘, seed, 시작 offset/counter, 원소와 난수 위치의 매핑, p와 비교 규칙이 같아야 한다. 같은 seed 하나만으로 충분하다고 일반화하지 않는다. 동일한 Forward를 위한 조건을 복원하며, 다음 Forward 호출은 새 난수 구간을 사용한다.
8. mask 저장과 조건 보존·재계산은 구현 선택이다. 저장 형식은 bool/byte/bit packing 등으로 달라질 수 있고, 항상 한 방식이 빠르다고 결론내리지 않는다. 일반적인 inverted dropout의 평가 모드에서는 identity다.

## 장면별 타임라인

| 구간 | 장면 목표 |
|---|---|
| 0–8초 | Mask라는 독립적인 선택표를 먼저 명명하고 크게 제시 |
| 8–17초 | 1=남김, 0=지움 · 입력 원이 선택표를 통과해 값 선택 |
| 17–25초 | 같은 표 유지, 남긴 값 ×2 보정 |
| 25–32초 | 앞의 표를 유지한 채 별도의 gradient 등장 |
| 32–43초 | 같은 Mask로 gradient 선택·보정, 새 선택을 하면 안 되는 이유 |
| 43–49초 | 같은 선택표를 Backward에서 다시 얻는 두 경로 전체 그림 |
| 49–58초 | 방법 1: mask 전체 WRITE → GPU MEMORY → READ |
| 58–64초 | 선택표의 저장 공간·쓰기·읽기 비용 |
| 64–75초 | 방법 2: 생성 조건으로 같은 난수·같은 Mask 재생성 |
| 75–83초 | seed와 counter/offset의 역할 |
| 83–92초 | 네 난수와 네 mask 선택을 Forward/Backward에서 함께 비교 |
| 92–102초 | 두 복원 경로 동시 이동, 메모리 대 재계산 tradeoff |
| 102–108초 | GPU의 많은 원소를 고르기 위한 난수 필요 |
| 108–114초 | 공유 상태를 순차 갱신하는 가정의 대기 |
| 114–123초 | 병렬 counter 기반 난수 → 익숙한 선택표 Mask |
| 123–131초 | 새 Forward의 다른 구간, 이전 Forward와 짝인 Backward |
| 131–137초 | 일반적인 추론의 identity |
| 137–147초 | 큰 Mask 중심에 Forward·Backward 공유와 저장/재생성 요약 |

## 제작과 검토 기준

구간 종료 시각을 `Scene.time`으로 맞춘다. 한글 폰트 Malgun Gothic과 시리즈 색상을 사용하고, 360×640 미리보기에서 이동 중 숫자와 설명의 겹침을 확인한 뒤 최종본을 렌더한다. 실제 TTS 음원은 제공되지 않았으므로 음성 싱크는 원고·구간 시간까지만 맞춘다. 화면에는 원래 숫자·영문, 발음용 원고에만 한국어 읽기를 사용한다.

### 2026-10-02 TTS 길이에 맞춘 전환 조정

- 사용자가 알려준 TTS 총 길이 2:27에 맞춰 전체를 147초로 조정한다.
- 18개 구간은 발음용 원고의 한글 음절 수와 문장·쉼표 경계에 따라 시간을 배분했다. Mask를 통과하는 원의 이동, 저장·읽기, 재생성 애니메이션 속도는 유지하고 장면 내부 대기 시간을 줄였다.
- TTS 원고는 그대로 유지하며 대본의 시간 표기와 SRT 구간만 함께 조정했다.
- 현재 12화 음원 파일은 작업 폴더에서 확인되지 않았다. 전체 길이는 지정값에 맞추며, 개별 문장의 실제 음성 타임스탬프는 검증하지 않았다.

### 렌더 검증 결과

- 360×640 미리보기와 1080×1920 최종본 모두 30fps, 4,410프레임으로 완료했다. 프레임 기준 재생 길이는 147초이며 MP4 스트림 메타데이터는 약 146.974초다(1프레임 이내 차이).
- 최종본은 무음이며 SRT 18개 구간의 종료 시각은 00:02:27이다.
- 미리보기의 Mask 적용·저장/재생성·마무리 장면과 최종본의 40초·99초·145초 화면을 확인했다. 한글, 선택표, 데이터 이동 경로가 프레임 안에 표시된다.
- 전환 대기를 줄이고 기존 이동 애니메이션의 실행 시간을 유지했다. 실제 음원과 문장별 싱크는 별도 검증이 필요하다.
