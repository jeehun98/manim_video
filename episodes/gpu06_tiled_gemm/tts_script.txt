앞에서는 스레드 하나가 출력 하나를 계산하는 나이브 젬을 살펴봤습니다.

계산은 맞지만 여러 스레드가 같은 에이와 비의 값을 글로벌 메모리에서 반복해서 읽었습니다.

한 번 가져온 데이터를 함께 재사용할 수는 없을까요? 여기서 타일링이 등장합니다.

행렬을 작은 영역으로 나눠 계산합니다. 에이와 비에서 잘라낸 작은 사각형을 타일이라고 부릅니다.

하나의 블록이 씨의 작은 영역을 맡습니다. 이 블록의 스레드들은 필요한 에이와 비의 타일을 함께 사용합니다.

먼저 각 스레드가 타일의 일부를 나눠 가져옵니다. 글로벌 메모리에서 읽은 값을 셰어드 메모리에 저장합니다.

이제 필요한 두 타일이 블록 안에 있습니다. 가져온 데이터는 같은 블록의 스레드들이 함께 쓸 수 있습니다.

단, 함께 읽기 전에 적재가 끝났는지 맞춰야 합니다. 필요한 동기화 뒤에 계산을 시작합니다.

에이의 한 값은 여러 출력에 필요합니다. 셰어드 메모리에 한 번 올려두면 여러 스레드가 재사용합니다.

비의 값도 마찬가지입니다. 다른 출력 행을 맡은 스레드들이 같은 값을 함께 사용합니다.

각 스레드는 셰어드 메모리의 에이와 비 값을 곱하고, 자신의 중간 합에 더합니다.

첫 타일의 부분 합이 만들어졌습니다. 중간 합은 각 스레드의 레지스터에 유지합니다.

다음 타일을 가져오기 전에는, 모든 스레드가 현재 타일을 다 읽었는지 동기화로 맞춥니다.

이제 에이에서는 오른쪽 조각으로, 비에서는 아래쪽 조각으로 이동합니다. 출력 영역은 그대로이고, 합산할 입력 구간만 바뀝니다.

새 타일을 셰어드 메모리에 올리고, 적재 완료를 맞춥니다. 레지스터에 있던 중간 합은 지우지 않습니다.

새 조각에서도 곱셈과 덧셈을 이어갑니다. 첫 출력의 중간 합 사에 팔을 더하면 십이가 됩니다.

모든 입력 구간의 계산이 끝나면 각 스레드가 최종 결과를 씨의 담당 위치에 씁니다.

다른 출력 영역도 각 블록이 같은 방식으로 계산합니다. 이 과정을 통해 전체 행렬곱 결과를 완성합니다.

수학적 계산은 바뀌지 않았습니다. 여전히 에이의 한 행과 비의 한 열을 곱해서 더합니다.

나이브 젬은 각 스레드가 직접 입력을 읽습니다. 타일드 젬은 함께 쓸 데이터를 가져와 블록 안에서 재사용합니다.

이 예제의 한 출력 타일에서는 입력 읽기 요청을 줄일 수 있습니다. 실제 메모리 이동과 속도 차이는 캐시 등에도 영향을 받습니다.

핵심은 단순히 작은 사각형으로 자르는 것이 아닙니다. 데이터 이동의 단위를 바꾸고, 여러 계산이 재사용하는 구조입니다.

그렇다고 타일이 작을수록 좋은 것은 아닙니다. 너무 작으면 함께 재사용할 기회가 충분하지 않을 수 있습니다.

너무 크면 셰어드 메모리 사용량이 늘어납니다. 설계에 따라 레지스터 사용량과 스레드 배치에도 영향을 줍니다.

그래서 타일 크기, 스레드당 출력 수, 셰어드 메모리와 레지스터 사용량을 함께 고민합니다.

이제 스레드와 블록, 워프가 한 계산에 모입니다. 블록 안의 스레드들은 워프 단위로 실행됩니다.

타일을 가져올 때도 워프의 접근 주소가 중요합니다. 코얼레스트 메모리 액세스를 고려해 읽기 작업을 나눕니다.

셰어드 메모리는 함께 쓰는 타일을, 레지스터는 개인의 중간 합을 맡습니다. 이 구조들이 함께 데이터 재사용을 만듭니다.

지피유 최적화에서 중요한 질문은 연산 수뿐만이 아닙니다. 한 번 가져온 데이터를 얼마나 많이 다시 사용할 수 있을까요?
