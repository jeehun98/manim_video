# AI 컴파일러 08 — 코드의 모양을 지우면 무엇이 남을까?

현재는 사용자 확정 25개 발화 구간과 종료 시각을 반영한 170초 제작본이다. 초기 검토 기록은 제작 이력이며 실제 음원 파일 대조는 미실시다. 재귀 하강 파서 구현 설명은 추가하지 않는다.

## 학습 목표와 주장

코드 표면의 중첩·중간 변수 차이를 넘어서 연산과 값의 정의·사용 관계를 분석하기 좋은 표현을 만든다. 중심 시각화는 같은 생산자의 결과를 두 소비자가 공유하는 DAG이다. AST에 계산 정보가 없다거나 IR이 반드시 AST와 완전히 별개라고 하지 않는다.

## 장면 계획

| 장면 | 주장 | 화면 |
|---|---|---|
| 01 | 다른 표기에서도 같은 계산 표현을 얻을 수 있다 | 중첩 코드와 중간 변수 코드, 의미 조건 표시 |
| 02 | 분석하기 좋은 정의·사용 관계를 명시한다 | AST와 MatMul→Add→ReLU IR, 값 이름 t1/t2 |
| 03 | 같은 결과가 둘 이상의 소비자에게 연결된다 | MatMul 1개→ReLU/Sigmoid→Add DAG, 준비·공유 관계 |
| 04 | 변수 이름과 값의 정의를 구분한다 | x 재할당→x₀/x₁/y₀, 사용에서 정의로 강조 |
| 05 | IR은 분석·변환의 대상이지 속도 보장이 아니다 | 재사용·저장·커널 결합의 합법성과 비용 검토 |

## 화면용 코드·IR

코드 A:
```python
y = relu(x @ W + b)
```

코드 B (사용자 메시지에서 붙은 줄바꿈을 복구):
```python
t1 = x @ W
t2 = t1 + b
y = relu(t2)
```

개념적 계산 IR (특정 MLIR/LLVM 방언의 유효 문법이 아님):
```text
t1 = MatMul(x, W)
t2 = Add(t1, b)
y  = ReLU(t2)
```

공유 예시:
```python
a = x @ W
b = relu(a)
c = sigmoid(a)
y = b + c
```

SSA 직관 예시:
```text
# 원문
x = 2
x = x + 3
y = x * 4

# 개념적 SSA
x₀ = 2
x₁ = x₀ + 3
y₀ = x₁ * 4
```

## 정확성 조건

1. 소스의 이름·타입·연산 의미를 확인한 뒤 IR로 변환한다. 알려진 순수 ReLU/Sigmoid, 호환되는 행렬 형상과 dtype, 올바른 bias broadcast, 관찰 가능한 부작용·별칭·변이 문제가 없는 설명용 계산을 가정한다. 두 코드의 이름 차이와 추가 로컬 중간 변수 자체는 여기서 관찰 대상이 아니다. 연산 순서나 dtype을 바꾼 동등성 주장이 아니다.
2. 코드 A/B의 같은 IR은 적절한 프런트엔드 처리·정규화에서 얻을 수 있는 예시이며 모든 컴파일러가 즉시 바이트 단위로 같은 IR을 만든다는 뜻이 아니다. 모든 동등한 프로그램의 공통 정규형을 항상 찾을 수 있다는 주장도 하지 않는다.
3. AST도 연산 관계를 나타낼 수 있고 IR의 한 형태일 수 있다. 계산 IR을 만드는 목적은 정의·사용, 타입, 형상, 효과 등 분석에 필요한 관계를 명시하기 쉽게 하는 것이다. 모든 IR이 동일한 정보를 갖거나 무조건 모든 표기·디버그 정보를 버리는 것은 아니다. 제목의 '모양을 지운다'는 핵심 계산 관계에 주목한다는 비유이다.
4. AST의 변수 참조 두 개가 같은 정의를 가리킬 수 있다. AST가 반드시 행렬곱을 두 번 복제해 계산한다는 그림을 만들지 않는다. 공유 예시는 두 a 참조에서 하나의 정의로 연결선을 정리하는 과정이다. IR 구성 자체로 중복 계산 제거 최적화가 이미 실행됐다고 하지 않는다.
5. 이 직선적·순수 계산 예시는 DAG지만 모든 IR이 DAG는 아니다. 제어 흐름, 루프, 메모리 효과, 영역을 포함하는 IR도 있다. AST→IR을 무조건 '트리보다 강한 그래프'로의 표현력 상승이라고 설명하지 않는다.
6. ReLU와 Sigmoid 사이에 직접적인 데이터 의존성이 없다는 사실은 실제 동시 실행의 보장이 아니다. 효과·메모리 alias·장치 자원·스케줄 조건도 확인한다. 최종 Add는 두 결과에 의존한다.
7. a가 두 소비자에 사용 가능해야 한다는 것은 논리적 값의 유효성이다. 전체 텐서를 반드시 별도 DRAM 버퍼에 유지하거나 커널 두 개로 실행해야 한다는 뜻은 아니다. fusion·타일 처리·재계산 등 실제 저장 계획은 별도 선택이다.
8. SSA는 각 SSA 이름/값이 정적으로 하나의 정의를 갖도록 한다. 원래 소스 변수에는 여러 정의가 있을 수 있다. 루프의 동일 정적 명령이 동적으로 여러 번 실행될 수 있으므로 '실행 중에도 단 한 번만 계산한다'고 하지 않는다. 같은 수치 값을 갖는 모든 정의를 하나로 합친다는 뜻도 아니다.
9. 분기·반복에서의 φ 노드나 블록 인수는 합류·루프 값을 연결하는 예시이며 이번 발화에서는 상세 구현을 생략한다. SSA의 각 사용은 해당 정의로 추적되어야 하고 필요한 지배 관계 조건을 만족해야 한다. SSA를 문자열 치환만으로 일반 구현할 수 있다고 하지 않는다.
10. 문법·IR 데이터 구성, 최적화의 합법성, 성능 효과를 구분한다. 재사용·상수 계산·fusion은 효과와 수치 의미 등 조건이 허용할 때 검토하며 IR이 있다고 자동 적용하거나 성능을 보장하지 않는다.
11. 이전 편 복습과 다음 편 예고는 없다. 재귀 하강 파서 설명을 추가하지 않는다. 화면·대본은 원래 수식·영문 표기, TTS는 발음 표기이며 화면 변화 단위로 빈 줄 하나를 넣는다. 발화 길이 미확정.

## 사용자 발화 시각 반영 제작

- 25개 문장과 종료 시각을 반영해 전체 170초(2분 50초)로 확정했다. 장면 경계 0/19/53/93/136/170초. TTS 문장을 보존하고 원고의 숫자 타임코드를 timing.json과 SRT로 이동했다.
- ir_model.py는 알려진 순수 연산의 설명용 부분 언어를 Python AST에서 연산·값 정의 자료로 변환한다. 일반 Python 의미 분석이나 실제 MLIR/LLVM 백엔드 구현이라고 하지 않는다.
- 중첩 코드와 중간 변수 코드의 연산·피연산자 구조가 같음을 확인했다. 공유 예시에는 MatMul 1개, 그 결과 v0의 소비자 v1/v2가 있다. scene.py의 flow는 같은 자료의 사용 관계를 그린다.
- 20개 임의 텐서 입력에서 중첩/중간 변수 IR 및 직접 계산의 값 일치를 확인했다. 공유 그래프 계산도 직접 계산과 일치하며 SSA 예시는 20을 얻는다. 이는 일반적인 의미 동등성 증명이나 성능 측정이 아니다.
- SSA 예시는 원문 x의 두 정의를 x₀/x₁로 구분한다. 상수를 내부 IR 값으로 표현하는 모델과 화면의 상수 인라인 표기는 동일 계산을 나타내는 별도 표기다. 정적 정의 한 번이 동적 실행 횟수 한 번을 뜻하지 않음을 화면에 표시한다.
- 분기 합류는 φ/블록 인수의 개념도로만 소개하며 완전한 SSA 구성 알고리즘은 범위 밖이다. 공유 값이 반드시 전체 DRAM 버퍼로 보존되어야 한다거나 무조건 두 커널로 병렬 실행된다고 하지 않는다.
- 출력은 1080×1920·30fps 무음, 360×640 미리보기. TTS와 SRT 별도 제공.


### 170초 최종 검증

- 미리보기와 최종 렌더 완료. 25개 누적 종료 시각과 timeline gate를 통과했다.

- SSA 정의·사용 연결과 외부 입력의 짧은 화살표를 보완해 식별성을 높였고 수정본으로 미리보기·최종을 다시 렌더했다.
- TTS 원고는 사용자 발화 25개 구간을 유지하고 빈 줄로 나누며 타임코드는 제외한다. 실제 음원 파일 대조·실제 컴파일러 최적화·성능 실측은 미실시다.
