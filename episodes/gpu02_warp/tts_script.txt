앞에서는 GPU가 계산을 여러 Thread로 나누고, Block과 Grid로 조직한다고 했습니다.

그렇다면 이 Thread들은 실제로 하나씩 따로 실행될까요?

GPU에서는 여러 Thread를 일정한 묶음으로 처리합니다.

NVIDIA GPU에서는 32개의 Thread가 하나의 Warp를 이룹니다.

예를 들어 Thread 0부터 Thread 31까지가 Warp 0,

Thread 32부터 Thread 63까지가 Warp 1이 됩니다.

즉, Block 안의 Thread들은 다시 Warp 단위로 나뉩니다.

Warp는 같은 명령을 활성화된 Thread들에 실행합니다.

예를 들어 모든 Thread가 자신이 맡은 값에 1을 더한다고 해보겠습니다.

Thread 0은 x₀을, Thread 1은 x₁을, Thread 2는 x₂를 처리합니다.

다루는 데이터는 서로 다르지만, 수행하는 명령은 같습니다.

이런 실행 방식을 SIMT라고 부릅니다. Single Instruction, Multiple Threads.

하나의 명령을 여러 Thread가 각자의 데이터에 대해 실행하는 구조입니다.

우리는 Thread 하나하나를 독립적인 작업처럼 작성합니다.

실제 명령은 Warp 안에서 활성화된 Thread들을 묶어 실행합니다.

그렇다면 Warp 안의 Thread들이 서로 다른 일을 해야 한다면 어떻게 될까요?

예를 들어 입력이 0보다 크면 한 연산을, 그렇지 않으면 다른 연산을 한다고 해보겠습니다.

일부 Thread는 위쪽 경로를 선택하고, 다른 Thread는 아래쪽 경로를 선택합니다.

한 번의 Warp 명령으로는 서로 다른 두 경로의 명령을 함께 실행하지 않습니다.

한쪽 경로를 실행하는 동안, 다른 쪽 Thread는 그 명령에서 비활성화됩니다.

반대쪽 경로를 실행할 때는, 이번에는 처음 Thread들이 비활성화됩니다.

이처럼 하나의 Warp 안에서 실행 경로가 갈라지는 현상을 Branch Divergence라고 합니다.

각 경로의 계산을 마친 Thread들은 다시 공통된 다음 명령으로 이어질 수 있습니다.

GPU 성능을 볼 때는 Thread가 몇 개인지만 중요한 것이 아닙니다.

Warp 안의 Thread들이 얼마나 같은 실행 경로를 따르는지도 중요합니다.

Thread는 우리가 작성하는 작업의 단위이고, Warp는 명령을 실행하는 중요한 묶음입니다.

Warp를 이해하면 GPU의 병렬 실행을 조금 더 실제 모습에 가깝게 볼 수 있습니다.
