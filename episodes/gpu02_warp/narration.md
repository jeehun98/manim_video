# GPU 02 — Warp란 무엇인가

기준: 실제 영상에 표시되는 scene.py의 CAPTIONS 원문과 화면 전환 시각. 모든 문구는 자막 그대로이며 추가 설명이나 의역을 넣지 않습니다. 전체 길이 164초.

tts_script.txt도 동일한 원문을 사용하며 문장 내부 줄바꿈만 공백으로 바꿉니다. 용어·숫자의 발음 치환도 하지 않습니다.

## 00:00:00.000–00:00:06.000 / 6초 / recap

앞에서는 GPU가 계산을 여러 Thread로 나누고,
Block과 Grid로 조직한다고 했습니다.

## 00:00:06.000–00:00:11.000 / 5초 / question

그렇다면 이 Thread들은 실제로
하나씩 따로 실행될까요?

## 00:00:11.000–00:00:16.000 / 5초 / group

GPU에서는 여러 Thread를
일정한 묶음으로 처리합니다.

## 00:00:16.000–00:00:22.000 / 6초 / warp32

NVIDIA GPU에서는
32개의 Thread가 하나의 Warp를 이룹니다.

## 00:00:22.000–00:00:27.000 / 5초 / warp0

예를 들어 Thread 0부터 Thread 31까지가
Warp 0,

## 00:00:27.000–00:00:32.000 / 5초 / warp1

Thread 32부터 Thread 63까지가
Warp 1이 됩니다.

## 00:00:32.000–00:00:37.000 / 5초 / block_warps

즉, Block 안의 Thread들은
다시 Warp 단위로 나뉩니다.

## 00:00:37.000–00:00:42.000 / 5초 / instruction

Warp는 같은 명령을
활성화된 Thread들에 실행합니다.

## 00:00:42.000–00:00:48.000 / 6초 / add_one

예를 들어 모든 Thread가
자신이 맡은 값에 1을 더한다고 해보겠습니다.

## 00:00:48.000–00:00:55.000 / 7초 / indices

Thread 0은 x₀을, Thread 1은 x₁을,
Thread 2는 x₂를 처리합니다.

## 00:00:55.000–00:01:00.000 / 5초 / same_instruction

다루는 데이터는 서로 다르지만,
수행하는 명령은 같습니다.

## 00:01:00.000–00:01:07.000 / 7초 / simt

이런 실행 방식을 SIMT라고 부릅니다.
Single Instruction, Multiple Threads.

## 00:01:07.000–00:01:13.000 / 6초 / simt_meaning

하나의 명령을 여러 Thread가
각자의 데이터에 대해 실행하는 구조입니다.

## 00:01:13.000–00:01:18.000 / 5초 / programmer

우리는 Thread 하나하나를
독립적인 작업처럼 작성합니다.

## 00:01:18.000–00:01:24.000 / 6초 / execution

실제 명령은 Warp 안에서
활성화된 Thread들을 묶어 실행합니다.

## 00:01:24.000–00:01:30.000 / 6초 / different

그렇다면 Warp 안의 Thread들이
서로 다른 일을 해야 한다면 어떻게 될까요?

## 00:01:30.000–00:01:38.000 / 8초 / condition

예를 들어 입력이 0보다 크면 한 연산을,
그렇지 않으면 다른 연산을 한다고 해보겠습니다.

## 00:01:38.000–00:01:44.000 / 6초 / paths

일부 Thread는 위쪽 경로를 선택하고,
다른 Thread는 아래쪽 경로를 선택합니다.

## 00:01:44.000–00:01:51.000 / 7초 / one_instruction

한 번의 Warp 명령으로는
서로 다른 두 경로의 명령을 함께 실행하지 않습니다.

## 00:01:51.000–00:01:59.000 / 8초 / path_a

한쪽 경로를 실행하는 동안,
다른 쪽 Thread는 그 명령에서 비활성화됩니다.

## 00:01:59.000–00:02:07.000 / 8초 / path_b

반대쪽 경로를 실행할 때는,
이번에는 처음 Thread들이 비활성화됩니다.

## 00:02:07.000–00:02:14.000 / 7초 / divergence

이처럼 하나의 Warp 안에서 실행 경로가 갈라지는
현상을 Branch Divergence라고 합니다.

## 00:02:14.000–00:02:20.000 / 6초 / rejoin

각 경로의 계산을 마친 Thread들은
다시 공통된 다음 명령으로 이어질 수 있습니다.

## 00:02:20.000–00:02:26.000 / 6초 / performance

GPU 성능을 볼 때는
Thread가 몇 개인지만 중요한 것이 아닙니다.

## 00:02:26.000–00:02:32.000 / 6초 / similar

Warp 안의 Thread들이 얼마나 같은 실행 경로를
따르는지도 중요합니다.

## 00:02:32.000–00:02:39.000 / 7초 / summary

Thread는 우리가 작성하는 작업의 단위이고,
Warp는 명령을 실행하는 중요한 묶음입니다.

## 00:02:39.000–00:02:44.000 / 5초 / ending

Warp를 이해하면 GPU의 병렬 실행을
조금 더 실제 모습에 가깝게 볼 수 있습니다.
