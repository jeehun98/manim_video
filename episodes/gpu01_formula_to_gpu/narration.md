# GPU 01 — 수식 하나가 GPU에서 실행되기까지

145초 · 1080×1920 · 30fps. Scene 수정 → 대본·타이밍 정리 → 렌더 → MP4 전달.

렌더: `python scripts/render.py gpu01`
결과: `exports/gpu01.mp4`

Scene: `scene.py` / 문장별 시간과 화면 동작: `timeline.py` / 공통 컴포넌트: `gpu_series/`

현재 완성 MP4는 보존했습니다. 이후 렌더는 합성 음성 생성 없이 기존 Activation 시리즈처럼 무음으로 생성합니다.
**0.00–11.30초**
각 원소에 1을 더합니다.
수학적으로는 이 한 줄이면 충분합니다.
그런데 이 계산은 GPU에서 어떻게 실행될까요?

**11.30–25.93초**
먼저 데이터를 펼쳐 보겠습니다.
사각형 하나가 원소 하나입니다.
이 데이터를 읽고, 계산하고, 결과를 쓰는 GPU 함수를 Kernel이라고 합니다.

**25.93–35.43초**
여기서는 Thread 하나가 원소 하나를 맡습니다.
같은 Kernel을 실행하지만 담당 위치는 서로 다릅니다.

**35.43–48.23초**
3은 4가 되고, 7은 8이 됩니다.
다른 Thread도 같은 계산을 수행합니다.
하나의 연산이 독립적인 여러 작업으로 나뉜 것입니다.

**48.23–60.90초**
Thread가 많아지면 여러 Thread를 하나의 Block으로 묶습니다.
시야를 넓혀 보면 여러 Block이 있고,
각 Block 안에 다시 여러 Thread가 있습니다.

**60.90–77.80초**
한 번의 Kernel 실행에서 이 Block 전체를 Grid라고 합니다.
Thread, Block, Grid는 작업을 조직하는 계층 구조입니다.
모든 Block이 반드시 동시에 실행되는 것은 아닙니다.

**77.80–91.13초**
계산 구조 옆에는 데이터를 저장하는 구조도 있습니다.
입력과 출력은 Global Memory에 있고,
Thread는 계산할 값을 Register에서 사용합니다.

**91.13–98.30초**
Thread 하나를 따라가 보겠습니다.
입력값 3을 읽어 Register로 가져옵니다.

**98.30–101.37초**
여기에 1을 더하면 4가 됩니다.

**101.37–109.70초**
계산된 4를 출력 위치에 씁니다.
다른 Thread도 같은 과정을 거쳐 결과를 완성합니다.

**109.70–120.20초**
Block 안에는 Thread들이 함께 사용하는 Shared Memory도 있습니다.
하지만 이 단순한 계산에서는 필요하지 않습니다.

**120.20–133.90초**
다시 처음 수식으로 돌아가 봅시다.
계산을 Kernel로 표현하고,
Thread, Block, Grid로 나눈 뒤
데이터를 읽고 계산해 결과를 씁니다.

**133.90–145.00초**
같은 수식도 작업을 어떻게 나누고
데이터를 어떻게 배치하느냐에 따라
GPU의 실행 방식과 성능은 달라집니다.
