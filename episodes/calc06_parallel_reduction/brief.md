# 계산의 두 얼굴 06 — 같은 숫자를 더했는데 왜 결과가 달라질까?

부제: GPU 병렬화와 부동소수점. 주제: Parallel Reduction.

## 학습 목표

실수 덧셈의 결합법칙과 유한 정밀도 FP32 덧셈을 구분한다. 고정 Tree가 다른 순차 경로와 다른 값을 내는 현상, Atomic 누적 순서 변화로 반복 실행 결과도 달라질 수 있는 현상을 구분한다. 수학적 동치·오차 내 일치·비트 동일성 및 재현성 요구가 최적화 허용 범위를 결정함을 이해한다.

## 제작 기준

- 사용자가 구간 시간을 지정하지 않아 초기 편집 예산 150초로 구성한다. 9장면 종료 12,29,43,62,77,103,118,139,150초.
- 1080×1920·30fps, 미리보기 360×640. 무음, 별도 SRT·TTS 원고. 실제 음원 발화 싱크 미검증.
- 같은 세 숫자의 FP32 결과 1/0으로 시작한다. 이전 편 복습·요약과 다음 편 예고 없음.
- 모든 수치는 NumPy float32로 각 단계를 명시적으로 반올림해 검산한다. GPU 커널 실측 또는 실제 스케줄을 재현한 영상이 아니다.

## 수치와 조건

1. a=10⁸, b=−10⁸, c=1은 모두 정확히 표현 가능한 FP32 값이다. IEEE binary32, 최근접 짝수 반올림, 덧셈마다 FP32로 반올림, 초과 정밀도 누산이나 연산 재결합 없음. `(a+b)+c=1`, `a+(b+c)=0`.
2. −100000000 근처의 FP32 간격은 8이다. 다음 큰 표현값은 −99999992. 정확한 b+1=−99999999는 b에서 거리 1, 다음 값에서 거리 7이라 b로 반올림된다. 그림은 이 인접 간격을 확대한다. 모든 FP32 값의 간격이 8이라는 뜻은 아니다.
3. 여덟 값 `[10⁸,1,−10⁸,1,1,1,1,1]`의 실수 합은 6. 초기 FP32 누산값 0인 왼쪽 순차 합은 5. 인접 pair tree의 첫 레벨은 `[10⁸,−10⁸,2,2]`, 다음 `[0,4]`, 최종 4다. Tree가 항상 더 정확하거나 덜 정확하다고 일반화하지 않는다. 차이가 항상 마지막 비트에만 있는 것도 아니다.
4. 순차/병렬은 CPU/GPU의 본질적 구분이 아니다. 양쪽에서 여러 구현을 선택할 수 있음을 표시한다. 8개 leaf의 Tree는 부분합이 병렬로 만들어지는 구조를 보여주며 실제 처리량이나 속도 배수는 측정하지 않는다.
5. 고정 입력·고정 Tree·고정 dtype/반올림·고정 실행 환경의 결정적 구현은 반복 같은 결과를 얻을 수 있다. 단순히 Tree를 고정했다는 사실만으로 버전·백엔드·GPU·혼합 정밀도 변경까지의 bitwise 보장을 일반화하지 않는다.
6. Atomic 예시는 세 FP32 partial sum `[10⁸,−10⁸,1]`, 초기 누산값 FP32 0이다. 가능한 직렬화 순서 `[a,b,c]`는1, `[b,c,a]`는0. Atomic은 갱신 원자성을 제공하나 해당 블록 간 누적 순서를 고정하지 않는다. 결과 차이는 lost update나 데이터 race가 아니라 허용된 직렬화 순서에서의 부동소수점 반올림 차이다. 매 실행마다 결과가 반드시 달라지는 것은 아니다. 이 두 순서를 실제 GPU에서 관측했다는 주장이 아니다.
7. CCCL의 determinism 정책은 특정 API·지원 타입/연산·CCCL/CUDA 버전 범위에서 제공된다. 이 영상은 최신 정책 사용법을 설명하지 않는다. 반복 실행 결정성과 GPU 간 결정성은 별도 요구라는 개념 참고다.
8. Softmax의 합, LayerNorm 집계, MatMul 곱 누산, gradient reduction은 서로 다른 수치 조건을 가진다. Fusion이 항상 재결합하거나 모든 reduction이 atomic을 쓴다는 뜻이 아니다. 부동소수점 순서 변경은 커널/컴파일러 선택에 따라 가능하다.
9. 오차 내 일치는 문제와 dtype에 맞는 atol/rtol 등 기준을 명시해야 한다. 작은 차이를 무조건 허용하거나 본문의 1/0 차이를 acceptable tolerance로 제시하지 않는다. 비트 단위 동일성이 요구되면 수학적 동치만으로 재결합을 허용할 수 없다. strict semantics·fast-math·명시적 재결합 옵션 등의 계약에 따른다.
10. 결정성·정확도·실수 동치는 별개다. 결정적인 결과가 정확한 실수 합과 가깝다는 보장은 없고, 다른 경로의 다른 답이 곧 버그라는 뜻도 아니다. 해당 프로그램의 수치 계약으로 판단한다.
