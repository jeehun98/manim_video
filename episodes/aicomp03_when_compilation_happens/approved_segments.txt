같은 신경망을 여러 번 실행한다면, 컴파일러도 매번 새로운 실행 코드를 만들어야 할까요?
행렬곱에 편향을 더하고 렐루를 적용하는 프로그램을, 시간의 흐름에 놓아 보겠습니다.
먼저 입력이 도착하기 전에 실행 코드를 준비해 둡니다. 모델을 컴파일러에 전달하고, 만들어진 실행 프로그램을 보관합니다.
나중에 실제 입력이 들어오면, 런타임은 준비된 프로그램을 이용해 하드웨어에 실행을 요청합니다.
이처럼 실행에 앞서 컴파일하는 방식을 에이오티라고 합니다. 코드를 만드는 시점과 사용하는 시점이 떨어져 있습니다.
미리 컴파일한다고 입력에 관한 정보를 전혀 모르는 것은 아닙니다. 알려진 텐서 크기와 자료형, 대상 하드웨어 같은 조건을 활용할 수 있습니다.
이번에는 실행 코드가 아직 준비되지 않은 상태에서 첫 입력이 들어옵니다.
첫 호출 중에 컴파일러가 필요한 코드를 만들고, 런타임이 그 코드의 실행을 요청합니다. 현재 입력의 크기 같은 조건을 참고할 수도 있습니다.
이처럼 프로그램이 실행되는 과정에서 필요한 코드를 컴파일하는 방식이 제이아이티입니다. 여기서는 첫 호출에서 컴파일하는 예를 보고 있습니다.
이제 두 번째 입력을 넣어 보겠습니다. 앞서 만든 코드를 저장해 두었고, 이번 입력에도 사용할 수 있다면 어떨까요?
컴파일러가 같은 코드를 다시 만들 필요는 없습니다. 저장된 코드를 꺼내 실행할 수 있습니다.
제이아이티라고 해서 매번 컴파일하는 것은 아닙니다. 코드를 생성하는 일과, 생성된 코드를 재사용하는 일은 다릅니다.
이번에는 입력 조건이 다른 두 코드가 준비되어 있다고 해 보겠습니다. 하나는 배치 크기 팔, 다른 하나는 육십사에 맞춘 코드입니다.
배치 크기 팔의 입력이 들어오면, 실행 중에 조건을 확인해 그 입력에 맞는 코드를 선택합니다.
이것이 런타임 디스패치, 런타임 코드 선택입니다. 이 장면에서는 새 코드를 만드는 대신 이미 준비된 코드 중에서 고릅니다.
실제 선택 조건은 텐서 크기 외에도 다양합니다. 하나의 코드가 여러 입력 크기를 처리할 수도 있습니다.
중요한 것은 런타임 코드 선택이 세 번째 컴파일 방식은 아니라는 점입니다. 에이오티로 미리 만든 코드도, 제이아이티로 만든 코드도 실행할 때 선택할 수 있습니다.
이제 시간축을 겹쳐 보겠습니다. 실행 전에 코드를 만들 수도 있고, 실제 호출 과정에서 만들 수도 있습니다.
만들어진 코드는 조건이 맞으면 재사용하거나, 여러 구현 중 하나를 선택해 실행할 수 있습니다.
코드를 만드는 것, 사용할 코드를 고르는 것, 실제로 실행하는 것은 서로 다른 작업입니다. 컴파일이 일어나는 시점과 코드가 실행되는 시점은 반드시 같지 않습니다.
