# 04. KV Cache — 반복 계산을 기억으로 바꾸기

구간 시간은 발화 추정치입니다. 실제 음성의 누적 시각으로 재동기화할 수 있습니다.

## 00:00–00:06

언어 모델은 지금까지의 토큰으로 다음 토큰을 하나씩 예측합니다. 문장은 한 토큰씩 길어집니다.

## 00:06–00:14

Cache 없이 전체 입력을 다시 넣으면 과거 토큰의 Key와 Value도 다시 계산합니다. 새 토큰은 하나인데 반복 계산은 삼각형처럼 쌓입니다.

## 00:14–00:20

같은 열을 보겠습니다. 첫 토큰의 Key와 Value는 이미 만들었는데 다음 생성 단계에서도 계속 다시 만듭니다.

## 00:20–00:30

이 중복을 지워보겠습니다. 각 위치의 Key와 Value를 한 번 계산해 저장하면, 뒤에서는 새 토큰의 Key와 Value만 추가하면 됩니다. 새 계산은 대각선에 남습니다.

## 00:30–00:36

옆에 남겨둔 결과가 KV Cache입니다. 각 Attention 레이어가 자신의 과거 Key와 Value를 보관합니다.

## 00:36–00:47

재사용할 수 있는 이유는 Causal Attention입니다. 과거 위치는 미래 토큰을 볼 수 없습니다. 같은 모델과 입력이라면 뒤에 토큰이 붙어도 과거 표현이 바뀌지 않아 Key와 Value도 그대로입니다.

## 00:47–00:54

이제 새 토큰을 확대해보겠습니다. 새 위치에서는 Query, 키, Value를 모두 계산합니다. Query는 지금의 질문이고 Key와 Value는 이후에도 필요한 정보입니다.

## 00:54–01:03

새 Key와 Value를 Cache 뒤에 추가합니다. 그리고 새 Query가 저장된 과거 키와 현재 키를 비교해 새로운 Attention 점수를 계산합니다.

## 01:03–01:10

점수를 가중치로 바꾸고 그 비율에 맞춰 Value를 섞습니다. 이 Attention 계산은 Cache가 있어도 매 단계 계속 필요합니다.

## 01:10–01:18

과거 Query는 그 위치의 출력을 만들 때 역할을 마쳤습니다. 다음 위치에서는 새로운 Query가 질문합니다. 그래서 과거 Query 대신 Key와 Value를 남깁니다.

## 01:18–01:25

Cache가 없으면 과거 계산이 반복됩니다. Cache가 있으면 새 Key와 Value만 만듭니다. 반복을 줄이는 대신 결과를 기억해둘 공간이 필요합니다.

## 01:25–01:34

전체 문맥을 보관하는 Cache는 문장이 길어질수록 커집니다. 새 Query가 읽어야 하는 Key와 Value도 늘어납니다. 계산을 줄여도 메모리를 읽는 비용은 남습니다.

## 01:34–01:40

KV Cache의 핵심은 이미 했던 계산을 기억하는 것입니다. 한 번 계산하고 저장해 다시 사용합니다. 계산과 메모리 사이의 교환입니다.
