# GPU 연산과 최적화 06 — 여러 값이 필요한 연산도 합칠 수 있을까?

## 00:00–00:08
앞에서는 현재 가지고 있는 값 하나를 Bias와 ReLU에 계속 넘겼습니다. 원소 하나의 경로를 이어 붙인 Fusion이었습니다.

## 00:08–00:14
이번에는 상황을 바꿔보겠습니다. 각 원소에 ReLU를 적용한 뒤 모든 결과를 더합니다.

## 00:14–00:22
ReLU까지는 원소 하나만 있으면 됩니다. 하지만 최종 합은 `x₂` 하나만 가지고 결정할 수 없습니다. 여러 결과가 만나야 합니다.

## 00:22–00:32
두 Kernel을 따로 실행하면 모든 ReLU 결과를 Tensor로 만들어 Global Memory에 저장하고, Reduction Kernel이 다시 읽어 합을 계산합니다.

## 00:32–00:38
그런데 최종 출력에 이 배열 자체가 필요한 것은 아닙니다. 필요한 것은 배열 안 값들의 합입니다.

## 00:38–00:46
그렇다면 ReLU 결과가 만들어지는 순간 그 값을 현재까지의 partial sum에 반영할 수 있습니다. 중간값 대신 필요한 상태를 갱신합니다.

## 00:46–00:55
GPU에서는 여러 Thread가 동시에 값을 처리합니다. 하나의 합을 순서대로 만들기보다, 각 실행 그룹이 자신의 partial sum을 만들 수 있습니다.

## 00:55–01:04
합은 부분적으로 계산한 결과를 다시 합칠 수 있습니다. 여러 partial sum을 트리처럼 merge하면 전체 Reduction 결과가 됩니다.

## 01:04–01:12
이제 모든 ReLU 결과를 하나의 중간 Tensor로 완성해 놓을 필요가 없습니다. 값은 생성되면서 partial state로 축약됩니다.

## 01:12–01:21
Epilogue Fusion은 현재 값 하나를 다음 연산에 넘겼습니다. Reduction Fusion은 여러 값을 작은 부분 상태로 축약하면서 넘깁니다.

## 01:21–01:30
이 구조는 SUM뿐 아니라 MAX나 MIN에도 나타납니다. 여러 값을 어떤 작은 상태로 모아 다시 합칠 수 있는가, 다음에는 Softmax를 생각해볼 수 있습니다.
