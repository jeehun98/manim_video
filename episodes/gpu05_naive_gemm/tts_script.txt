앞에서는 글로벌 메모리, 셰어드 메모리, 레지스터가
서로 다른 역할을 가진다고 했습니다.

이번에는 실제 계산으로 보겠습니다.
두 행렬 에이와 비를 곱해 행렬 씨를 만드는 행렬곱입니다.

씨의 한 원소를 계산하려면
에이의 한 행과 비의 한 열이 필요합니다.

첫 번째 출력은 에이의 첫 행과 비의 첫 열에서
같은 위치의 값들을 곱해서 더합니다.

즉, 출력 원소 하나는
여러 번의 곱셈과 덧셈으로 만들어집니다.

지피유에서는 이 작업을 여러 스레드에 나눌 수 있습니다.
단순하게 스레드 하나가 출력 원소 하나를 맡습니다.

스레드제로는 첫 번째 출력, 스레드원은 그 옆의 출력.
각 스레드가 자신이 맡은 결과 하나를 계산합니다.

각 스레드는 자신에게 필요한
에이의 행과 비의 열을 따라 값을 하나씩 읽습니다.

읽은 두 값을 곱하고, 결과를 계속 더합니다.
이 중간 합은 레지스터에 둘 수 있습니다.

첫 두 곱셈의 결과는 각각 이입니다.
레지스터의 중간 합은 영에서 이, 다시 사가 됩니다.

나머지 곱셈의 결과 영과 팔도 더합니다.
모든 항을 더한 최종 값은 십이입니다.

계산이 끝나면 레지스터의 최종 결과를
자신이 담당한 씨의 위치에 씁니다.

각 스레드가 출력 하나를 독립적으로 계산합니다.
구조는 단순하고 자연스럽습니다.

하지만 옆의 스레드를 보겠습니다.
다른 출력을 계산하려고 이 스레드도 에이와 비를 읽습니다.

같은 출력 행을 맡은 스레드들은
같은 에이의 값을 반복해서 읽습니다.

같은 출력 열을 맡은 스레드들은
같은 비의 값도 다시 읽습니다.

행렬이 커지면 한 입력값을 사용하는 출력도 많아집니다.
여러 스레드의 반복 읽기도 늘어납니다.

곱셈과 덧셈 자체는 필요한 연산입니다.
하지만 같은 입력값을 여러 스레드가 다시 요청하고 있습니다.

즉, 연산 수뿐 아니라 같은 데이터를 몇 번 읽는지도 중요합니다.
실제 메모리 이동 비용은 캐시 등에도 영향을 받습니다.

에이의 한 값을 여러 출력에 쓴다면,
한 번 가져와 여러 스레드가 재사용할 수 있으면 좋겠습니다.

비의 원소도 마찬가지입니다.
여러 출력이 필요로 하는 값을 함께 재사용할 수 있습니다.

지금의 단순한 커널은 각 스레드가
필요한 값을 글로벌 메모리에서 직접 읽습니다.
이것이 나이브 젬입니다.

수학적으로는 올바른 행렬곱입니다.
하지만 빠른 메모리와 명시적인 공유 재사용은 충분히 활용하지 못합니다.

여기서 셰어드 메모리가 다시 등장합니다.
같은 블록의 스레드들이 쓸 데이터를 함께 준비하는 공간입니다.

행렬 전체 대신 필요한 작은 영역만 가져오면 어떨까요?
에이와 비에서 작은 조각, 타일을 선택합니다.

선택한 조각들을 셰어드 메모리에 가져옵니다.
데이터 준비가 끝났는지 필요한 동기화도 맞춥니다.

이제 같은 블록의 스레드들이 조각 안의 값을 함께 재사용합니다.
글로벌 메모리에서 반복해서 읽는 일을 줄일 수 있습니다.

작은 조각을 가져와 여러 계산에 사용하는 방식.
이것이 다음 단계인 타일링의 출발점입니다.

같은 계산이라도 데이터를 몇 번 읽고 얼마나 재사용하느냐에 따라,
지피유의 실행 비용은 달라질 수 있습니다.
