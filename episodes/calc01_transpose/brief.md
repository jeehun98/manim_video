# 계산의 두 얼굴 01 — Transpose는 정말 행렬을 뒤집을까?

부제: 수학과 GPU의 다른 계산법.

현재 기준: 사용자 제공 문장 종료 시각에 맞춘 107초 수정본. 아래 최초 74초 제작 결과는 이력이다.

## 학습 목표

수학은 결과의 위치 관계를 정의하지만 실제 전치 배열을 만드는 GPU 실행에는 주소 계산과 데이터 읽기·쓰기가 필요함을 이해한다. 요청한 원소 개수와 메모리 접근 구간 수를 구별한다. 같은 전치를 실제 재배열 또는 저장소를 공유하는 View로 표현할 수 있고, 후속 소비 방식에 따라 전체 비용이 달라짐을 이해한다.

- 3×4 입력 A의 값은 1–12. 출력 B는 4×3, 행 우선 저장 순서 `[1,5,9,2,6,10,3,7,11,4,8,12]`.
- 입력 첫 행 1,2,3,4는 노랑으로 추적한다. 첫 행의 원소 위치 0,1,2,3이 출력 0,3,6,9로 대응한다.

## 기술 조건과 과장 방지

1. 서로 다른 연속 행 우선 입력·출력 배열 사이에 데이터를 실제 재배치하는 단순 전치 커널을 다룬다. 모든 transpose가 이동을 요구한다고 일반화하지 않는다. 53초 이후 같은 저장소를 공유하는 View를 비교한다. PyTorch의 일반적인 strided tensor transpose로 조건을 한정한다.
2. “계산하지 않는다”는 덧셈·곱셈 같은 값의 산술 연산이 없다는 뜻이다. 인덱스 계산·메모리 명령·실행 비용은 존재한다. 복잡도 0이나 실행 시간 0을 표시하지 않는다.
3. Warp는 32-thread 단위다. 접근 장면은 그중 4개 lane의 요청만 보여주는 부분 예시다. 정렬된 32B 구간, FP32 8개/구간에서 인덱스 `[0,1,2,3]`은 한 구간, `[0,8,16,24]`는 네 구간에 닿는다. 전체 warp의 트랜잭션 횟수로 표시하지 않는다.
4. 이 장면의 구간 수는 단순 주소 모형이다. 캐시와 실제 DRAM 트래픽·처리 시간은 별개다. 정량 속도나 보편적인 배속 주장을 하지 않는다.
5. 작은 3×4 전치 장면은 주소 대응을 설명한다. 이 작은 예시의 stride=3을 4개 트랜잭션으로 계산하지 않는다. 큰 행렬에서 간격이 커질 수 있다는 설명과 구별한다.
6. Shared Memory·Padding·Bank Conflict의 이름이나 최적화 구현은 이번 편에서 설명하지 않는다. 마지막은 재배열/메타데이터 변경의 비교와 독립적인 결론이다. 이전 영상 복습과 다음 영상 예고는 사용하지 않는다.

## 수정본 기술 기준

- View는 원소 복사가 없다는 뜻이며 메타데이터 처리 비용까지 0이라는 뜻은 아니다. 후속 연산의 비용 증가 역시 가능성이며 필연이 아니다.
- offset=0, 원소 단위 stride를 사용한다. View의 B[i,j] 위치는 i+4j. 재배열 B는 stride (3,1)이며 위치는 3i+j. 두 경로의 모든 논리 값은 같다.
- 입력 수정은 다루지 않는다. View는 저장소를 공유하므로 일반적으로 aliasing에 주의해야 한다.
- [PyTorch transpose 공식 문서](https://docs.pytorch.org/docs/main/generated/torch.transpose.html): strided tensor 결과는 원본 저장 공간을 공유한다.
- [PyTorch Tensor Attributes](https://docs.pytorch.org/docs/main/tensor_attributes.html): stride는 축에서 다음 원소까지의 이동 간격이다.
- 속도 실측 없이 접근 패턴 차이를 설명한다. 작은 배열의 간격을 곧바로 정량 트랜잭션 횟수로 해석하지 않는다.

## 전체 비용 관점 확장 (현재 제작 기준)

- 86–104초: Y=XWᵀ의 재배열/View/MatMul operand 지원 세 경로. B와 C가 같은 구현으로 귀결될 수 있음을 명시한다. 세 경로는 실수 산술의 수학적 동치이며 서로 다른 GEMM 구현의 bitwise 동일성은 보장하지 않는다.
- [cuBLAS 공식 문서](https://docs.nvidia.com/cuda/cublas/): GEMM의 transa/transb로 전치 operand를 지정할 수 있다. 내부 packing이나 레이아웃 변환이 절대로 없다는 뜻으로 확대하지 않는다.
- 104–123초: k번 사용 비용의 단순 모형. T_view≈k T_strided, T_copy≈T_transpose+k T_contiguous. View 메타데이터 비용은 생략하며, 후속 전체 연산 시간 비교다. 원본 W가 유지되고 재배열 결과를 재사용하는 조건이다.
- 가상 예시: T_transpose=3, T_strided=2, T_contiguous=1. k=1이면 View 2/Copy 4, k=6이면 View 12/Copy 9. 실측이 아니며 단위 없는 설명용 수치다.
- T_strided>T_contiguous는 이 가상 예시의 가정이며 전치 operand MatMul의 보편적 성능 특성이 아니다. 이 차이가 양수인 모형에서만 k>T_transpose/(T_strided−T_contiguous)에 재배열이 유리하다. 캐시·크기·커널 지원·저장 비용에 따라 실제 결과가 달라진다.
- 123–135초: 최종 주장은 개별 전치가 아닌 후속 연산까지의 전체 비용 선택이다. 이전 편 복습과 후속 편 예고 없음.
