# GPU 연산과 최적화 09 — ReLU는 GPU에서 어떻게 계산될까?

## 00:00–00:08
ReLU는 음수를 0으로 만들고 양수는 그대로 통과시킵니다. 예를 들어 `[-2, 1, -5, 3]`은 `[0, 1, 0, 3]`이 됩니다.

## 00:08–00:15
각 출력은 자기 입력 하나만 보면 됩니다. 첫 번째 원소를 계산할 때 다른 원소의 값은 필요하지 않습니다.

## 00:15–00:25
그래서 GPU에서는 여러 Thread가 서로 다른 원소를 맡아 같은 연산을 수행할 수 있습니다. 한 Thread가 하나 이상의 원소를 처리할 수도 있습니다.

## 00:25–00:32
그런데 Thread 하나의 ReLU 계산 자체는 아주 작습니다. 값을 보고 `0`과 비교해 선택하면 끝입니다.

## 00:32–00:41
하지만 계산 전에 입력을 Global Memory에서 읽고, 결과를 다시 저장해야 합니다. 별도 ReLU 커널의 흐름은 `Read → ReLU → Write`입니다.

## 00:41–00:50
큰 Tensor에서는 이처럼 값을 읽고 쓰는 일이 ReLU 계산보다 더 큰 부담이 될 수 있습니다. 이런 경우를 memory-bound라고 부릅니다.

## 00:50–01:00
이제 ReLU 앞에 MatMul이 있다고 해봅시다. MatMul 결과 `Y`를 메모리에 쓰고, 별도 ReLU 커널이 `Y`를 다시 읽으면 중간 결과가 한 번 나갔다가 돌아옵니다.

## 01:00–01:09
그런데 MatMul이 만든 출력 일부가 아직 실행 중인 타일에 남아 있다면, 그 값에 바로 ReLU를 적용하고 최종 결과만 저장할 수 있습니다.

## 01:09–01:18
두 연산을 같은 실행 흐름에 넣는 Fusion입니다. 분리 실행의 중간 `Write Y → Read Y`를 피할 수 있지만, 최종 결과의 Write는 남습니다.

## 01:18–01:27
ReLU 수식은 그대로입니다. GPU에서 실행 비용을 가르는 것은 계산뿐 아니라, 값을 어디서 읽고 어디에 저장하느냐일 수 있습니다.
