# GPU 연산과 최적화 13 — LayerNorm

## 학습 목표

한 행의 출력은 그 행 전체의 평균과 분산에 의존한다. 평균과 분산 정보를 병렬로 합칠 수 있고, 내부에 입력을 보관하거나 계산을 결합해 불필요한 메모리 이동을 줄일 수 있음을 이해한다.

## 제작 기준

- 148초(2:28), 15장면. 사용자가 알려준 TTS 총 길이에 맞춘 시간이며 실제 음원 파일은 아직 확인되지 않았다. 12화의 147초 길이는 12화 전용으로 유지한다.
- 1080×1920, 30fps. 미리보기 360×640. 무음 영상, SRT와 TTS 원고 별도.
- 입력 [2,4,6,8] 유지. 첫 값 2는 노란 원으로 추적, 다른 값은 청록색. 제곱 편차 [9,1,1,9], 평균 5, 분산 5.
- 수식은 데이터 이동과 집계 장면 뒤에 보조로 등장. 입력 원·부분합 원·통계 카드를 길을 따라 이동시킨다.
- 메모리는 분홍, 통계 상태는 보라, 결합 경로는 초록. 같은 입력과 같은 출력을 유지한 채 이동 경로를 비교한다. 경로 길이와 애니메이션 시간은 측정 성능을 뜻하지 않는다.

## 콘티 검토와 표현 보정

1. LayerNorm은 원소를 정렬하지 않는다. 한 행의 중심과 퍼짐을 조정하며 순서는 보존한다. 일반적으로 지정한 마지막 축들의 원소를 정규화한다. 영상의 한 행은 그 정규화 범위를 펼친 예시다.
2. 분산은 원소 수 N으로 나눈 모집단 형태(correction=0). 출력은 `(x-μ)/sqrt(σ²+ε)`에 원소별 γ, β를 적용한다. 초반 γ=1, β=0, ε=1e-5일 때 두 자리 근삿값을 표시한다. 마지막 대사는 ‘분산으로 나눈다’ 대신 ‘퍼짐을 기준으로 조정한다’로 고친다.
3. 평균을 구한 뒤 제곱 편차를 모으는 두 집계는 기본적인 설명 방식이다. 모든 LayerNorm이 반드시 두 별도 reduction/kernel을 사용하는 것은 아니다.
4. 계산에서 같은 값을 세 번 사용한다고 외부 메모리에서 꼭 세 번 읽는 것은 아니다. 세 Read는 입력을 보관하지 않는 단순 구현의 예다. LOAD 명령, 캐시 적중, 실제 DRAM 트래픽도 서로 다르다.
5. 합과 제곱합은 함께 누적할 수 있지만 `E[x²]-E[x]²`는 큰 값과 작은 분산에서 상쇄 오차에 민감하다. 10000.1/10000.2/10000.3 예시의 수치는 실수 산술 근삿값이며 특정 dtype 측정 결과가 아니다.
6. Welford 계열의 병렬 병합 상태는 `(n, μ, M₂)`이며 M₂는 분산 자체가 아니라 해당 평균에 대한 제곱 편차합이다. 최종 분산은 M₂/n이다. 그룹 A [2,4]=(2,3,2), B [6,8]=(2,7,2), 최종=(4,5,20). 단순 M₂ 합이 아니라 그룹 중심의 차이 16도 반영한다.
7. 병합식: δ=μB−μA, n=nA+nB, μ=μA+δ·nB/n, M₂=M₂A+M₂B+δ²·nA·nB/n. Welford를 모든 구현의 필수 선택으로 일반화하지 않는다. 부동소수점 병합 순서에 따른 차이가 있을 수 있다.
8. 통계 계산을 한 pass로 해도 최종 정규화에는 입력 원소가 다시 필요하다. 내부 자원에 보관할 수 있으면 재사용하고, 그렇지 않으면 다시 읽거나 다른 분할 전략을 쓸 수 있다. 입력 크기·dtype·레지스터·공유 메모리 한계에 따라 결합 방식이 달라진다.
9. Fused에서도 학습의 backward에 필요한 평균/역표준편차 등을 저장할 수 있다. ‘중간 값 전체를 절대 저장하지 않는다’고 주장하지 않는다. 이 영상은 Forward 구현의 개념이다.

## 장면별 시간

| 구간 | 장면 |
|---|---|
| 0–10 | 중심과 퍼짐 조정, 순서 보존 |
| 10–19 | 평균 reduction: 2/4/6/8 → 6/14 → 20 → 5 |
| 19–26 | 평균 전달, 차이와 제곱 |
| 26–33 | 분산 reduction: 9/1/1/9 → 20 → 5 |
| 33–43 | 전체 통계로 각 원소 정규화 |
| 43–53 | 같은 입력의 세 단계 재사용 |
| 53–63 | 보관하지 않을 때 세 Read 예시 |
| 63–73 | 합과 제곱합을 함께 모으기 |
| 73–83 | 큰 수끼리 빼는 상쇄 위험 |
| 83–94 | 개수·평균·M₂ 통계 카드 병합 |
| 94–104 | 네 통계 카드의 병렬 tree |
| 104–115 | 입력 보관, normalize와 affine 결합 |
| 115–126 | Separate/Fused 경로 비교와 자원 한계 |
| 126–137 | ReLU/Softmax/LayerNorm 비교 |
| 137–148 | 통계 병렬화·안정성·데이터 재사용 요약 |

## 검증

Scene.time 구간 종료 gate를 적용한다. 미리보기로 원 이동, 문자 겹침, 세로 프레임과 자막 영역을 확인하고 최종 렌더한다. 실제 TTS 문장별 싱크는 음원 제공 후 검증 가능하다.

### 최초 165초 제작 결과 (수정 전 기록)

- 미리보기(360×640)와 최종본(1080×1920) 모두 30fps, 4,950프레임, 명목 165초로 렌더 완료. 최종 MP4 스트림 길이는 약 164.980초로 1프레임 이내 차이다. 오디오 스트림은 없다.
- 미리보기의 15장면을 확인한 뒤 작은 통계 카드 표기를 간결하게 하고 병합 경로가 숫자를 가리지 않도록 수정했다. 수정 후 98/104/115초, 최종본 46/115/140초 화면을 확인했다.
- 평균 5, 분산 5, 병합 상태 (4,5,20), 두 자리 정규화 출력과 γ=2, β=1 affine 출력을 검산했다.
- 대본과 SRT는 15구간, 마지막 자막 종료 시각 00:02:45. 실제 TTS 발화 시간은 검증하지 않았다.

### 2026-10-02 TTS 길이 2:28에 맞춘 전환 조정

- 165초에서 148초로 감축한다. TTS 원고의 한글 음절 수와 문장·쉼표 경계를 기준으로 15구간 시간을 다시 배분했다.
- 데이터 이동과 병합 애니메이션의 run_time은 유지하고 대기 시간을 줄인다. TTS 원고는 그대로이며 대본과 SRT 시간 표기를 함께 수정했다.
- 실제 13화 음원은 작업 폴더에서 확인되지 않아 전체 길이를 맞추되 개별 문장 타임스탬프는 검증하지 않았다.

### 148초 수정본 검증 결과

- 미리보기와 최종본 모두 30fps, 4,440프레임으로 렌더 완료했다. 최종본은 1080×1920, 명목 148초이며 스트림 메타데이터는 약 147.980초로 1프레임 이내 차이다. 무음 영상이다.
- 미리보기에서 평균 전달·정규화·합과 제곱합·통계 병합·결합 실행·경로 비교·마무리를 확인했다. 최종본 92/124/146초 화면도 확인했다.
- 15개 대본 및 자막 구간의 종료 시각은 00:02:28이다. TTS 원고와 기존 애니메이션 run_time은 유지했다.
