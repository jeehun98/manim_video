# 계산의 두 얼굴 08 — AI 컴파일러는 어떻게 같은 계산을 알아볼까?

부제: 의미 보존 변환과 실행 비용. 시리즈 마지막 편.

## 학습 목표

변환의 Legality(프로그램 의미와 조건상 허용되는가)와 Profitability(실행 비용상 유리한가)를 구분한다. 수학적 성질은 변환 후보의 근거이고 실제 적용에는 dtype·shape·효과·정밀도·타깃 조건이 필요함을 이해한다. 비용 모델·휴리스틱·실측은 제한된 탐색 안에서 좋은 실행 방법을 찾는 도구이지 전역 최적해의 보편적 보장이 아님을 발견한다.

## 제작 기준

- 사용자가 초를 무시해도 된다고 지정해 설명 흐름 기준 초기 예산 160초로 구성한다. 실제 음원 미제공으로 문장 시각은 추정이다.
- 1080×1920·30fps, 미리보기 360×640, 무음. 대본·발음 원고·SRT 별도.

- 마지막 편이지만 앞 영상 내용의 복습·요약과 후속 예고는 넣지 않는다. 이 영상 자체의 두 판단을 수학/하드웨어 사이의 컴파일러 역할로 결론 낸다.

## 기술 조건

1. Y=(XW)+b의 GEMM epilogue 편입은 가능한 후보 예시다. 모든 shape/dtype/라이브러리에서 가능하거나 bitwise 동일하다는 뜻은 아니다. 허용되는 수치 계약과 broadcast·의존성·부작용 등을 먼저 확인한다.
2. 재결합 `(A+B)+C → A+(B+C)`는 실수의 동치 후보이나 FP에서 반올림 순서가 바뀔 수 있다. 이전 영상 수치를 다시 요약하지 않고 변환의 전제 조건으로만 제시한다.
3. 새 예시 X+(+0)→X: FP32 X=−0, IEEE 최근접 짝수 반올림, signed zero 관찰·보존이 요구되는 조건. 원래 덧셈 결과 +0의 bits 0x00000000, 대체 X의 bits 0x80000000. 이 계약에서는 무조건 같은 변환이 아니다. nsz 등 부호0을 구분하지 않는 의미/옵션에서는 허용 여부가 달라질 수 있다. 모든 +0 제거가 금지된다는 뜻이 아니다. NaN·예외 등 추가 조건의 완전한 규칙은 범위 밖이다.
4. f(x)=x², a=1,b=−1에서 f(a+b)=0, f(a)+f(b)=2. 실수의 선형 L(x)=2x에서는 L(a+b)=L(a)+L(b)=0. affine 함수와 linear를 혼동하지 않는다. 선형성의 분배가 FP bitwise 동일성을 자동 보장하지 않는다.
5. 연산 이름이 전혀 중요하지 않다는 뜻이 아니라, 이름·명세·인터페이스·속성·분석 결과로 알려진 성질과 적용 조건을 이용한다는 관점이다. 컴파일러가 임의 CustomOp의 성질을 자동 증명하거나 모든 AI 컴파일러가 완전한 정리증명기를 내장한다고 말하지 않는다.
6. Linear·Associative·Pure·Elementwise는 후보 생성의 단서다. FP add의 결합성을 가정하지 않는다. Pure의 중복 제거·재배치는 입력 값의 안정성·효과·메모리·제어 의존성 등의 조건에 따른다. RNG 상태와 mutation·aliasing도 변환의 관찰 가능 효과에 포함된다.
7. MLIR ConversionTarget의 target legality는 변환 단계에서 허용되는 IR op/dialect/조건이다. Rewrite Pattern의 matching·rewrite와 target legality가 수학/프로그램 의미 보존을 자동 증명하는 것은 아니다. 변환 구현의 정당성과 타깃 제약은 별도로 관리한다.
8. Legality→Profitability 도식은 개념적 두 판단이며 모든 실제 compiler pass의 고정된 직렬 순서가 아니다. 법적인 변환에도 register pressure·spilling·occupancy 등 비용이 있고 fusion이 항상 유리하지 않다.
9. 탐색 트리는 가상 독립 이진 선택 Fusion2×Layout2×Tile2=8이다. 실제 선택은 서로 종속·제약되고 합법적이지 않은 조합도 있으며 현실 후보 수나 compile 시간을 측정한 그림이 아니다. MLIR Transform Dialect는 변환 조합 표현·실행 도구이지 전역 최적성 보장이나 보편적 cost model이 아니다.
10. 비용 표는 가상 예측 A8/B6/C7, 가상 측정 A10/B8/C7, 단위 없음. 실제 GPU benchmark가 아니고 예측 순위와 측정 순위의 차이를 보여주는 예시다. C는 이 세 측정 후보 내 최저이며 모든 가능한 계획의 전역 최적해가 아니다. 실측에 잡음·warmup·동기화 조건이 필요하다는 사실을 일반적인 고려 요소로 표시한다.
11. 검색·컴파일 비용 예산 안에서 규칙·휴리스틱·cost model·지원되는 autotuning을 조합할 수 있다. 모든 compiler가 모든 후보를 생성·실측하거나 모든 변환을 자동 증명한다고 일반화하지 않는다. 프로그램 수치 의미와 하드웨어 실행 비용을 함께 고려한다.
