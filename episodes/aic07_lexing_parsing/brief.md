# AI 컴파일러 07 — 문자를 읽는 것과 구조를 이해하는 것은 다르다

현재 단계: 사용자 확정 25개 발화 구간과 종료 시각에 따른 164초 영상 제작. 초기 대본 검토·v2 기록은 제작 이력이다. 실제 음원 파일 대조는 미실시.

## 중심 주장

문자 패턴으로 토큰을 식별하는 일과 토큰 사이의 문법적 관계를 명시하는 일은 다르다. Lexer/Parser의 역할 분리가 실제 소스 기반 컴파일러에서 구조를 만드는 데 어떻게 기여하는지 설명한다. 정규 언어의 한계를 재증명하지 않고 토큰 목록→서로 다른 두 AST 장면을 중심으로 한다.

## 장면·화면 계획

| 장면 | 주장 | 시각화 |
|---|---|---|
| 01 | 같은 변수·연산자도 묶음이 다르다 | `a+b*c`와 `(a+b)*c`, 묶음 강조 |
| 02 | 문자 나열을 토큰으로 구분한다 | `result = a + b * c`, lexeme와 token kind |
| 03 | 문법이 우선순위와 재귀적 묶음을 정의한다 | Expr/Term/Factor EBNF를 순서대로 강조 |
| 04 | 토큰 관계가 AST로 명시된다 | Add(a,Mul(b,c))와 Mul(Add(a,b),c) 병렬 구성 |
| 05 | 역할 구분으로 규칙을 나눠 다룬다 | Lexer: 토큰 식별 / Parser: 계층 구성, 재귀 복귀 한 장면 |
| 06 | 구문 구조와 계산 표현의 역할도 다르다 | 소스→AST→의미 분석→계산 IR, 별도 그래프 캡처 경로 |

## 화면용 문법과 토큰

```text
Expr   → Term ( "+" Term )*
Term   → Factor ( "*" Factor )*
Factor → IDENT | "(" Expr ")"
```

이는 반복·그룹 표기를 사용한 **EBNF로 쓴 문맥 자유 문법**이다. EBNF의 `*`는 문법 요소의 반복을 뜻하며 원문 코드의 곱셈 토큰 `"*"`와 구분한다. 예시는 덧셈·곱셈·괄호·식별자만 포함한 표현식 문법이다. 전체 할당문을 파싱하는 문법이라고 표시하지 않는다. 필요 시 별도로 `Stmt → IDENT "=" Expr EOF`를 제시한다.

식별자 규칙: `[A-Za-z_][A-Za-z0-9_]*`. 단순화한 ASCII 규칙이며 모든 실제 언어의 Unicode 식별자 규칙이라고 일반화하지 않는다.

토큰 목록은 `IDENT(result), ASSIGN, IDENT(a), PLUS, IDENT(b), STAR, IDENT(c), EOF`이다. 원문 lexeme와 token kind를 구분한다. 시각화에서는 공백을 건너뛰며 이 소형 언어에서는 의미 없는 구분자라고 가정한다. Python 들여쓰기 등 모든 공백이 의미 없다고 설명하지 않는다.

## 정확성·연출 조건

1. 두 식의 변수·산술 연산자는 같지만 괄호 토큰이 추가되므로 **완전히 동일한 토큰 목록**이라고 하지 않는다. 첫 식은 `Add(a,Mul(b,c))`, 둘째는 `Mul(Add(a,b),c)`로 시각화한다.
2. 연산자 우선순위는 단순 문자 식별만으로 결정되지 않고 문법 또는 파서의 규칙으로 정한다. AST는 묶음과 데이터 의존성을 표현하지만 모든 언어의 피연산자 평가 순서·최종 스케줄을 단독으로 정하지는 않는다. 화면도 실행 커널 순서 대신 트리의 부모·자식 관계를 강조한다.
3. EBNF 반복만으로 AST 결합 방향이 자동 명시되는 것은 아니다. 향후 구현에서 `a+b+c`를 다루면 반복된 항을 왼쪽으로 fold하는 규칙을 별도로 정한다. 이번 두 식은 결합법칙 이슈를 요구하지 않는다.
4. 파서가 구체 구문 트리를 만든 후 AST로 바꾸거나 바로 AST를 만들 수 있다. 모든 파서가 반드시 AST를 직접 생성한다고 하지 않는다. AST에는 핵심 구문을 남기며 괄호·구분자·중간 문법 비단말이 그대로 남을 필요는 없다. AST가 원문의 공백과 주석까지 보존한다고 하지 않는다.
5. 임의 깊이 균형 괄호의 비정규성은 짧은 동기만 제공한다. 고전적 정규식의 한계와 재귀 패턴 등 실용 엔진 확장은 구분한다. 스택의 상세 push/pop 시연이나 상태 충돌 증명은 반복하지 않는다. 한 종류 괄호의 균형 판정은 무제한 카운터로도 가능하므로 스택만이 유일한 해결책이라고 하지 않는다.
6. Lexer/Parser 분리는 흔한 설계지만 이론적 필수는 아니다. scannerless parsing 등 분리하지 않는 구현도 존재한다. 문맥 자유 문법만으로 모든 실제 언어의 이름 해석·타입·문맥 제약을 해결한다고 하지 않는다.
7. `y = relu(x @ W + b)`는 Python 형태의 설명용 코드다. AST 예시는 Assign(y,Call(relu,Add(MatMul(x,W),b))). `@`의 AST 연산자 이름이 MatMul인 것과 실제 타입에 따른 행렬곱 의미 확인은 구분한다. relu라는 이름만 보고 항상 같은 연산이라고 확정하지 않는다.
8. 계산 IR 예시는 이름이 알려진 ReLU 함수이고 x/W가 호환되는 행렬, b가 허용되는 broadcast 형태의 텐서이며 부작용 제약이 없다는 조건에서 MatMul→Add→ReLU로 표현한다. 타입·이름·형상·broadcast 의미는 의미 분석 또는 IR 추론에서 확인한다. AST를 기계적으로 그림만 바꾸면 항상 올바른 계산 IR이 된다고 하지 않는다.
9. AST와 IR의 경계는 실제 시스템마다 다르고 AST 자체도 넓은 의미의 중간 표현이다. 이번 편의 '계산 IR'은 연산과 데이터 의존성을 명시하는 표현을 가리킨다. 계산 IR이 반드시 트리이거나 선형 체인이라는 주장도 하지 않는다.
10. AI 그래프 캡처/연산 추적의 경로를 소스 파싱 경로와 구분한다. 모든 AI 프레임워크가 자체 Lexer/Parser를 구현한다고 하지 않는다.
11. 각 발화 블록은 화면 전환·주요 변화 단위, TTS 사이에 빈 줄 하나. 제목·장면 번호·타임코드는 읽을 원고에서 제외한다. 이전 영상 복습과 다음 영상 예고는 넣지 않는다.

## v2 피드백 반영·축약

- 6장면을 유지하며 발화 블록을 34개에서 25개로 줄였다. 화면용 대본 본문은 1,739자→1,441자로 약 17% 축약했다. 실제 3분 이내 여부는 TTS 발화 후 확인하며 추정 종료 시각을 확정값으로 쓰지 않는다.
- `result`의 여섯 문자가 하나의 IDENT가 되는 과정을 강조한다. 여섯 글자에 각각 토큰을 붙이는 그림 대신 하나의 경계로 감싸고 IDENT(result)를 붙인다.
- 문맥 자유 문법은 모호할 수 있으므로 모든 문법이 유일한 트리를 정한다고 하지 않는다. 발화는 '이번처럼 우선순위를 반영한 문법'으로 한정한다. 모호성의 상세 강의는 추가하지 않는다.
- 정규식 한계와 스택은 한 발화 블록으로 압축하고 증명·push/pop 상세 시연을 생략한다. 두 AST의 부모·자식 관계를 비교하는 장면에 시각적 비중을 둔다.
- AST에도 연산 관계가 있음을 전제로, 계산 IR의 차이를 분석·변환 목적과 추상화 수준으로 설명한다. AST도 IR의 한 형태일 수 있다는 문장을 추가했다.
- AI 예시는 소스 기반 프런트엔드라는 조건을 유지하고, 추적·캡처 경로는 한 문장으로 축약했다. 마지막 결론도 '소스 코드'로 범위를 한정한다.
- TTS 원고는 수정된 25개 발화 블록과 동일한 순서이며 각 블록 사이 빈 줄 하나, 제목·타임코드 없음. 영상·타이밍 파일은 아직 제작하지 않는다.


## 사용자 발화 시각 반영 제작

- 전체 164초, 25개 구간. 장면 경계는 0/12/41/63/92/115/164초. 사용자 TTS 문장은 유지하고 대본·자막에는 원래 영문·수식 표기를 사용한다.
- syntax_model.py의 소형 Lexer와 재귀 하강 Parser가 실제 토큰·AST 자료를 만든다. 장면 04 트리는 이 자료를 사용한다. 예시는 Expr/Term/Factor 문법을 기본으로 하며 AI 예시를 위해 할당·단일 인수 호출·@를 추가 지원한다. 실제 언어 전체를 구현했다고 주장하지 않는다.
- 9개 AST가 Python의 동일 식 구문 분석 결과와 일치하고 잘못된 식 5개를 거부함을 확인했다. result 토큰 목록도 정확히 일치한다. 토큰의 lexeme와 kind를 별도 열로 보여준다.
- a+b*c와 (a+b)*c를 나란히 보여주고 토큰 복사 이동으로 대응 노드를 강조한다. 괄호 노드는 생략하되 묶음은 부모·자식 관계에 남는다.
- 소스 기반 AI 예시는 이름·타입·형상·알려진 ReLU 조건을 명시한다. AST와 계산 IR의 목적 차이, AST도 IR일 수 있음, 소스 파싱 외 추적·캡처 경로를 각각 구분한다.
- 영상은 1080×1920·30fps 무음, 미리보기 360×640. TTS 원고와 SRT는 별도 자료다.
