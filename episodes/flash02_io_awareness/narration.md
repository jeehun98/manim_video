## 전체 내레이션

앞에서는 Attention 계산 과정에서 큰 중간 행렬 S와 P가 생기는 것을 봤습니다.

문제는 값을 계산하는 것뿐 아니라, 어디에 저장하고 다시 읽느냐에도 있습니다.

HBM은 많은 데이터를 저장할 수 있지만, 계산 중에 큰 값을 계속 읽고 쓰면 데이터 이동이 반복됩니다.

반대로 GPU 안쪽의 메모리는 훨씬 작지만, 계산 장치 가까이에서 사용할 수 있습니다.

일반적인 Attention은 점수 행렬을 계산해 HBM에 기록하고, Softmax를 위해 다시 읽습니다.

Softmax로 만든 가중치도 다시 저장하고, Value와 곱하기 위해 다시 읽을 수 있습니다.

FlashAttention은 FLOP만 세는 대신, GPU 메모리 사이의 read와 write까지 함께 봅니다.

전체 행렬을 한꺼번에 처리하지 않고, 필요한 부분을 작은 블록으로 나눠 GPU 안쪽으로 가져옵니다.

블록 안에서는 local score를 계산하고 상태를 갱신해, 거대한 중간 행렬 전체를 HBM에 남기지 않습니다.

그런데 분모의 합을 구하려면 모든 score를 먼저 알아야 하는 것처럼 보입니다.
