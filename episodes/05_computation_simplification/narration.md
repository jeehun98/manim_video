# 05 — Information Guides Optimization

사용자 제공 한국어 대본을 100초 영상에 배치했습니다. 영어 화면·수식, 무음 마스터입니다. 구간은 편집 가이드이며 실제 녹음 후 조정할 수 있습니다.

| 시간(초) | 한국어 내레이션 |
| --- | --- |
| 0–8 | 비가역 연산을 단순한 정보 손실 이상으로 해석할 수 있는 또 다른 이유는, 이어지는 다른 연산들과 결합했을 때 나타납니다. |
| 8–15 | ReLU를 예로 들어보겠습니다. ReLU를 지난 값은 항상 0 이상입니다. |
| 15–22 | 이제 그 뒤에 절댓값 연산이 있다고 해봅시다. 절댓값은 음수를 양수로 바꾸는 연산이지만, ReLU 이후에는 애초에 음수가 존재하지 않습니다. |
| 22–27 | 따라서 Abs(ReLU(x))는 ReLU(x)와 완전히 같은 결과를 만듭니다. |
| 27–33 | 즉, 뒤의 절댓값 연산은 제거할 수 있습니다. |
| 33–41 | 비슷하게 ReLU 뒤에서 다시 max(x, 0)을 계산하는 것도 필요하지 않습니다. 이미 그 조건이 만족된 상태이기 때문입니다. |
| 41–48 | 조금 더 흥미로운 예도 있습니다. 분류 모델에서 Softmax 뒤에 Argmax가 이어지는 경우를 생각해봅시다. |
| 48–57 | Softmax는 값의 크기는 바꾸지만, 가장 큰 값의 위치는 바꾸지 않습니다. |
| 57–65 | 따라서 최종적으로 가장 큰 클래스 하나만 필요하다면, Softmax를 계산한 뒤 Argmax를 하는 것과, Logit에서 바로 Argmax를 하는 결과는 같습니다. |
| 65–73 | 즉, 경우에 따라서는 연산 하나가 아니라 하나의 레이어 전체를 건너뛸 수도 있습니다. |
| 73–84 | 여기서 중요한 점은 단순히 값의 범위를 아는 것만이 아닙니다. 각 연산이 어떤 정보를 보존하고, 어떤 정보를 무시하는지를 알면, 뒤의 연산이 실제로 필요로 하는 정보만 남겨 계산을 줄일 수 있습니다. |
| 84–93 | 비가역 연산은 정보를 제거합니다. 하지만 그로 인해 이후 계산에서 고려해야 할 가능성도 함께 줄어들 수 있습니다. |
| 93–100 | 그래서 정보의 제거는 때로는 계산의 자유도와 최적화 가능성으로 이어집니다. |

## 수학적 범위와 제작 메모

- Abs(ReLU(x)) = ReLU(x), max(ReLU(x), 0) = ReLU(x)는 실수 연산의 항등식입니다. 화면의 y는 ReLU(x)입니다.
- 유한 실수 logit z에 대해 exp는 엄격히 증가하고 모든 성분을 같은 양의 합으로 나누므로 Softmax는 순서와 동률을 보존합니다. 따라서 같은 축, 같은 동률 처리 규칙에서 argmax 결과가 같습니다.
- 실제 부동소수점 Softmax는 반올림·언더플로 등으로 동률을 새로 만들 수 있습니다. NaN/무한대 및 비트 단위 동치까지 보장하는 일반적인 코드 변환을 주장하지 않습니다.
- 확률, 신뢰도, 확률을 쓰는 다른 분기나 loss가 필요하면 그 소비자를 위한 Softmax까지 제거할 수 없습니다.
- 막대그래프는 [1, 3, 2]와 안정적인 Softmax 결과 [약 0.090, 0.665, 0.245]입니다. 두 그래프는 각각 최댓값으로 높이를 정규화하며 실제 값도 표시합니다. 높이 자체의 전후 절대 비교가 아닌 순서 비교입니다.
- Softmax→Argmax 최적화는 순서 보존과 Argmax의 요구 정보에서 도출됩니다. 비가역성 자체가 모든 최적화의 필요조건이나 충분조건은 아닙니다.
- 최적화의 자유도는 요구 결과를 유지하는 구현 선택지라는 의미입니다. 실제 속도 향상은 런타임, 융합, 하드웨어 등에 달려 있으며 측정 결과를 주장하지 않습니다.
