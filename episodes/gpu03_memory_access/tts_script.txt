앞에서는 서른두 개의 스레드가 하나의 워프를 이루고, 같은 명령을 함께 실행한다고 했습니다.

이번에는 이 스레드들이 메모리에서 데이터를 읽는 모습을 보겠습니다.

하나의 워프가 연속된 배열을 읽는다고 해보겠습니다.

스레드제로는 엑스제로, 스레드원은 엑스원, 스레드투는 엑스투. 각 스레드가 바로 옆의 값을 읽습니다.

스레드들이 요청하는 주소도 메모리에서 서로 가깝게 모여 있습니다.

지피유는 이렇게 모인 요청을 효율적인 메모리 접근으로 묶어 처리할 수 있습니다.

이런 형태를 보통 코얼레스트 메모리 액세스라고 합니다.

이번에는 계산은 그대로 두고, 스레드들이 읽는 위치만 바꿔보겠습니다.

스레드제로는 엑스제로, 스레드원은 엑스서티투, 스레드투는 엑스식스티포, 스레드쓰리는 엑스나인티식스를 읽습니다.

각 스레드가 수행하는 계산은 이전과 같습니다. 읽은 값에 일을 더합니다.

하지만 이번에는 요청하는 주소들이 메모리에서 서로 멀리 떨어져 있습니다.

스레드 수는 같고, 계산도 같습니다. 달라진 것은 데이터를 읽는 위치입니다.

연속된 주소를 읽을 때는 여러 스레드의 요청을 비교적 적은 메모리 트랜잭션으로 처리할 수 있습니다.

주소가 멀리 흩어지면 더 많은 메모리 트랜잭션이 필요할 수 있습니다.

같은 양의 값을 읽어도, 요청이 걸치는 메모리 영역 수는 달라집니다.

즉, 지피유에서 성능을 결정하는 것은 계산량만이 아닙니다.

스레드들이 어떤 주소의 데이터를 읽고 쓰는지도 중요합니다.

이 차이는 배열뿐 아니라, 행렬이나 이미지 같은 큰 데이터를 다룰 때도 중요합니다.

예를 들어 한 행이 서른두 개인 행렬을 행 순서대로 메모리에 저장했다고 해보겠습니다.

워프의 스레드들이 같은 행의 옆 원소들을 읽으면, 연속된 메모리 주소에 접근할 수 있습니다.

반대로 같은 열을 따라 읽으면, 이 예제에서는 주소가 서른두 개 원소 간격으로 떨어집니다.

결국 같은 행렬 원소들을 모두 읽더라도, 한 번의 워프 요청에 묶이는 주소는 달라질 수 있습니다.

여기서는 스레드 하나의 접근만 보지 말고, 워프 전체가 어떤 주소들을 함께 요청하는지 봐야 합니다.

워프 안의 스레드들이 가까운 주소를 읽으면, 메모리 접근을 더 효율적으로 처리할 수 있습니다.

반대로 접근 주소가 흩어져 있다면, 같은 양을 읽더라도 더 많은 비용이 들 수 있습니다.

실제 속도 차이는 캐시와 정렬 상태 등에도 영향을 받지만, 접근 패턴은 중요한 출발점입니다.

지피유 최적화에서는 무엇을 계산하는지만큼 데이터를 어떤 순서로 배치하는지도 중요합니다.

그리고 워프의 스레드들이 어떤 순서로 읽고 쓰게 할지도 중요합니다.

같은 커널, 같은 스레드 수, 같은 계산이라도,

워프가 요청하는 주소의 배치가 달라지면 메모리에서 처리해야 할 일이 달라집니다.

메모리 접근 패턴 하나만으로도 지피유의 실행 성능은 달라질 수 있습니다.
