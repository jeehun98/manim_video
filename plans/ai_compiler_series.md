# AI 컴파일러

계산을 표현하고, 의미를 지키며, 실행을 바꾸는 방법.

새 영상 7편과 기존 영상 2편을 재생목록에 배치한다. 역사적 계보와 기술적 변환 경로를 구분한다. 정규식에서 오토마타를 거쳐 IR로 직접 변환된다고 설명하지 않는다. 영상 안에서는 앞 영상 복습·다음 영상 예고 없이 각 질문을 독립적으로 완결한다.

| 편 | 제목 | 범위 |
|---|---|---|
| 01 / aic01 | 유한한 뉴런으로 무한히 많은 패턴을 인식할 수 있을까? — 신경망에서 정규 표현식까지 | 사용자 콘티에 따른 역사·상태·정규 언어 도입 |
| 02 / aic02 | 유한한 기억으로 모든 규칙을 인식할 수 있을까? — 유한 오토마타와 학습되는 기억 | 상태·구별 불가능성·스택·RNN의 학습되는 상태 갱신 |
| 03 / aic03 | 무한히 많은 문자열을 하나의 식으로 표현할 수 있을까? | 선택·연결·반복 |
| 04 / aic04 | 수식과 기계, 어느 쪽이 더 강력할까? — 정규 표현식과 유한 오토마타 | 언어 부류의 양방향 포함·표현력의 동등성·보존 기준 |
| 05 / aic05 | 수식은 어떻게 실행 가능한 기계가 될까? — Thompson's Construction | 구문 트리의 구조적 변환·ε-NFA 조각 조립 |
| 06 / aic06 | 같은 정규식인데 왜 실행 속도가 다를까? | 상태 집합 시뮬레이션·DFA 실행·백트래킹 |
| 07 / aic07 | 컴파일러는 소스 코드를 어떻게 구조화할까? | Lexing·Parsing·AST의 실제 변환 |
| 08 / aic08 | 코드의 모양을 지우면 무엇이 남을까? — AST에서 계산 IR까지 | 공통 계산 표현·공유 DAG·SSA 정의와 사용 |
| 기존 calc07 | 같은 신경망인데 실행 그래프는 왜 다를까? | 연산 그래프·실행 계획 |
| 기존 calc08 | AI 컴파일러는 어떻게 같은 계산을 알아볼까? | 의미 보존·합법성·비용 모델 |

02에서 비정규 언어와 스택을 소개하고, 07은 한계 논증을 반복하지 않고 토큰화·문법 분석·AST 구성에 집중한다. IR 연결은 표현 능력의 언어 계층 상승이 아니라 대상에 적합한 표현과 의미 계약의 설계 원리이다.

01의 실제 제작 자료는 `episodes/aic01_neurons_regex/`에 있다. 02의 실제 제작 자료는 `episodes/aic02_finite_memory/`에 있으며 03의 실제 제작 자료는 `episodes/aic03_composable_regex/`에 있으며 04의 실제 제작 자료는 `episodes/aic04_equivalent_representations/`에 있으며 05는 `episodes/aic05_thompson_construction/`에서 확정 대본과 발화 시각 기준으로 제작했으며 06은 `episodes/aic06_regex_execution/`에서 사용자 확정 30개 구간·154초 기준으로 제작하며 07은 `episodes/aic07_lexing_parsing/`에서 사용자 확정 25개 구간·164초로 제작한다.

5편부터는 대본과 발화 길이를 먼저 확정한 뒤 화면을 제작한다. 5편은 대본 검토 후 사용자 수정 대본과 26개 종료 시각(147초)을 받아 화면을 제작한다.

08은 `episodes/aic08_ast_to_ir/`에서 사용자 확정 25개 구간·170초로 제작한다. 재귀 하강 파서 강의는 생략하며 기존 calc08과 별개로 AST→계산 IR·SSA에 집중한다.
