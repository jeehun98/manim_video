### 기본 화면

- 16:9 검은 배경. 격자·지형·사물·메뉴·HP 바는 표시하지 않는다.
- 위에서 내려다보는 3인칭 공간 개념으로 두 점을 화면 안에 배치한다.
- 주인공: 흰색 사각 점 0.12×0.12, Manim 중심 (−1.5, 1.125).
- 적: 붉은색 사각 점 0.12×0.12, 중심 (1.5, 1.125). 두 점은 화면 중앙 기준 좌우 대칭이다.

### 적의 원본 수식

- 적의 오른쪽 위에 흰색 `x + 3 = 5`와 작은 붉은 표식을 표시한다.
- 적 점에서 수식까지 가는 붉은 꺾은 연결선을 흐리게 유지한다.
- 원본은 복사·풀이·답 제출 중에도 수정하거나 없애지 않는다.

### 주인공의 풀이

- 원본 수식의 복사본이 주인공의 왼쪽 위로 이동한다.
- 흰색의 흐린 꺾은 연결선으로 풀이 묶음과 주인공 점을 연결한다.
- 풀이를 세 줄로 누적하고 좌변·등호·우변을 분리해 등호의 세로 위치를 맞춘다.

```text
    x + 3 = 5
x + 3 − 3 = 5 − 3
        x = 2
```

- 원래 식과 최종 답은 흰색, 양변에서 3을 빼는 줄은 옅은 청색으로 구별한다.
- 1280×720 기준 풀이 등호 열은 x=300, 각 줄 기준선 y=145/180/217이다.
- 적의 원본은 우측 상단, 주인공의 풀이 흔적은 좌측 상단에 남아 서로의 역할을 구분한다.

### 진행과 제출

1. 적의 원본 문제 표시.
2. 복사본을 주인공 왼쪽 위로 이동.
3. 양변에서 3을 빼는 과정을 두 번째 줄에 표시.
4. 세 번째 줄에 `x = 2` 표시.
5. 별도 작은 테두리 안의 답 `2`를 주인공 부근에서 적 바로 앞까지 보낸 뒤 멈춤.

보스 직전에 $x^5=2$와 $\sqrt[5]{2}$를 한 컷 보여주면, 근호로 풀 수 있는 5차식도 있음을 알려줄 수 있다. 보스 상태창 문구는 **‘이 방정식의 근호 표현 불가’**를 우선한다. 아벨–루피니 정리는 모든 5차 방정식에 적용되는 일반 근호 공식이 없다는 결과다. 이 보스 식 자체가 근호로 풀리지 않는다는 판정은 그 식의 갈루아 군이 $S_5$라는 사실에 근거한다.

## 초기 화면 문법 (이전 기획 참고)

현재 배치는 상단의 2026-11-19 화면 구성 기준을 따른다. 아래 메뉴·상태창·대각선 배치는 현재 초기 화면의 구현 요구가 아니다.

- **오른쪽 위**에 보스와 방정식, **왼쪽 아래**에 플레이어를 배치한다. 적 상태창은 방정식·현재 판정, 플레이어 상태창은 현재 영역·사용 가능한 도구를 보여준다. 캐릭터 체력보다 수학적 진행 상태에 화면을 쓴다.
- **하단 대화창**에 배틀 메시지와 메뉴를 배치한다. 수식, 내레이션 자막, 전투 메시지가 같은 내용을 반복하거나 서로 가리지 않도록 각 씬에서 역할을 정한다.
- 인벤토리는 잠긴 아이템까지 보여줄 수 있지만, 평소에는 현재 장면에 쓰는 항목만 강조한다. 무기 이름은 게임 연출이며, 상태창의 **수의 범위**와 **사용 가능한 연산·해법**은 구별한다.
- 픽셀아트는 도입, 조우, 전환, 해금에 집중한다. 수학 설명이 시작되면 기존 Manim 스타일의 그래프·수식으로 읽기 쉽게 전환한다.
- 독자적인 캐릭터와 배경을 준비한다. 아래위 대각선의 배치, 대화창, 커서 같은 고전 배틀 화면의 문법을 활용한다.

### 전투 배경이 수의 세계가 되는 연출

1. **ℕ → ℤ**. 수직선 위에 오른쪽 길로 시작해 첫 음의 해에서 0 왼쪽으로 카메라를 움직인다.
2. **ℤ → ℚ**. 같은 수직선의 0과 1 사이를 확대해 $1/2$에 발판을 찍는다.
3. **ℚ → ℝ**. 유리수는 조밀하므로 커다란 빈틈이 생기거나 메워지는 그림은 피한다. 영역 표기를 바꾼 뒤 함수 그래프에서 찾은 근의 $x$좌표를 수직선으로 가져온다.
4. **ℝ → ℂ**. 실수축을 유지하며 0을 지나는 허수축을 펼친다. 허수축에는 $\operatorname{Im}z$, 실수축에는 $\operatorname{Re}z$를 표시하고 $i,-i$를 찍는다. 전장이 실제로 한 줄에서 평면으로 확장되는 순간이다.

√2의 그래프에 잠시 나타나는 세로축은 **함숫값 $f(x)$**이다. 허수의 탑에서 등장하고 이후 전장에 남는 세로축은 **복소수의 허수부**다. 두 세로축에 명시적으로 라벨을 붙인다.

## 대표 장면 · 제곱근 골렘

1. $x^2-2=0$이 조우한다. 플레이어 HUD는 ‘현재 영역 ℚ’. ‘유리수 범위에 해 없음’은 알려진 무리수성 결과로 다룬다. 유리수 몇 개를 대입하는 장면은 예시로만 쓴다.
2. **확장**을 선택한다. 상태창의 ℚ가 ℝ로 바뀌고 같은 방정식이 유지된다.
3. **분석**을 선택한다. 보스의 식에서 $f(x)=x^2-2$로 이어진다. $(1,-1)$, $(2,2)$를 먼저 표시하고, 실제 포물선이 $x$축을 통과할 때 교점에 $c$를 표시한다. 연속성과 중간값 정리로 $1<c<2$, $c^2=2$를 확인한다. 소수 근삿값은 표시하지 않는다.
4. 배틀 화면으로 돌아오면 ‘양의 실근 확인 ✓’가 뜬다. **표현**을 선택해 $c=\sqrt2$를 표시한다. 양수 범위에서 제곱이 엄격히 증가하고 제곱이 좌우 대칭이므로 전체 해는 $x=\pm\sqrt2$다.
5. ‘근호의 지팡이’ 획득. 이후 같은 UI를 최종 보스에서 다시 사용한다.

## 최종 보스와 결말

- 배틀 배경은 복소평면이다. 근 다섯 개를 점으로 보이고 ‘근 존재 확인 ✓’를 띄운 뒤 근호 표현 항목만 잠근다. 실근의 존재는 $f(1)=-1$, $f(2)=29$와 연속성으로 LV.3과 직접 연결할 수 있다.
- 갈루아의 눈은 **유리수 계수를 고정하면서 근들 사이의 대수적 관계를 보존하는 대칭**을 보여준다. 근이 화면에서 기하학적으로 회전한다는 뜻으로 보이지 않게 한다.
- 엔딩에서는 **계산**으로 실근을 약 1.1673까지 근사하고, **표현**으로 그 근을 가리키는 이름을 붙일 수 있음을 보여주고, **분석**으로 근호 해법이 막힌 이유를 되짚는다. 근의 이름을 정하는 일과 사칙연산·근호식으로 표현하는 일을 구별한다.
- 마지막에 √2를 다시 불러온다. “그 수가 존재할까?”에서 시작한 질문을 “그 수를 어떤 연산으로 표현할 수 있을까?”로 닫는다.

## Manim 구현 및 인수인계

- **Manim + 픽셀아트 PNG**를 기본으로 한다. 투명 PNG 스프라이트를 선명하게 확대하고, 포즈 교체·짧은 이동·점멸·흔들림으로 반응을 만든다. 처음에는 플레이어 대기/행동 포즈와 보스 기본 이미지만으로 배틀이 읽히는지 본다.
- 배틀 프레임, HUD, 대화창, 메뉴 커서, 좌표축을 챕터에서 재사용한다. 보스 이미지·방정식·문구·이벤트만 씬별로 바꾼다. 다양한 연출이 실제로 필요해지면 UI 중심은 Remotion, 캐릭터 동작 중심은 Godot을 검토할 수 있다.
- 제작 전 화면 테스트 후보는 **제곱근 골렘의 배틀 → 포물선 → 배틀 복귀**를 담는 약 20초 분량이다. 20초는 화면 검토용 기준이다. 본편에서는 확정 발화시간을 따른다. 확인할 항목은 스프라이트의 가독성, ℚ → ℝ 상태 갱신, 식에서 그래프로의 연결, 복귀 후 판정 표시다.
- 새 프로젝트는 [롱폼 제작 규격](../longforms/README.md)과 [템플릿](../longforms/_template/)을 따른다. **전체 대본 → 씬 분할·spec → 씬별 TTS 또는 제공된 발화시간 확정 → Manim 화면 → 씬별 오디오 결합 → 최종 연결**. 한 씬은 주장 하나를 담고 독립 렌더·교체할 수 있게 한다. 범용 이벤트 변환기나 자동 대본 파이프라인은 현재 기획의 선행 조건이 아니다.
- 다른 로컬 환경에서는 그 체크아웃에 아래 쇼츠 소스가 있는지 먼저 확인한다. 이 기획을 정리한 시점에는 쇼츠 소스 폴더가 현재 작업 트리에 있었으나 Git 추적 전이었다. 기존 그래프 로직은 가로 레이아웃으로 재배치하고, 세로 MP4는 화면 참고 자료로 사용한다.
- 제작 전 해당 환경의 Python·Manim, FFmpeg, LaTeX/dvisvgm, 한글 폰트를 확인한다. 픽셀아트 에셋은 별도 준비가 필요하다.

### 픽셀 스프라이트와 배틀 모션

- **에셋 준비.** 움직임에 필요한 포즈를 투명 PNG 또는 스프라이트 시트로 준비한다. 같은 캐릭터의 프레임은 캔버스 크기와 발밑 기준점을 통일한다. Manim은 준비한 프레임을 교체하고 스프라이트의 위치와 효과를 제어한다.
- **픽셀 경계.** `ImageMobject`에 최근접 이웃 보간을 적용한다. 아래 API는 현재 작업 환경의 Manim Community 0.21.0에서 확인했다. 화면 검수 시 최종 출력 해상도에서 원본 픽셀의 정수배 확대를 우선하고, 프레임 교체 때 발밑 위치가 튀는지 확인한다.

```python
from manim import ImageMobject, RESAMPLING_ALGORITHMS

player = ImageMobject("player.png")
player.set_resampling_algorithm(RESAMPLING_ALGORITHMS["nearest"])
```

- **포즈와 위치.** 전진·복귀만 필요하면 한 포즈의 위치를 옮긴다. 걷거나 지팡이를 휘두르는 모습은 별도 프레임을 교체한다. `rate_func=linear`는 일정한 속도로 연속 이동시킨다. 도트 격자에 맞춰 끊어 움직이는 효과가 필요하면 위치를 정해진 간격으로 계단식 갱신한다.
- **모션 범위.** 대표 씬은 플레이어 대기·행동 포즈와 보스 기본 포즈부터 검토한다. 필요한 경우 대기 2~4장, 공격 3~6장, 피격 1~2장 정도로 늘린다. 보스 등장에는 짧은 슬라이드, 피격에는 점멸이나 흔들림, 해금에는 아이콘 확대와 강조를 사용한다.
- **재생 속도.** 스프라이트 포즈의 교체 주기는 영상 프레임률과 별도로 정한다. 약 8~12fps를 시안 범위로 두고, 30fps 영상에서는 10fps(영상 3프레임마다 교체), 60fps에서는 10fps 또는 12fps부터 확인한다. 수식과 UI 전환은 영상 프레임률을 그대로 활용한다.
- **제곱근 보스 적용.** 배틀에서 ‘유리수 범위에 해 없음’을 보여준 뒤 분석 화면에서 실근의 존재를 확인한다. 배틀 복귀 후 ‘근호의 지팡이’를 해금할 때 `√` 기호를 짧게 날리거나 아이콘을 강조한다. 이 연출은 확인한 근을 표현하는 단계에 배치한다.
