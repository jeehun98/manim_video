# 「모든 것이 필요할까?」 05 — 최소 실현(Minimal Realization) 상세 영상화 콘티

총 154초 · 2분 34초 · Manim 기반 · 9:16 세로 영상

이번 영상의 핵심은 두 개의 상태를 하나로 합쳤는데도 출력이 전혀 달라지지 않는 장면이야.

단순히 상태공간 방정식을 설명하는 영상보다는, 두 시스템을 나란히 실행하면서 상태 수는 달라도 출력이 일치한다는 사실을 보여주는 구성이 효과적이야.

특히 33\~61초의 상태 결합과 출력 비교, 105\~124초의 합·차이 분리가 가장 중요한 장면이야.

## 1. 영상 전체에서 사용할 시스템

다음 예시를 영상 전체에 일관되게 사용하자.

\\[ \begin{aligned} \dot x_1&=-x_1+u\\\ \dot x_2&=-x_2+u\\\ y&=x_1+x_2 \end{aligned} \\]

새로운 상태를 정의하면,

\\[ z=x_1+x_2 \\]

\\[ \boxed{\dot z=-z+2u,\qquad y=z} \\]

두 상태의 차이는 다음과 같아.

\\[ d=x_1-x_2,\qquad \dot d=-d \\]

즉, \\(d\\)는 입력에 영향을 받지 않고 출력에도 나타나지 않아.

이 예시는 상태 두 개를 하나로 줄이는 이유를 설명하기에 적합하고, 모든 장면을 실제 방정식과 일치시킬 수 있어.

원래 시스템 · 2 states

축소 시스템 · 1 state

두 모델의 내부 표현은 다르지만 같은 입력과 대응하는 초기 출력에 대해 출력 궤적이 일치한다.

색상은 입력 \\(u\\)를 청록색, 상태 \\(x_1,x_2\\)를 파란색 계열, 새로운 상태 \\(z\\)와 출력 \\(y\\)를 노란색, 제거되는 차이 방향 \\(d\\)를 붉은색으로 고정하자.

## 2. 상세 타임라인 콘티

### Scene 01. 내부 상태가 두 개라면 둘 다 필요할까? (00:00–00:11)

00:00–00:06

화면 중앙에 두 개의 상태 블록 \\(x_1,x_2\\)를 배치한다. 각각의 블록 안에 숫자가 실시간으로 변한다.

상단에는 `내부 상태 2개`라는 문구를 표시한다.

00:06–00:11

왼쪽에서 입력 \\(u(t)\\)가 들어오고, 오른쪽에서 출력 \\(y(t)\\)가 나오는 블록 다이어그램으로 확장한다.

입력은 작은 파형, 출력은 시간에 따른 곡선으로 표현한다.

Manim: `RoundedRectangle`, `MathTex`, `ValueTracker`, `Axes`, `VMobject`.

### Scene 02. 두 상태는 같은 방식으로 변한다 (00:11–00:24)

00:11–00:16

상태 블록 위에 \\(x_1\\), \\(x_2\\)를 표시하고 각각의 상태 변화 방정식을 나타낸다.

\\[ \dot x_1=-x_1+u,\qquad \dot x_2=-x_2+u \\]

두 방정식에서 \\(-x_i+u\\) 부분을 같은 색으로 강조한다.

00:16–00:21

동일한 입력 파형이 두 상태 블록으로 분기된다. 각 블록의 상태값이 입력에 반응한다.

이때 두 상태의 초기값을 다르게 설정해, 같은 방정식을 따르더라도 값 자체는 서로 다를 수 있음을 보여준다.

00:21–00:24

두 상태의 출력 화살표가 합산 노드 `+`로 들어간다.

\\[ y=x_1+x_2 \\]

화면에는 개별 상태보다 합계가 더 크게 표시된다.

### Scene 03. 외부에서는 합만 관찰된다 (00:24–00:33)

00:24–00:30

상태값 \\(x_1,x_2\\)를 별도의 작은 패널에 보여주고, 중앙에는 합계 \\(y\\)를 크게 표시한다.

예를 들어,

\\[ x_1=1.5,\quad x_2=0.5,\quad y=2 \\]

이후 상태값을 \\(x_1=1.2,\ x_2=0.8\\)로 바꾸되 출력 \\(y=2\\)는 그대로 유지한다.

이 장면은 한 시점의 출력만으로는 두 상태를 구별할 수 없다는 직관을 제공해. 실제로 이 예시에서는 시간에 따른 출력 전체로도 차이 방향을 구별할 수 없어.

00:30–00:33

상태 두 개를 둘러싸는 테두리가 나타나고, 그 위에 질문을 표시한다.

`두 상태를 따로 추적해야 할까?`

### Scene 04. 새로운 상태 z를 정의한다 (00:33–00:41)

00:33–00:38

두 상태 블록이 서로 가까워지고, 중앙의 합산 노드로 흡수되면서 하나의 노란색 블록 \\(z\\)로 변한다.

\\[ z=x_1+x_2 \\]

00:38–00:41

원래 상태 방정식 두 개를 화면 상단으로 올리고, 더하기 연산을 강조한다.

### Scene 05. 두 방정식이 하나로 합쳐진다 (00:41–00:47)

00:41–00:45

두 상태 변화 방정식이 다음과 같이 합쳐지는 과정을 보여준다.

\\[ \begin{aligned} \dot z&=\dot x_1+\dot x_2\\\ &=(-x_1+u)+(-x_2+u)\\\ &=-z+2u \end{aligned} \\]

수식은 한 번에 전부 등장시키지 말고, 각 줄을 `TransformMatchingTex`로 연결한다.

00:45–00:47

최종적으로 두 식만 남긴다.

\\[ \boxed{\dot z=-z+2u,\qquad y=z} \\]

화면의 두 상태 블록이 하나의 블록으로 대체된다.

### Scene 06. 두 시스템의 출력이 정확히 일치한다 (00:47–01:01)

이 장면은 영상에서 가장 중요한 시각적 증거야.

00:47–00:54

원래 시스템과 축소 시스템을 좌우로 배치한다. 같은 입력 \\(u(t)\\)를 두 시스템에 공급한다.

각 시스템에서 실시간 출력 곡선을 그린다.

00:54–01:01

두 출력 곡선을 하나의 좌표계에 겹친다. 청록색과 노란색 곡선이 정확히 일치한다.

`상태 2개 → 상태 1개`와 `출력 변화 없음`을 강조한다.

시뮬레이션에서는 예를 들어 \\(x_1(0)=1.5,\ x_2(0)=0.5,\ z(0)=2\\)로 설정하면 돼.

### Scene 07. 삭제가 아니라 새로운 표현이다 (01:01–01:22)

01:01–01:05

기존 두 상태 중 하나에 X 표시를 하는 장면을 잠깐 보여준 뒤, 그 방식은 아니라는 의미로 취소한다.

01:05–01:11

두 상태가 합쳐져 새로운 \\(z\\)를 만드는 과정을 다시 보여준다.

01:11–01:16

`Minimal Realization`이라는 용어를 중앙에 등장시킨다.

01:16–01:22

`입출력 관계 유지`와 `상태 차원 최소화`라는 두 조건을 화면 양쪽에 배치하고, 중앙에 축소된 시스템을 보여준다.

### Scene 08. 제어 가능성과 관측 가능성 (01:22–01:45)

01:22–01:29

시스템 블록 위에 질문을 표시한다.

`어떤 상태가 정말 필요한가?`

01:29–01:37 — 제어 가능성

입력 \\(u\\)에서 상태공간으로 향하는 화살표를 보여준다.

제어 가능한 방향은 청록색 화살표로, 입력으로 변화시킬 수 없는 방향은 회색으로 나타낸다.

01:37–01:45 — 관측 가능성

상태공간에서 출력 \\(y\\)로 향하는 화살표를 보여준다.

출력에 드러나는 방향은 노란색, 출력에 나타나지 않는 방향은 흐리게 처리한다.

여기서는 추상적인 정의를 길게 시각화하기보다, 곧바로 기존 예시로 돌아가는 편이 좋아.

### Scene 09. 합 방향과 차이 방향 (01:45–02:04)

01:45–01:48

2차원 상태공간에 \\(x_1,x_2\\) 축을 그린다.

01:48–01:54

두 상태의 차이 방향을 빨간색으로 강조한다.

\\[ d=x_1-x_2 \\]

그리고 \\(\dot d=-d\\)를 표시한다.

01:54–01:58

입력 \\(u\\)를 변화시켜도 \\(d\\)의 변화 방정식에는 입력이 나타나지 않음을 보여준다.

01:58–02:04

합 방향 \\(z=x_1+x_2\\)를 노란색으로 강조한다. 입력에 반응하고 출력에 직접 연결되는 방향이라는 것을 표시한다.

중요한 시각적 주의: 상태공간의 합 방향은 \\((1,1)\\), 차이 방향은 \\((1,-1)\\)이야. 그림에서는 두 방향이 원점을 지나는 직교하는 두 직선으로 나타나야 해. 위 도식은 개념 배치용이며, 실제 Manim 구현에서는 좌표 변환을 정확하게 적용해야 해.

### Scene 10. 최소 실현의 조건과 보존 범위 (02:04–02:21)

02:04–02:10

제어 가능성과 관측 가능성이 모두 충족된 상태만 남긴다는 개념을 보여준다.

`Controllable + Observable → Minimal Realization`

02:10–02:15

동일한 전달함수 \\(G(s)\\)를 가진 두 시스템을 비교한다.

원래 시스템과 축소 시스템의 전달함수는 모두 다음과 같아.

\\[ G(s)=\frac{2}{s+1} \\]

02:15–02:21

`영 초기 상태의 입출력 관계`를 강조한다.

단, 이번 예시에서는 축소 시스템의 초기 상태를 \\(z(0)=x_1(0)+x_2(0)\\)로 맞추면 영 초기 상태가 아니더라도 출력이 일치해. 영상에서는 일반적인 최소 실현의 동등성 기준과 이번 예시의 더 강한 일치 성질을 혼동하지 않도록 해야 해.

### Scene 11. 결론 — 필요한 상태는 몇 개인가? (02:21–02:34)

02:21–02:26

원래 시스템의 두 상태 블록이 다시 등장한다.

02:26–02:34

두 블록이 하나의 \\(z\\) 블록으로 합쳐진다. 화면 아래에는 두 시스템의 동일한 출력 곡선을 남긴다.

최종 문구:

“내부 상태의 개수 ≠ 필요한 최소 상태 차원”

마지막에는 `Minimal Realization`이라는 작은 영문 표기를 남기고 마무리한다.

## 3. Manim 구현을 위한 핵심 검증 사항

영상 제작 시 다음 조건들을 코드 수준에서 검증하면 좋아.

| 검증 대상  | 확인할 내용                                                   |
| ------ | -------------------------------------------------------- |
| 상태 방정식 | \\(\dot x_1=-x_1+u,\ \dot x_2=-x_2+u\\)                  |
| 축소 방정식 | \\(\dot z=-z+2u\\)                                       |
| 초기 상태  | \\(z(0)=x_1(0)+x_2(0)\\)                                 |
| 출력 비교  | \\(y\_{\mathrm{original}}(t)=y\_{\mathrm{reduced}}(t)\\) |
| 차이 방향  | \\(\dot d=-d\\), 입력과 무관                                  |
| 전달함수   | 두 시스템 모두 \\(2/(s+1)\\)                                   |
| 최소성    | 축소된 1차 시스템은 제어 가능하고 관측 가능                                |

구현할 때 `ValueTracker`로 입력을 조절하고, 상태 변화는 미분방정식의 해 또는 수치 적분으로 업데이트하면 돼. 단순히 두 출력 곡선을 같은 좌표로 강제 이동시키는 애니메이션보다는, 각 시스템을 독립적으로 계산했는데도 결과가 일치하도록 구현하는 편이 수학적으로 설득력 있어.

이번 영상의 시각적 중심은 두 상태의 결합(33\~47초), 동일 출력 확인(47\~61초), 합·차이 방향 분리(105\~124초) 세 장면이야. 이 세 장면이 정확하게 연결되면 최소 실현이라는 다소 추상적인 개념도 직관적으로 전달할 수 있어.
