# 01 — 블록과 워프의 실제 실행 공간

## 목적과 핵심 주장
논리적인 Block과 Warp는 물리적 SM에서 실행된다

## 앞 장면에서 받은 내용
없음. 독립적인 질문으로 시작.

## TTS
확정 길이 19초, 전체 0–19초. 사용자 문장 종료 시각 기준이며 음원은 미제공.

GPU에서는 여러 스레드가 블록을 구성하고, 블록 내부의 스레드들은 워프 단위로 명령을 실행합니다.
그렇다면 이러한 블록과 워프는 실제 GPU 하드웨어의 어디에서 실행될까요?
바로 에스엠, Streaming Multiprocessor입니다.
에스엠은 GPU에서 스레드들의 명령을 실제로 실행하는 핵심 하드웨어 장치입니다.

## 화면과 애니메이션
- 0초: Block 0·4 Warp를 SM 확대도와 연결
- 5초: 같은 Block을 감싸는 SM 외곽선 강조
- 10초: Streaming Multiprocessor 표시
- 13초: 물리적 실행 하드웨어 설명

## 화면 텍스트
SM 0 / Block 0 / Warp 0–3. 코드 패널은 테두리·배경·제목을 분리하고 줄 번호 없는 관련 발췌만 표시한다. 대기 주황, 명령 발행 초록, Warp 0 선택 파랑.

## 시작·종료 상태 및 연결
GPU·SM·Block 지도를 같은 위치에 유지하고 확대도만 갱신한다. 상주 Warp의 좌표는 변하지 않는다. 다음 씬은 같은 객체와 상태에서 이어받으며 다음 영상 예고는 없다.

## 정확성
스케줄러 수·배치는 단순화한 관계도다. 발행과 완료를 구분하며 대기 Warp를 SM 밖으로 이동시키지 않는다. 지연과 발행 순서는 가정한 예시이고 실측 cycle trace가 아니다. Occupancy의 최대32Warp는 가상 수치이며 성능비를 뜻하지 않는다. 일반 launch에서 Block 번호를 SM 번호로 해석하지 않는다. 출처는 brief.md와 compiler_notes.md 참조.
