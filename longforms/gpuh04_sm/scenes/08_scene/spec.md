# 08 — 다른 Warp 발행 · Warp 0 재개

## 목적과 핵심 주장
Warp 0 대기 중 Warp 1·2가 명령을 발행할 수 있다

## 앞 장면에서 받은 내용
앞 씬의 같은 GPU·SM 0 지도와 선택된 Warp 0의 정체성을 유지.

## TTS
확정 길이 13초, 전체 82–95초. 사용자 문장 종료 시각 기준이며 음원은 미제공.

워프 스케줄러는 실행할 준비가 된 다른 워프를 선택할 수 있습니다.
워프 1의 명령을 실행하고, 이후 워프 2의 명령을 실행하는 식입니다.
그사이 워프 0이 요청한 데이터가 준비되면, 워프 0도 다시 계산을 진행할 수 있습니다.

## 화면과 애니메이션
- 82초: Warp 0 Wait, Warp 1 Ready
- 86초: Warp 1 Compute 발행
- 88초: Warp 2 Compute 발행
- 90초: Warp 0 데이터 도착 후 Ready
- 92초: Warp 0 Compute 발행

## 화면 텍스트
SM 0 / Block 0 / Warp 0–3. 코드 패널은 테두리·배경·제목을 분리하고 줄 번호 없는 관련 발췌만 표시한다. 대기 주황, 명령 발행 초록, Warp 0 선택 파랑.

## 시작·종료 상태 및 연결
GPU·SM·Block 지도를 같은 위치에 유지하고 확대도만 갱신한다. 상주 Warp의 좌표는 변하지 않는다. 다음 씬은 같은 객체와 상태에서 이어받으며 다음 영상 예고는 없다.

## 정확성
스케줄러 수·배치는 단순화한 관계도다. 발행과 완료를 구분하며 대기 Warp를 SM 밖으로 이동시키지 않는다. 지연과 발행 순서는 가정한 예시이고 실측 cycle trace가 아니다. Occupancy의 최대32Warp는 가상 수치이며 성능비를 뜻하지 않는다. 일반 launch에서 Block 번호를 SM 번호로 해석하지 않는다. 출처는 brief.md와 compiler_notes.md 참조.
