# GPU 개론 10 — 컴퓨터는 어떻게 프로그램을 실행할까?

확정35문장 · 사용자제공165초 · 음원미제공. 발화자표기로 보이는 연우는 대본에 포함하지 않는다.

## 0–18초 · 다음 명령어는 어떻게 알까?

- 0–6초: 앞서 우리는 0과 1로 명령어를 표현하고, 이를 해독해 실제 회로의 동작을 제어하는 방법을 살펴봤습니다.
- 6–10초: 이제 컴퓨터는 하나의 명령어에 따라 계산을 수행할 수 있습니다.
- 10–14초: 하지만 실제 프로그램은 하나의 명령어로 끝나지 않습니다.
- 14–18초: 그렇다면 컴퓨터는 다음에 실행할 명령어를 어떻게 알 수 있을까요?

## 18–34초 · 명령어도 메모리에 저장한다

- 18–22초: 먼저 여러 명령어를 미리 저장해 놓는다고 생각해 보겠습니다.
- 22–27초: 명령어도 결국 0과 1로 이루어진 정보이므로, 메모리에 보관할 수 있습니다.
- 27–34초: 예를 들어 첫 번째 위치에는 두 값을 더하는 명령어를, 두 번째 위치에는 두 값을 빼는 명령어를 저장할 수 있습니다.

## 34–43초 · 어느 위치의 명령어를 가져올까?

- 34–37초: 이제 명령어를 하나씩 외부에서 전달하지 않아도 됩니다.
- 37–40초: 하지만 메모리에는 여러 명령어가 존재합니다.
- 40–43초: 그렇다면 그중 어떤 명령어를 가져와야 할까요?

## 43–57초 · 명령어의 위치를 기억하는 레지스터

- 43–47초: 여기서 앞서 살펴본 레지스터를 다시 활용할 수 있습니다.
- 47–51초: 이번에는 계산 결과가 아니라, 가져올 명령어의 위치를 저장하는 것입니다.
- 51–57초: 이렇게 명령어의 주소를 기억하는 레지스터를 프로그램 카운터, 즉 PC라고 합니다.

## 57–63초 · PC = 0 → 주소 0 인출

- 57–63초: 예를 들어 PC에 0이 저장되어 있다면, 명령어 메모리의 0번 위치에 있는 명령어를 가져옵니다.

## 63–76초 · 인출한 명령어로 계산한다

- 63–66초: 가져온 명령어는 앞서 만든 해독 회로로 전달됩니다.
- 66–72초: 해독 회로는 어떤 데이터를 선택하고, 어떤 연산을 수행할지 결정하는 제어 신호를 만듭니다.
- 72–76초: 그리고 ALU가 계산을 수행하고, 필요한 경우 결과를 레지스터에 기록합니다.

## 76–85초 · PC도 갱신해야 한다

- 76–80초: 이제 다음 명령어를 실행하려면 PC에 저장된 주소를 갱신해야 합니다.
- 80–85초: 명령어가 순서대로 배치되어 있다면, PC를 다음 위치로 증가시키면 됩니다.

## 85–94초 · 인출 · 해독 · 실행

- 85–91초: 이렇게 명령어를 가져오고, 해독하고, 실행하는 과정을 인출, 해독, 실행이라고 합니다.
- 91–94초: 영어로는 Fetch, Decode, Execute입니다.

## 94–107초 · 항상 다음 위치만 실행할까?

- 94–98초: 그런데 컴퓨터가 항상 다음 위치의 명령어만 실행해야 할까요?
- 98–103초: 예를 들어 어떤 계산 결과가 0일 때, 특정 명령어를 건너뛰고 싶을 수도 있습니다.
- 103–107초: 이때는 PC를 단순히 증가시키는 대신, 다른 주소로 변경하면 됩니다.

## 107–120초 · MUX로 다음 PC를 선택한다

- 107–114초: 앞서 살펴본 MUX를 이용하면 순서대로 이어지는 주소와 이동하려는 주소 중 하나를 선택할 수 있습니다.
- 114–120초: 이처럼 조건에 따라 다음에 실행할 명령어의 위치를 바꾸는 것이 분기의 기본적인 원리입니다.

## 120–126초 · 같은 메모리, 다른 실행 경로

- 120–126초: 이제 컴퓨터는 단순히 정해진 연산을 반복하는 것을 넘어, 조건에 따라 실행 순서를 바꿀 수 있게 되었습니다.

## 126–137초 · 계산과 저장을 하나의 구조로

- 126–132초: 지금까지 우리는 전기 신호에서 출발해 논리 게이트와 가산기, ALU를 만들었습니다.
- 132–137초: 그리고 값을 기억하는 회로와 클럭을 추가하고, 레지스터와 데이터 경로를 연결했습니다.

## 137–148초 · 여러 명령어를 실행하는 기본 구조

- 137–141초: 여기에 명령어를 해독하는 회로와 프로그램 카운터까지 더했습니다.
- 141–148초: 이렇게 우리는 계산하는 회로가 여러 명령어를 실행하는 기본적인 프로세서 구조로 발전하는 과정을 살펴봤습니다.

## 148–156초 · 기본 구조에서 더 복잡한 시스템으로

- 148–153초: 물론 이것만으로 현대적인 CPU나 GPU의 모든 기능이 완성된 것은 아닙니다.
- 153–156초: 하지만 이제 새로운 질문을 던질 수 있습니다.

## 156–165초 · 같은 명령어를 더 빠르게 실행하려면?

- 156–159초: 같은 명령어들을 더 빠르게 실행하려면 무엇을 바꿔야 할까요?
- 159–165초: 다음에는 컴퓨터가 계산 속도를 높이기 위해 어떤 구조를 발전시켜 왔는지 살펴보겠습니다.
