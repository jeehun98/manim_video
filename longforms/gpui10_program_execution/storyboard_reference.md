# GPU 개론 10 — 컴퓨터는 어떻게 프로그램을 실행할까?

상세 영상화 콘티 · 총 165초 · 9:16 세로 영상 · Manim 기반 2D 모션그래픽

이번 10편은 GPU 개론 2부의 마지막 영상이야.

따라서 새로운 부품인 프로그램 카운터(PC)를 소개하는 데 그치지 않고, 1\~9편에서 만들어 온 회로들이 어떻게 연결되어 여러 명령어를 실행하는 구조가 되는지 보여줘야 해.

이번 영상의 중심 메시지는 세 가지야.

1. 명령어도 0과 1로 표현된 정보이므로 메모리에 저장할 수 있다.
2. PC에 저장된 주소가 바뀌면 다음에 가져오는 명령어도 달라진다.
3. 분기 명령은 PC의 다음 값을 선택함으로써 프로그램의 실행 순서를 바꾼다.

특히 이전 편에서 소개한 레지스터와 MUX를 다시 활용해 PC와 분기를 구현하는 연출이 중요해. 새로운 회로가 갑자기 나타나는 느낌보다, 기존에 배운 요소들이 새로운 역할을 맡는 모습을 보여주는 것이 좋아.

주소는 명령어 한 개당 1씩 증가하는 가상 슬롯 주소다. 실제 CPU·GPU는 명령어 길이 및 주소 단위에 따라 PC 갱신 방식이 달라진다.

9편에서 만들었던 교육용 8비트 인코딩을 재사용한다면 첫 번째 ADD 명령어는 `00110110`, 두 번째 SUB 명령어는 `01111101`이야. 단, 비트열 자체보다 PC의 값으로 어느 명령어가 선택되는지를 영상에서 더 크게 강조하는 편이 좋아.

# ACT 1. 여러 명령어를 어디에 보관할까?

00:00–00:43 · 지난 9편의 명령어 해독 구조에서 명령어 메모리의 필요성 발견

### 00:00–00:06 — 앞서 만든 명령어 해독 회로

나레이션: 앞서 우리는 0과 1로 명령어를 표현하고, 이를 해독해 실제 회로의 동작을 제어하는 방법을 살펴봤습니다.

화면 연출

9편의 마지막 화면을 그대로 가져와.

상단에는 `00110110`이라는 8비트 명령어가 표시되고, 중앙의 `Instruction Decoder`에 입력돼.

해독 회로의 아래에서는 세 개의 제어 방향이 활성화돼.

- 입력 레지스터 선택: R1, R2
- ALU 연산: ADD
- 목적지 레지스터: R3

ALU에서 `5+3=8`이 계산되는 모습을 짧게 보여줘.

명령어 비트열은 화면 상단에 유지하고, 실제 데이터는 레지스터에서 ALU로 전달되도록 구분해.

### 00:06–00:10 — 명령어 하나의 실행

나레이션: 이제 컴퓨터는 하나의 명령어에 따라 계산을 수행할 수 있습니다.

화면 연출

상단 명령어와 해독 회로를 하나의 작은 구조로 묶어.

중앙에 `ADD R3, R1, R2`를 표시하고, 아래 R3의 값이 `0 → 8`로 갱신되는 장면을 보여줘.

한 명령어의 실행이 완료됐다는 것을 초록색 체크 표시 대신 `R3 = 8`이라는 결과로 전달해.

### 00:10–00:14 — 실제 프로그램은 여러 명령어

나레이션: 하지만 실제 프로그램은 하나의 명령어로 끝나지 않습니다.

화면 연출

단일 명령어 블록이 화면 위쪽으로 이동해.

그 아래로 두 번째, 세 번째 명령어 블록이 차례로 나타나.

첫 번째 `ADD R3, R1, R2`

두 번째 `SUB R3, R3, R1`

세 번째는 아직 내용이 정해지지 않은 빈 블록으로 표시해.

화면 상단에 `하나의 명령어 → 여러 명령어`라는 문구를 짧게 띄워.

### 00:14–00:18 — 다음 명령어를 어떻게 결정할까?

나레이션: 그렇다면 컴퓨터는 다음에 실행할 명령어를 어떻게 알 수 있을까요?

화면 연출

첫 번째 명령어만 밝게 강조해.

첫 번째 명령어에서 두 번째 명령어로 이어지는 화살표를 점선으로 표현해.

화살표 중앙에 `?`를 배치해.

아직 다음 위치를 결정하는 장치가 없기 때문에 화살표가 실제로 이동하는 애니메이션은 실행하지 않아.

### 00:18–00:22 — 여러 명령어를 저장한다

나레이션: 먼저 여러 명령어를 미리 저장해 놓는다고 생각해 보겠습니다.

화면 연출

흩어져 있던 명령어 블록들이 화면 중앙에 세로로 정렬돼.

바깥쪽에 하나의 큰 파란색 테두리가 생기고, 상단에 `Instruction Memory`라는 명칭이 나타나.

각 명령어 왼쪽에는 주소를 표시할 공간을 확보해.

### 00:22–00:27 — 명령어도 0과 1이다

나레이션: 명령어도 결국 0과 1로 이루어진 정보이므로, 메모리에 보관할 수 있습니다.

화면 연출

명령어의 사람이 읽는 표기를 이진수로 변경해.

`ADD R3,R1,R2` → `00110110`

`SUB R3,R3,R1` → `01111101`

명령어 메모리의 각 행이 비트열을 보관하는 모습을 보여줘.

이때 앞선 9편과 동일한 인코딩 규칙이라는 점을 유지해야 해.

### 00:34–00:37 — 외부 입력 없이도 명령어를 보관한다

나레이션: 이제 명령어를 하나씩 외부에서 전달하지 않아도 됩니다.

### 00:37–00:40 — 여러 명령어 중 무엇을 가져올까?

나레이션: 하지만 메모리에는 여러 명령어가 존재합니다.

화면 연출

명령어 메모리의 주소 0과 1을 동시에 강조해.

두 명령어는 서로 다른 비트열이라는 것을 보여주고, 출력단에는 아직 아무것도 표시하지 않아.

### 00:40–00:43 — 주소 선택의 필요성

나레이션: 그렇다면 그중 어떤 명령어를 가져와야 할까요?

화면 연출

메모리 왼쪽에 하나의 `Address` 입력선을 등장시켜.

주소 0과 1의 두 행이 모두 이 입력선의 선택을 기다리는 느낌으로 표현해.

입력선 끝에는 주황색 `?`가 나타나.

여기서는 메모리에 데이터를 저장하는 것과 그중 특정 위치를 선택하는 것은 별개라는 점을 분명히 보여줘.

# ACT 2. 명령어의 위치를 기억하는 레지스터

### 00:43–00:47 — 앞서 만들었던 저장 회로 재사용

나레이션: 여기서 앞서 살펴본 레지스터를 다시 활용할 수 있습니다.

화면 연출

8편에서 등장했던 레지스터 하나가 화면 왼쪽 아래에 나타나.

레지스터의 내부가 잠깐 투명하게 표현되면서 1비트 저장 회로 여러 개로 구성된 모습을 보여줘.

그 후 다시 하나의 레지스터 블록으로 합쳐져.

핵심: PC가 새로운 원리의 저장 장치가 아니라는 점을 시각적으로 연결하는 장면이야.

### 00:47–00:51 — 숫자 대신 주소를 기억한다

나레이션: 이번에는 계산 결과가 아니라, 가져올 명령어의 위치를 저장하는 것입니다.

레지스터 출력 Q를 ALU가 아니라 명령어 메모리의 주소 입력에 연결해.

메모리의 주소 0 행이 파란색으로 밝아져.

상단 문구:

### 00:51–00:57 — 프로그램 카운터의 등장

나레이션: 이렇게 명령어의 주소를 기억하는 레지스터를 프로그램 카운터, 즉 PC라고 합니다.

화면 연출

명칭이 바뀌더라도 블록의 D 입력, Q 출력, 클럭 입력은 그대로 유지해.

PC의 출력 Q가 명령어 메모리의 주소 입력에 연결된 상태에서 두 블록을 중앙에 정렬해.

# ACT 3. 명령어를 가져오고, 해독하고, 실행한다

01:03–01:34 · PC, 메모리, 해독 회로, ALU가 하나로 연결되는 과정

이번 구간은 10편의 첫 번째 핵심 장면이야.

이전까지 따로 설명했던 회로가 하나의 실행 과정으로 연결되므로, 카메라가 새로운 블록으로 계속 이동하는 것보다 모든 회로를 한 화면에 유지하고 활성 신호만 바꾸는 방식을 추천해.

### 01:03–01:06 — 명령어가 해독 회로로 전달된다

화면 연출

해독 회로를 화면 중앙에 배치하고, 메모리는 그 위쪽에 유지해.

필드별로 실제 회로의 제어 입력이 순차 강조돼.

- RS1=01 → R1을 첫 번째 ALU 입력으로 선택

아직 명령어 비트열이 자동으로 연산 결과를 만드는 것처럼 표현하지 말고, 제어 신호가 기존 데이터 경로에 전달되는 모습으로 연출해.

### 01:12–01:16 — ALU 계산과 결과 저장

나레이션: 그리고 ALU가 계산을 수행하고, 필요한 경우 결과를 레지스터에 기록합니다.

화면 연출

R1=5와 R2=3에서 두 개의 읽기 경로가 활성화돼.

ALU 출력에 `8`이 표시돼.

그다음 R3로 이어지는 쓰기 경로를 초록색으로 강조해.

유효한 클럭 에지가 발생하는 순간 R3가 `0 → 8`로 갱신돼.

장면 종료 상태

`R1=5`, `R2=3`, `R3=8`

명령어 `ADD R3,R1,R2`가 완료된 것으로 표시해.

### 01:16–01:20 — 다음 명령어를 실행하려면?

나레이션: 이제 다음 명령어를 실행하려면 PC에 저장된 주소를 갱신해야 합니다.

화면 연출

R3의 결과 8을 유지하고, 이번에는 PC를 확대해.

PC 오른쪽에 `Next Address`라는 작은 입력 후보를 등장시켜.

중요한 연출: ALU가 계산을 끝냈다고 해서 PC가 자동으로 다음 주소를 기억하는 것은 아니야. PC도 레지스터이기 때문에 다음 주소를 입력으로 받고, 적절한 저장 시점에 값을 갱신해야 해.

### 01:20–01:25 — PC를 다음 위치로 증가시킨다

# ACT 4. 컴퓨터는 반드시 다음 명령어만 실행해야 할까?

이번 구간은 10편의 두 번째 핵심 장면이야.

앞부분에서는 PC를 증가시키기만 해도 여러 명령어를 순서대로 실행할 수 있다는 사실을 확인했어.

이제 다른 명령어를 선택하는 새로운 방법을 추가하면 돼.

### 01:34–01:38 — 항상 다음 명령어만 실행해야 할까?

나레이션: 그런데 컴퓨터가 항상 다음 위치의 명령어만 실행해야 할까요?

명령어 메모리에 주소 0, 1, 2, 3의 네 행을 배치해.

현재 PC는 1이고, 주소 1의 명령어가 선택된 상태로 시작해.

기존 구조대로라면 PC가 2로 증가하고, 주소 2를 실행하게 돼.

화면에 `1 → 2 → 3`이라는 순차적인 화살표를 표시해.

그다음 주소 2를 건너뛰고 주소 3으로 바로 이동하는 점선 화살표가 나타나.

나레이션: 예를 들어 어떤 계산 결과가 0일 때, 특정 명령어를 건너뛰고 싶을 수도 있습니다.

화면 연출

왼쪽에는 레지스터의 저장값 `0`을 표시해.

중앙에는 다음 조건을 제시해.

`값 == 0 ?`

오른쪽에는 명령어 메모리의 주소 1, 2, 3을 표시해.

조건이 참이면 주소 2를 건너뛰고 주소 3으로 이동하는 화살표를 강조해.

이때 주소 2의 명령어가 메모리에서 삭제되는 것이 아니라, 실행 경로에서 선택되지 않는 것임을 보여줘.

### 01:43–01:47 — PC에 다른 주소를 저장한다

나레이션: 이때는 PC를 단순히 증가시키는 대신, 다른 주소로 변경하면 됩니다.

화면 연출

기존 PC와 `PC+1` 회로를 다시 보여줘.

원래의 다음 주소 후보는 2야.

여기에 새로운 주소 후보 3을 추가해.

화면에서 다음 두 값을 나란히 표시해.

`Sequential = 2`

`Branch Target = 3`

PC는 아직 1을 저장하고 있어.

이제 PC의 입력 D 앞에 두 주소 후보가 존재하는 상황을 만들어.

### 01:47–01:54 — MUX로 다음 주소 선택

나레이션: 앞서 살펴본 MUX를 이용하면 순서대로 이어지는 주소와 이동하려는 주소 중 하나를 선택할 수 있습니다.

화면 연출

두 주소 입력 사이에 5편과 8편에서 등장했던 MUX 블록을 배치해.

MUX의 위쪽 입력은 `PC+1`, 아래쪽 입력은 `Branch Target`이야.

MUX의 출력은 PC의 D 입력에 연결돼.

제어 신호는 `Branch Taken`으로 표시해.

MUX를 이용한 다음 PC 선택

분기 조건이 거짓이므로 다음 주소 2가 선택된다.

MUX가 선택한 주소는 PC 입력에 제공되고, PC는 유효한 갱신 시점에 그 값을 저장한다.

애니메이션에서는 조건이 거짓일 때 위쪽 경로가 초록색으로 강조되고, 조건이 참일 때 아래쪽 경로가 초록색으로 강조되도록 해.

중요한 점은 두 경로의 배선이 모두 존재하고, 제어 신호에 따라 선택되는 경로만 달라진다는 사실이야.

나레이션: 이처럼 조건에 따라 다음에 실행할 명령어의 위치를 바꾸는 것이 분기의 기본적인 원리입니다.

### 02:00–02:06 — 실행 순서가 달라진다

## 실제 제작 시 중요한 기술적 주의사항

첫째, PC의 주소 증가를 지나치게 일반화하지 않기.

이번 영상에서는 교육용으로 명령어마다 주소가 1씩 증가한다고 가정했어. 실제 프로세서는 명령어 길이와 주소 지정 방식에 따라 다음 PC 계산이 달라질 수 있어. 따라서 화면 한쪽에 `가상 명령어 슬롯 주소`라는 작은 표기를 유지하면 좋아.

둘째, 클럭과 데이터 흐름을 구분하기.

PC에 주소가 저장되면 해당 주소의 메모리 출력이 결정되고, 해독 회로 및 연산 회로가 조합논리에 따라 동작할 수 있어. 그러나 레지스터에 값을 기록하고 PC를 갱신하는 시점은 해당 저장 회로의 클럭 및 제어 방식에 의해 결정돼. 영상의 단계별 연출은 논리적인 설명 순서이지 반드시 실제 하드웨어의 모든 신호가 그 순서대로만 변한다는 뜻은 아니야.

셋째, 분기에서 명령어 자체가 이동하는 것으로 표현하지 않기.

분기는 명령어 메모리의 내용을 바꾸는 동작이 아니야. PC에 저장할 다음 주소를 변경함으로써 다음에 선택할 명령어를 바꾸는 동작이지.

넷째, 2부의 마지막 영상답게 이미 배운 회로를 재사용하기.

SR 래치, 플립플롭, 레지스터, ALU, MUX, 해독 회로는 모두 이전 편에서 사용한 시각적 형태를 유지하는 것이 좋아. 시청자는 익숙한 회로가 다시 등장할 때 별도의 설명 없이도 이전 지식과 연결할 수 있어.
