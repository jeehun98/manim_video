# 04 · 명령어의 위치를 기억하는 레지스터

목적·주장: PC는 명령어 자체가 아니라 인출할 주소를 기억한다.

시작: 어느 위치의 명령어를 가져올까?

확정길이: 43–57초(14초). 사용자 문장 종료 시각을 그대로 사용한다.

## 확정 대본·화면 변화 시각
- 43–47초: 여기서 앞서 살펴본 레지스터를 다시 활용할 수 있습니다.
- 47–51초: 이번에는 계산 결과가 아니라, 가져올 명령어의 위치를 저장하는 것입니다.
- 51–57초: 이렇게 명령어의 주소를 기억하는 레지스터를 프로그램 카운터, 즉 PC라고 합니다.

## 화면과 텍스트
../../storyboard_reference.md의해당구간,../../scene_engine.py의pc참조. 가로1920×1080/세로1080×1920별도배치.30fps. PC와저장초록,메모리파랑,해독·연산보라,분기·제어주황. PC입출력D/Q·CLK,Address,InstructionMemory,Fetch/Decode/Execute,PC+1,BranchTarget,BranchTaken을일관되게사용한다. 자막한객체를문장경계에서교체하고세로최대높이1.95로제한한다.

## 정확성·전제
가상슬롯주소는명령어1개당+1이며실제ISA의바이트주소증분을일반화하지않는다.명령어형식OP|RD|RS1|RS2각2비트. ADD00110110,SUB01111101.초기R1=5,R2=3,R3=0→ADD후8→SUB후3. PC는주소,메모리는명령어,레지스터는계산데이터를보관한다. PC와일반레지스터쓰기에는해당유효갱신에지가필요하다.단계애니메이션은설명순서이지특정마이크로아키텍처의사이클수주장이아니다. 분기는별도예시로조건판정·목표주소계산후의선택을보여주며8비트산술ISA에분기명령인코딩을임의로추가하지않는다.조건거짓PC1→2,참PC1→3.명령어메모리는변하지않는다.후보두입력과MUX배선은고정한다. 사용자제공요약·마지막문장은유지하되추가GPU11예고·NEXT타이틀은넣지않는다.성능배율·현대CPU/GPU완성주장은없다.

종료: PC는 명령어 자체가 아니라 인출할 주소를 기억한다.
연결: PC = 0 → 주소 0 인출
