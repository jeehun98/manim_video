# 13 · 여러 명령어를 실행하는 기본 구조

목적·주장: PC·메모리·해독·데이터경로와PC갱신을하나의시스템으로보여준다.

시작: 계산과 저장을 하나의 구조로

확정길이: 137–148초(11초). 사용자 문장 종료 시각을 그대로 사용한다.

## 확정 대본·화면 변화 시각
- 137–141초: 여기에 명령어를 해독하는 회로와 프로그램 카운터까지 더했습니다.
- 141–148초: 이렇게 우리는 계산하는 회로가 여러 명령어를 실행하는 기본적인 프로세서 구조로 발전하는 과정을 살펴봤습니다.

## 화면과 텍스트
../../storyboard_reference.md의해당구간,../../scene_engine.py의processor참조. 가로1920×1080/세로1080×1920별도배치.30fps. PC와저장초록,메모리파랑,해독·연산보라,분기·제어주황. PC입출력D/Q·CLK,Address,InstructionMemory,Fetch/Decode/Execute,PC+1,BranchTarget,BranchTaken을일관되게사용한다. 자막한객체를문장경계에서교체하고세로최대높이1.95로제한한다.

## 정확성·전제
가상슬롯주소는명령어1개당+1이며실제ISA의바이트주소증분을일반화하지않는다.명령어형식OP|RD|RS1|RS2각2비트. ADD00110110,SUB01111101.초기R1=5,R2=3,R3=0→ADD후8→SUB후3. PC는주소,메모리는명령어,레지스터는계산데이터를보관한다. PC와일반레지스터쓰기에는해당유효갱신에지가필요하다.단계애니메이션은설명순서이지특정마이크로아키텍처의사이클수주장이아니다. 분기는별도예시로조건판정·목표주소계산후의선택을보여주며8비트산술ISA에분기명령인코딩을임의로추가하지않는다.조건거짓PC1→2,참PC1→3.명령어메모리는변하지않는다.후보두입력과MUX배선은고정한다. 사용자제공요약·마지막문장은유지하되추가GPU11예고·NEXT타이틀은넣지않는다.성능배율·현대CPU/GPU완성주장은없다.
