# 01 · 다음 명령어는 어떻게 알까?

목적·주장: 단일 명령의 실행에서 다음 명령어 선택 문제로 연결한다.

시작: 명령어·해독·ALU 기존 구조

확정길이: 0–18초(18초). 사용자 문장 종료 시각을 그대로 사용한다.

## 확정 대본·화면 변화 시각
- 0–6초: 앞서 우리는 0과 1로 명령어를 표현하고, 이를 해독해 실제 회로의 동작을 제어하는 방법을 살펴봤습니다.
- 6–10초: 이제 컴퓨터는 하나의 명령어에 따라 계산을 수행할 수 있습니다.
- 10–14초: 하지만 실제 프로그램은 하나의 명령어로 끝나지 않습니다.
- 14–18초: 그렇다면 컴퓨터는 다음에 실행할 명령어를 어떻게 알 수 있을까요?

## 화면과 텍스트
../../storyboard_reference.md의해당구간,../../scene_engine.py의hook참조. 가로1920×1080/세로1080×1920별도배치.30fps. PC와저장초록,메모리파랑,해독·연산보라,분기·제어주황. PC입출력D/Q·CLK,Address,InstructionMemory,Fetch/Decode/Execute,PC+1,BranchTarget,BranchTaken을일관되게사용한다. 자막한객체를문장경계에서교체하고세로최대높이1.95로제한한다.

## 정확성·전제
가상슬롯주소는명령어1개당+1이며실제ISA의바이트주소증분을일반화하지않는다.명령어형식OP|RD|RS1|RS2각2비트. ADD00110110,SUB01111101.초기R1=5,R2=3,R3=0→ADD후8→SUB후3. PC는주소,메모리는명령어,레지스터는계산데이터를보관한다. PC와일반레지스터쓰기에는해당유효갱신에지가필요하다.단계애니메이션은설명순서이지특정마이크로아키텍처의사이클수주장이아니다. 분기는별도예시로조건판정·목표주소계산후의선택을보여주며8비트산술ISA에분기명령인코딩을임의로추가하지않는다.조건거짓PC1→2,참PC1→3.명령어메모리는변하지않는다.후보두입력과MUX배선은고정한다. 사용자제공요약·마지막문장은유지하되추가GPU11예고·NEXT타이틀은넣지않는다.성능배율·현대CPU/GPU완성주장은없다.
