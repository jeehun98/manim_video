# 01 · 여러 선택을 하나의 정보로

주장: 데이터 경로를 외부에서 지정하던 선택들의 묶음을 도출한다.

시작: 레지스터·MUX·ALU 데이터 경로

확정 길이: 0–16초, 16초. 사용자 제공 발화시간을 그대로 사용한다.

## 확정 대본 및 화면 변화 시점
- 0–7초: 앞서 우리는 레지스터에 저장된 값을 선택해 ALU로 전달하고, 계산 결과를 다시 저장하는 데이터 경로를 만들었습니다.
- 7–13초: 하지만 지금까지는 어떤 값을 선택하고, 어떤 연산을 수행할지 직접 지정해야 했습니다.
- 13–16초: 그렇다면 이러한 선택을 하나의 정보로 표현할 수는 없을까요?

## 화면
상세 콘티 ../../storyboard_reference.md, 구현 ../../scene_engine.py의 hook. 가로1920×1080/세로1080×1920 별도 배치,30fps. OP 주황,RD 초록,RS1 파랑,RS2 보라. 중앙의 기존 데이터 경로를 유지하고 필드별 연결과 활성 경로를 강조한다. 자막은 문장 경계에 단일 Text를 교체하며 전환 중 중첩하지 않는다.

## 정확성
8비트는 교육용 가상 ISA이며 GPU/CUDA 기계어가 아니다. OP|RD|RS1|RS2의 네 2비트 필드다. 00110110은 ADD R3,R1,R2. 레지스터 식별자는 번호이고 저장값은 별도의4비트 데이터다. R0도 일반 레지스터로 가정하며 특정 실제ISA의zero레지스터를 암시하지 않는다. 주소 필드는 읽기·쓰기 선택에 전달될 수 있으며 OP는 이미 설계된 해독 논리로 ALU 제어를 만든다. WE는 실행 유효 시점의 제어이며 임의의 특정 명령어 비트 하나로 설명하지 않는다. 쓰기 대상 선택+WE+CLK상승에지에서만 갱신하며 읽기는 비파괴적이다. ADD→SUB 비교 때 WE=0으로 R3=8을 유지한다. 배선·블록 위치는 변경하지 않는다. 후속 명령어는 ???????? 자리 표시자이며 이번 편에서 실행하지 않는다. 사용자 도입·끝 원문은 유지하되 추가 복습 및 GPU10 예고 타이틀은 넣지 않는다.
