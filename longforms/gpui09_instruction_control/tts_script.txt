앞서 우리는 레지스터에 저장된 값을 선택해 에이 엘 유로 전달하고, 계산 결과를 다시 저장하는 데이터 경로를 만들었습니다.

하지만 지금까지는 어떤 값을 선택하고, 어떤 연산을 수행할지 직접 지정해야 했습니다.

그렇다면 이러한 선택을 하나의 정보로 표현할 수는 없을까요?

예를 들어 첫 번째 레지스터에 5, 두 번째 레지스터에 3이 저장되어 있다고 생각해 보겠습니다.

두 값을 더해 세 번째 레지스터에 저장하려면 몇 가지 선택이 필요합니다.

먼저 첫 번째와 두 번째 레지스터의 값을 가져와야 합니다.

그리고 에이 엘 유가 덧셈을 수행하도록 설정하고, 결과는 세 번째 레지스터에 기록해야 합니다.

지금까지는 각각의 회로에 제어 신호를 전달해 이러한 동작을 결정했습니다.

그런데 우리가 계산할 숫자를 0과 1로 표현했던 것처럼, 수행할 동작도 0과 1로 표현하면 어떨까요?

예를 들어 두 비트의 값이 00이면 덧셈, 01이면 뺄셈을 의미하도록 규칙을 정할 수 있습니다.

마찬가지로 각 레지스터에도 번호를 부여하고, 이를 이진수로 표현할 수 있습니다.

이제 연산 종류와 입력 레지스터, 결과를 저장할 레지스터의 번호를 하나의 비트열로 묶어보겠습니다.

이것이 명령어의 기본적인 아이디어입니다.

예를 들어 첫 번째와 두 번째 레지스터의 값을 더해 세 번째 레지스터에 저장한다는 명령을 만들 수 있습니다.

하지만 비트열을 회로에 전달한다고 해서 에이 엘 유가 자동으로 그 의미를 이해하는 것은 아닙니다.

각 비트가 어떤 동작을 의미하는지 해석하고, 실제 회로에 필요한 제어 신호로 연결해야 합니다.

이를 담당하는 것이 명령어 해독 회로입니다.

해독 회로는 명령어의 각 부분을 확인해 어떤 레지스터를 선택할지, 어떤 연산을 수행할지, 결과를 어디에 저장할지 결정하는 신호를 만듭니다.

이 신호에 따라 먹스는 필요한 데이터를 에이 엘 유로 전달하고, 에이 엘 유는 지정된 연산을 수행합니다.

그리고 계산 결과는 선택된 레지스터에 기록됩니다.

여기서 중요한 것은 명령어가 회로의 물리적인 연결을 바꾸는 것은 아니라는 점입니다.

연산 회로와 데이터 경로는 이미 설계되어 있습니다.

명령어는 그중 어떤 기능을 사용하고, 어떤 데이터를 전달할지 지정하는 것입니다.

이제 우리는 여러 제어 신호를 각각 직접 설정하는 대신, 하나의 명령어로 회로의 동작을 지정할 수 있게 되었습니다.

하지만 아직 명령어는 하나씩 외부에서 제공해야 합니다.

그렇다면 여러 명령어를 미리 저장해 놓고, 컴퓨터가 다음에 실행할 명령어를 스스로 찾아오도록 만들 수는 없을까요?
