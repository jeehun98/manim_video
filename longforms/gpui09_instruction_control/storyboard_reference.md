# GPU 개론 09 — 명령어는 어떻게 회로를 제어할까?

상세 영상화 콘티 · 총 141초 · 9:16 세로 영상 · Manim 기반 2D 애니메이션

이번 편의 시각적 핵심은 지금까지 사람이 직접 조작하던 여러 제어 신호를 하나의 비트열로 표현하고, 그 비트열이 실제 회로의 동작을 결정하는 과정이야.

이전 8편에서는 레지스터, MUX, ALU를 연결해 데이터 경로를 완성했어. 따라서 이번 영상에서는 새로운 연산 장치를 만드는 대신 기존 데이터 경로 위에 명령어 해독 및 제어 구조를 추가하는 방식으로 진행하는 게 좋아.

특히 영상의 중심 장면은 다음과 같아.

이번 영상에서 완성할 회로 구조

개념적 전체 구조. 두 피연산자용 읽기 경로와 쓰기 대상 선택은 실제 상세 장면에서 각각 구분해 표현한다.

8비트 명령어는 이번 영상에서 정의한 가상의 형식이다. 연산 2비트, 목적지 2비트, 입력 레지스터 각각 2비트로 구성한다.

실제 회로에서 잘못된 동작이 나오지 않게, 레지스터 식별자는 `R0=00`, `R1=01`, `R2=10`, `R3=11`로 고정하고, ALU는 4비트 정수 연산을 수행하는 것으로 통일해.

# ACT 1. 계산 회로에는 선택할 것이 많다

00:00–00:40 · 이전 8편의 데이터 경로에서 새로운 문제 발견

### 00:00–00:07 — 이전 편의 데이터 경로

나레이션: 앞서 우리는 레지스터에 저장된 값을 선택해 ALU로 전달하고, 계산 결과를 다시 저장하는 데이터 경로를 만들었습니다.

화면 구성

8편 마지막 장면에서 사용한 데이터 경로를 그대로 이어받아.

- 왼쪽: R1, R2, R3 저장 블록
- 가운데: 입력 A용 MUX, 입력 B용 MUX
- 오른쪽: ALU
- 아래쪽: ALU 결과를 레지스터로 되돌리는 쓰기 경로

처음에는 모든 연결선을 어둡게 표시해.

그다음 R1에서 입력 A용 MUX를 거쳐 ALU로 이어지는 경로를 파란색으로 강조해. R2에서 입력 B용 MUX로 이어지는 경로는 보라색으로 강조해.

ALU가 계산한 결과는 초록색으로 쓰기 경로를 따라 이동해.

연출 포인트: 화면에는 아직 명령어나 해독 회로가 등장하지 않아. 8편에서 완성한 회로가 이번 영상의 출발점이라는 점만 보여줘.

### 00:07–00:13 — 지금까지는 직접 제어했다

나레이션: 하지만 지금까지는 어떤 값을 선택하고, 어떤 연산을 수행할지 직접 지정해야 했습니다.

화면 구성

기존 데이터 경로 위에 세 개의 작은 제어 표시를 추가해.

`Select A`, `Select B`, `ALU OP`

각 제어 표시가 바뀌면 MUX 출력이나 ALU 연산 종류가 바뀌는 모습을 간단히 보여줘.

이때 화면 가장자리에는 가상의 수동 제어 패널을 배치할 수 있어.

제어 패널에서 `R1`, `R2`, `ADD`를 각각 지정하면 데이터 경로가 활성화돼.

중요: 실제 회로에 누군가 손으로 스위치를 움직여야 한다는 의미가 아니라, 이전 영상의 설명에서 선택 신호를 외부에서 임의로 지정했다는 뜻이야.

### 00:13–00:16 — 여러 선택을 하나로 표현한다면?

나레이션: 그렇다면 이러한 선택을 하나의 정보로 표현할 수는 없을까요?

화면 구성

세 개의 제어 표시가 화면 중앙으로 모여.

`입력 선택 / 연산 선택 / 저장 위치`

세 항목 주위에 하나의 얇은 테두리가 그려져.

그 안에는 아직 내용을 표시하지 않고 `?`만 둬.

이후 테두리를 화면 상단으로 이동시키면서 다음 장면으로 넘어가.

### 00:16–00:22 — 레지스터에 5와 3 저장

나레이션: 예를 들어 첫 번째 레지스터에 5, 두 번째 레지스터에 3이 저장되어 있다고 생각해 보겠습니다.

화면 구성

중앙에 레지스터 세 개를 세로로 배치해.

| 레지스터 | 저장값 | 4비트    |
| ---- | --- | ------ |
| R1   | 5   | `0101` |
| R2   | 3   | `0011` |
| R3   | 0   | `0000` |

R1과 R2는 초록색으로 밝게 표시하고, R3는 아직 결과가 없는 상태이므로 회색으로 표현해.

영상에서는 숫자를 크게, 이진수는 그 아래에 작게 표시해.

### 00:22–00:27 — 원하는 계산 결과

나레이션: 두 값을 더해 세 번째 레지스터에 저장하려면 몇 가지 선택이 필요합니다.

화면 구성

레지스터 오른쪽에 작은 ALU 블록을 배치해.

R1과 R2에서 ALU로 향하는 두 경로를 점선으로 표시하고, ALU에서 R3로 향하는 쓰기 경로도 점선으로 표시해.

화면 중앙에는 다음 연산을 표시해.

`R3 ← R1 + R2`

아직 실제 계산을 수행하지 않아.

선택해야 할 경로들을 먼저 제시하는 장면이야.

### 00:27–00:30 — 두 레지스터의 값 읽기

나레이션: 먼저 첫 번째와 두 번째 레지스터의 값을 가져와야 합니다.

화면 구성

R1과 R2를 각각 파란색과 보라색으로 강조해.

두 레지스터의 출력선이 각각 ALU의 A와 B 입력으로 이어지도록 해.

이때 선택되지 않은 다른 레지스터의 읽기 경로는 회색으로 유지해.

중앙의 ALU 입력에는 `A=5`, `B=3`이 나타나.

### 00:30–00:36 — 연산과 저장 위치 결정

나레이션: 그리고 ALU가 덧셈을 수행하도록 설정하고, 결과는 세 번째 레지스터에 기록해야 합니다.

화면 구성

ALU 아래에 `OP = ADD`가 나타나고, ALU 출력에 8이 표시돼.

다음에는 쓰기 경로가 R3로 강조돼.

저장 직전에는 `Destination = R3`를 표시하고, 유효한 쓰기 클럭 에지가 발생했을 때 R3의 값이 0에서 8로 갱신되는 모습을 보여줘.

기존 R1=5와 R2=3은 변하지 않아야 해.

### 00:36–00:40 — 세 종류의 제어 신호

나레이션: 지금까지는 각각의 회로에 제어 신호를 전달해 이러한 동작을 결정했습니다.

화면 구성

방금 실행한 회로를 잠깐 멈추고 화면에 다음 세 항목을 표시해.

입력 선택

R1, R2

연산 선택

ADD

저장 위치

R3

각 항목 왼쪽에는 별도의 주황색 제어선이 연결된 듯한 구성을 만들어.

여기까지의 결론: ALU가 계산할 수 있는 것과 어떤 계산을 실행할지 결정하는 것은 다른 문제야.

# ACT 2. 수행할 동작도 0과 1로 표현한다

00:40–01:13 · 제어 신호를 명령어 비트열로 묶는 과정

### 00:40–00:46 — 숫자뿐 아니라 동작도 정보가 된다

나레이션: 그런데 우리가 계산할 숫자를 0과 1로 표현했던 것처럼, 수행할 동작도 0과 1로 표현하면 어떨까요?

화면 구성

화면 왼쪽에는 숫자 5가 `0101`로 변환되는 모습을 보여줘.

오른쪽에는 `ADD`라는 글자가 등장하고, 아래에 `??`라는 두 개의 비트 자리 표시를 만들어.

숫자 표현과 연산 종류 표현을 나란히 놓아.

이후 `ADD` 아래의 물음표가 `00`으로 바뀌어.

핵심 문구:

`숫자뿐 아니라 동작도 비트로 표현할 수 있다`

### 00:46–00:53 — 연산 종류를 이진수로 정의

나레이션: 예를 들어 두 비트의 값이 00이면 덧셈, 01이면 뺄셈을 의미하도록 규칙을 정할 수 있습니다.

화면 구성

화면 중앙에 연산 선택표를 만들어.

연산 코드의 예시

## 00

ADD

## 01

SUB

## 10

AND

## 11

OR

처음에는 00과 01만 보여주고, 나머지 10과 11은 작게 추가해도 좋아.

ALU의 선택 신호가 00으로 바뀌면 ADD 경로가 강조되고, 01로 바뀌면 SUB 경로가 강조되는 장면을 이어 붙여.

연산 코드는 인위적으로 정한 규칙임을 나타내기 위해 `예시 인코딩`이라는 작은 문구를 넣어줘.

### 00:53–00:58 — 레지스터 번호도 이진수로

나레이션: 마찬가지로 각 레지스터에도 번호를 부여하고, 이를 이진수로 표현할 수 있습니다.

화면 구성

연산 코드표가 왼쪽으로 이동하고 오른쪽에 네 개의 레지스터가 나타나.

`R0 = 00`

`R1 = 01`

`R2 = 10`

`R3 = 11`

각 레지스터의 비트 번호는 이후 명령어의 필드에서 그대로 사용해.

특히 R1과 R2는 입력으로, R3는 결과 저장 위치로 사용한다는 점을 색상으로 연결해.

### 00:58–01:03 — 각 선택 정보를 하나의 비트열로

나레이션: 이제 연산 종류와 입력 레지스터, 결과를 저장할 레지스터의 번호를 하나의 비트열로 묶어보겠습니다.

화면 구성

여기서 영상의 가장 중요한 명령어 구조를 처음 만들어.

화면에 흩어져 있던 네 정보가 차례로 중앙으로 이동해.

- `ADD = 00`
- `R3 = 11`
- `R1 = 01`
- `R2 = 10`

이 네 항목을 하나의 가로 막대 안에 배치해.

하나의 명령어로 묶기

OP

## 00

RD

## 11

RS1

## 01

RS2

## 10

# 00110110

비트열은 오른쪽에서 왼쪽으로 역순으로 읽히지 않도록, 필드 위치를 고정해.

### 01:03–01:06 — 명령어라는 이름 부여

나레이션: 이것이 명령어의 기본적인 아이디어입니다.

화면 구성

방금 완성한 `00110110` 전체를 하나의 직사각형 테두리로 감싸.

상단에 `Instruction`이라는 명칭이 등장해.

이때 내부 비트들이 다시 네 필드로 분리되었다가 합쳐지는 짧은 움직임을 보여줘.

비트 필드들이 실제로 물리적으로 합쳐지는 것은 아니라, 하나의 명령어 형식 안에 서로 다른 정보가 들어 있다는 뜻으로 연출해.

### 01:06–01:13 — 명령어의 의미 설명

나레이션: 예를 들어 첫 번째와 두 번째 레지스터의 값을 더해 세 번째 레지스터에 저장한다는 명령을 만들 수 있습니다.

화면 구성

비트열 아래에 사람이 이해하기 쉬운 형태를 표시해.

`00110110`

↓

`ADD R3, R1, R2`

↓

`R3 ← R1 + R2`

세 표현을 위에서 아래로 연결해.

비트열의 각 필드가 명령문의 어떤 부분에 대응하는지 해당 색상을 유지하면서 가느다란 연결선을 그려줘.

여기서는 기계어 비트열과 사람이 읽기 쉬운 명령어 표기 사이에 미리 정의된 대응 관계가 있다는 점을 보여주는 것이 중요해.

# ACT 3. 비트열은 어떻게 실제 제어 신호가 될까?

01:13–01:35 · 명령어 해독 회로가 필요한 이유와 제어 신호의 생성

### 01:13–01:18 — 비트열은 스스로 의미를 이해하지 않는다

나레이션: 하지만 비트열을 회로에 전달한다고 해서 ALU가 자동으로 그 의미를 이해하는 것은 아닙니다.

화면 구성

중앙에 ALU 하나만 크게 표시해.

왼쪽에서 `00110110`이라는 8비트 명령어가 ALU를 향해 이동해.

하지만 ALU 입력은 A와 B 두 개의 데이터 입력, 연산 선택 신호만 존재하므로 8비트 명령어 전체를 단순히 A 입력에 넣는다고 원하는 동작이 실행되지 않는다는 점을 강조해.

명령어가 ALU 데이터 입력 바로 앞에서 멈추고, ALU 주변에 필요한 입력 종류가 표시돼.

`Data A`, `Data B`, `Operation`

비트열을 ALU 안으로 밀어 넣는 연출은 피하고, 명령어와 계산 데이터는 회로에서 담당하는 역할이 다르다는 사실을 보여줘.

### 01:18–01:23 — 각각의 필드를 해석해야 한다

나레이션: 각 비트가 어떤 동작을 의미하는지 해석하고, 실제 회로에 필요한 제어 신호로 연결해야 합니다.

화면 구성

비트열이 다시 네 부분으로 분리돼.

`OP | RD | RS1 | RS2`

각 필드 아래에 해당 목적을 표시해.

- OP: 연산 종류
- RD: 결과 저장 위치
- RS1: 첫 번째 입력 레지스터
- RS2: 두 번째 입력 레지스터

비트 필드 아래쪽에는 실제 회로로 이어지는 배선들을 점선으로 그려.

일부 필드는 주소 선택선으로 직접 전달될 수 있고, OP처럼 연산 선택을 위한 추가 해석이 필요한 필드도 있다는 점을 화면 구성에 반영해.

### 01:23–01:26 — 명령어 해독 회로

나레이션: 이를 담당하는 것이 명령어 해독 회로입니다.

화면 구성

기존 비트열 아래에 주황색 테두리의 `Instruction Decoder` 블록이 등장해.

비트열이 해독 회로의 입력으로 연결되고, 아래쪽에는 여러 제어 출력선이 추가돼.

이때 해독 회로 내부를 복잡하게 묘사하지 않고 작은 논리 게이트와 배선 몇 개만 보이게 해.

명령어 해독 역시 결국 미리 설계된 논리 회로에서 수행된다는 사실을 자연스럽게 암시하는 정도면 충분해.

### 01:26–01:35 — 제어 신호 생성

나레이션: 해독 회로는 명령어의 각 부분을 확인해 어떤 레지스터를 선택할지, 어떤 연산을 수행할지, 결과를 어디에 저장할지 결정하는 신호를 만듭니다.

화면 구성

해독 회로 아래쪽에 다음 제어 정보가 차례로 나타나.

명령어 해독 결과

| 읽기 주소 A | R1 = 01  |
| ------- | -------- |
| 읽기 주소 B | R2 = 10  |
| ALU 연산  | ADD = 00 |
| 쓰기 주소   | R3 = 11  |

이 장면은 단순히 글자만 표시하기보다, 각각의 필드에서 실제 제어 입력으로 연결되는 선을 하나씩 강조하는 것이 중요해.

예를 들어 RS1 필드의 `01`은 첫 번째 레지스터 읽기 주소 경로로 전달되고, RD 필드의 `11`은 목적지 레지스터 선택 경로로 전달돼.

쓰기 허용 신호는 이 명령어가 계산 결과를 기록하도록 설계된 명령이라는 사실과 실행 시점에 따라 제어 회로에서 활성화한다고 가정해.

# ACT 4. 하나의 명령어가 실제로 실행된다

01:35–02:06 · 저장된 숫자를 읽고 계산한 뒤 결과를 기록하는 전체 실행 과정

이 구간에서는 화면을 크게 전환하지 말고, 같은 데이터 경로 위에서 어느 배선이 활성화되는지만 순서대로 보여주는 연출을 추천해.

### 01:35–01:42 — MUX 선택과 ALU 계산

나레이션: 이 신호에 따라 MUX는 필요한 데이터를 ALU로 전달하고, ALU는 지정된 연산을 수행합니다.

화면 구성

화면 상단에는 명령어 `00110110`이 작게 유지돼.

중앙에는 레지스터와 두 개의 읽기 선택 경로, ALU가 나타나.

먼저 읽기 주소 A=01에 의해 R1의 값 5가 선택돼. 파란색 경로가 ALU 입력 A까지 강조돼.

다음에는 읽기 주소 B=10에 의해 R2의 값 3이 선택돼. 보라색 경로가 ALU 입력 B까지 강조돼.

마지막으로 ALU 연산 선택이 ADD로 설정되고 출력에 `8`이 나타나.

실제 레지스터 파일이 MUX를 내부에 포함하는 방식으로 구현될 수도 있으므로, 영상에서는 기존 8편에서 사용한 MUX 구조를 그대로 재사용해 일관성을 유지하면 돼.

### 01:42–01:45 — 결과 저장

나레이션: 그리고 계산 결과는 선택된 레지스터에 기록됩니다.

화면 구성

ALU 출력 `8`에서 R3로 이어지는 쓰기 경로가 초록색으로 강조돼.

R3는 처음에 0이었지만, 쓰기 주소=R3와 쓰기 허용이 설정된 상태에서 유효한 클럭 에지가 발생하면 `8`로 갱신돼.

R1=5와 R2=3은 그대로 유지해.

실행 결과

R1

# 5

R2

# 3

R3

# 0

ADD R3, R1, R2 실행명령어 실행 전에는 R3=0, 실행 후에는 R3=8. 입력 레지스터의 값은 그대로 유지된다.

### 01:45–01:51 — 물리적인 배선은 바뀌지 않는다

나레이션: 여기서 중요한 것은 명령어가 회로의 물리적인 연결을 바꾸는 것은 아니라는 점입니다.

화면 구성

데이터 경로를 화면 중앙에 크게 고정해.

그다음 상단의 명령어가 `ADD`에서 `SUB`로 변경되는 가상의 비교 장면을 짧게 보여줘.

- 동일한 ALU
- 동일한 레지스터
- 동일한 MUX
- 동일한 물리적 연결선

달라지는 것은 연산 선택 신호와 활성화되는 회로 내부 경로뿐이야.

배선이 이동하거나 기존 게이트가 다른 게이트로 변형되는 연출을 사용하지 않아야 해.

### 01:51–01:54 — 회로는 이미 설계되어 있다

나레이션: 연산 회로와 데이터 경로는 이미 설계되어 있습니다.

화면 구성

화면에 남은 데이터 경로의 모든 블록을 회색 외곽선으로 잠깐 강조해.

그다음 각 블록에 작은 표기를 추가해.

`ALU — Fixed Hardware`

`MUX — Fixed Hardware`

`Registers — Fixed Hardware`

이를 통해 명령어 실행이 물리 회로의 재구성이 아니라, 이미 설계된 하드웨어의 동작을 선택하는 과정이라는 것을 보여줘.

### 01:54–01:59 — 명령어는 기능을 선택한다

나레이션: 명령어는 그중 어떤 기능을 사용하고, 어떤 데이터를 전달할지 지정하는 것입니다.

화면 구성

명령어 비트열이 화면 상단에서 강조되고, 아래쪽의 제어 신호들이 동시에 밝아져.

다음 세 항목을 순서대로 표시해.

`데이터 선택`

`연산 선택`

`결과 저장`

이후 세 항목이 하나의 `Instruction` 블록 아래로 정렬돼.

### 01:59–02:06 — 여러 제어를 하나의 명령어로

나레이션: 이제 우리는 여러 제어 신호를 각각 직접 설정하는 대신, 하나의 명령어로 회로의 동작을 지정할 수 있게 되었습니다.

화면 구성

영상 앞부분에서 보여줬던 수동 제어 패널이 화면 왼쪽에 다시 등장해.

개별적으로 존재했던 선택 항목들이 점점 흐려지고, 그 자리에 `00110110` 비트열 하나가 나타나.

기존 데이터 경로는 그대로 유지한 상태에서, 명령어와 해독 회로가 제어 신호들을 제공하는 구조를 완성해.

화면 중앙에는 다음 핵심 문장을 표시해.

`하나의 명령어 → 여러 제어 신호`

# ACT 5. 다음 명령어는 어디서 가져올까?

### 02:06–02:10 — 아직은 명령어 하나만 실행한다

나레이션: 하지만 아직 명령어는 하나씩 외부에서 제공해야 합니다.

### 02:10–02:17 — 여러 명령어를 미리 저장한다면?

나레이션: 그렇다면 여러 명령어를 미리 저장해 놓고, 컴퓨터가 다음에 실행할 명령어를 스스로 찾아오도록 만들 수는 없을까요?

화면 구성

기존 명령어 하나가 위쪽으로 이동하고, 그 아래에 여러 개의 명령어가 세로로 쌓여.

명령어가 여러 개 저장되어 있다면?

주소 0

00110110

주소 1

0000 0000

주소 2

0000 0000

뒤의 두 비트열은 아직 내용을 정하지 않은 자리 표시자다. 실제 명령어로 해석하거나 실행하는 장면은 이번 편에서 다루지 않는다.

각 명령어 왼쪽에 주소를 표시하고, 첫 번째 명령어를 가리키는 화살표가 나타나.

그다음 화살표가 두 번째 명령어를 가리키려는 순간 애니메이션을 멈춰.

핵심 연출: 지금까지 만든 명령어 해독 회로는 명령어 하나를 처리할 수 있지만, 여러 명령어 중 다음에 무엇을 가져올지는 아직 결정할 수 없다는 사실을 보여줘.

## Manim 구현 지침

이번 영상은 장면마다 새로운 회로를 만들기보다는 하나의 데이터 경로 객체를 유지한 채, 명령어와 제어 신호를 추가하는 방식이 효과적이야.

| 재사용 객체                     | 역할                             |
| -------------------------- | ------------------------------ |
| `RegisterBank`             | R0\~R3의 저장값, 읽기 주소와 쓰기 대상 표시   |
| `DataPath`                 | 두 입력 선택 경로, ALU, 결과 저장 경로      |
| `InstructionBits`          | 8비트 명령어의 네 필드 표시와 강조           |
| `InstructionDecoder`       | 필드의 의미를 제어 신호로 연결              |
| `ControlSignals`           | 입력 레지스터 선택, ALU 연산, 쓰기 주소 및 허용 |
| `InstructionMemoryPreview` | 다음 편을 예고하는 명령어 목록              |

특히 `InstructionBits`와 `DataPath`는 비트 필드 색상과 실제 제어선 색상을 일치시켜야 해.

예를 들어 `RS1=01` 필드를 파란색으로 강조했다면, 그 필드가 R1의 값을 선택하는 읽기 경로로 이어지는 애니메이션에서도 동일한 파란색을 유지해.

이렇게 하면 명령어 비트열이 추상적인 숫자 조합이 아니라 실제 회로의 어느 부분을 제어하는지 직관적으로 전달할 수 있어.

### 이번 편에서 가장 중요한 장면

00:58–01:35의 37초에 가장 많은 공을 들이는 것을 추천해.

앞부분에서 여러 선택 사항을 확인하고, 그 선택을 비트로 표현한 뒤, 하나의 명령어로 묶고, 다시 제어 신호로 분리하는 과정이 이번 영상의 핵심이야.

그리고 01:45–01:59에서는 회로의 물리적 연결이 바뀌지 않는다는 사실을 반드시 보여줘.

결국 이번 9편의 핵심은 다음 한 문장으로 정리할 수 있어.

“우리는 이미 계산하는 회로를 만들었다. 이제 그 회로가 무엇을 할지를 0과 1로 표현하고, 다시 제어 신호로 바꾸는 방법을 만든 것이다.”
