출력은 가로 1920×1080 / 세로 1080×1920, 60fps, 각각 10,500프레임. 기존 요청대로 내레이션 전체 자막을 포함하며, 음원 미제공으로 무음이다. 두 비율은 연산 로직을 공유하고 layouts.py에서 좌표·축 간격·자막 영역을 분리한다.

핵심 주장은 중첩된 상태에 연산과 간섭을 적용해 정답을 찾는 데 필요한 조회 횟수를 줄일 수 있다는 것이다. 이전 종료 질문·다음 편 예고·별도 엔드카드는 넣지 않는다.

수학: 그로버 예의 정답은 11. 초기 [0.5,0.5,0.5,0.5], 오라클 [0.5,0.5,0.5,-0.5], 평균 0.25, 확산 [0,0,0,1]. 진폭 막대와 P=|a|²를 별도 표시한다. 오라클 애니메이션은 마지막 진폭을 0.5 exp(iφ)로 회전시키며 실수부만 막대로 표시한다. 전체 상태는 정규화되고 확률은 각 25%를 유지한다. 평균 반사의 점 이동은 기하학적 작도이며 중간 계산 상태가 아님을 명시한다. 실제 상태는 연산 전후의 정규화된 값으로 갱신한다.

4개 후보의 순서·막대 위치를 13–16씬에서 유지한다. 12씬과 13씬 경계인 91초는 86–93초 문장 내부의 화면 변화이며 문장 자체나 자막 종료 시각을 바꾸지 않는다. 씬별 script.txt에는 해당 구간과 겹치는 원문 전체를 참고용으로 기재한다.

64개 후보는 실제 6회 반복, 성공 확률 약 99.66%를 사용한다. 4개 후보의 반복을 계속해 무조건 개선되는 것처럼 그리지 않는다. 판별 규칙을 오라클로 구현한다는 가정과 적절한 반복 횟수를 표시한다. 백만 개 예는 O(N) 대 O(√N)의 조회 규모 비교이며 실행시간·게이트 수와 구별한다.
