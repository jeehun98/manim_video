### SCENE 05 — 일반 컴퓨터는 특정 위치를 읽는다

00:26–00:31

> 일반적인 컴퓨터는 데이터를 확인할 때 특정 위치의 비트를 읽습니다.

화면 구성

앞서 등장한 비트 격자 위에 작은 파란색 조회 포인터가 나타난다.

\\[ \text{Query}(3)=1 \\]

애니메이션

1. 파란색 테두리가 세 번째 비트를 감싼다.

3. `Query(3) = 1`이라는 결과가 표시된다.
4. 조회 카운터가 `0 → 1`로 증가한다.

이후 포인터가 다른 비트로 이동하면서 조회 카운터가 증가하는 모습을 짧게 보여준다.

### SCENE 06 — 양자컴퓨터는 중첩된 위치에 조회할 수 있다

00:31–00:41

대응 나레이션

> 반면 양자컴퓨터는 여러 위치가 중첩된 상태에 조회 연산을 적용할 수 있습니다. 이러한 차이가 양자 알고리즘의 속도 향상을 가능하게 만드는 요소 중 하나입니다.

고전적 조회와 양자 오라클 조회의 비교

고전적

\\[ i\longrightarrow x_i \\]

양자

\\[ \sum_i\alpha_i|i\rangle|0\rangle \\]

\\[ \sum_i\alpha_i|i\rangle|x_i\rangle \\]

Manim 연출

- 입력 격자의 여러 칸이 동시에 보라색으로 강조된다.
- 각 칸에서 보라색 선이 오라클 상자로 연결된다.
- 상자에 `Uₓ`를 표시한다.
- 연산 후 각 위치에 대응하는 조회 결과가 얽힌 상태로 표현된다.

수학적 정확성

화면에 나타나는 여러 조회 결과가 개별적으로 읽을 수 있는 값처럼 표현되면 안 돼. 양자 오라클은 중첩 상태에 선형적으로 작용하며, 여러 \\(x_i\\)를 한 번에 독립적으로 측정할 수 있다는 뜻이 아니야.

따라서 마지막에는 중첩 상태를 하나의 수식으로 다시 합치는 연출을 사용한다.

### SCENE 10 — 같은 입력에서도 출력은 확률적이다

01:11–01:19 · 나레이션 71\~79초

대응 나레이션

> 양자컴퓨터는 확률적으로 작동하므로, 같은 입력에 대해서도 예를 출력할 확률이 존재합니다. 이 확률은 입력 데이터에 따라 달라집니다.

화면 구성

앞 장면의 양자 알고리즘을 유지한다.

오른쪽의 YES와 NO 상자가 확률 막대로 변환된다.

예시 입력 A에서는 다음과 같이 표시한다.

- YES: 70%
- NO: 30%

이후 입력 A에서 비트 한 개가 변경되면 출력 확률이 바뀌는 모습을 보여준다.

예시 입력 B:

- YES: 40%
- NO: 60%

입력에 따라 달라지는 출력 확률 — 개념 예시

입력 A입력 B

01011010

YES

70%

NO

30%

70%와 40%는 출력 확률의 개념을 보여주기 위한 예시값이며, 특정 양자 회로를 계산한 결과는 아니다.

Manim 구현

- `ValueTracker`를 사용해 YES 확률을 0.7에서 0.4로 변화.
- NO 확률은 항상 `1 - YES`로 계산.
- 입력의 변경 전후에 확률 막대가 함께 변화.
- 입력 비트가 변할 때만 확률이 변경되도록 동기화.

확률의 합은 언제나 100%여야 한다.

# 4. 영상의 핵심 수학적 표현

3편에서 중요한 것은 어려운 수식을 많이 보여주는 것이 아니라, 세 가지 관계를 서로 혼동하지 않도록 시각화하는 것이야.

| 개념       | 영상에서 사용할 표현              | 의미                |
| -------- | ------------------------ | ----------------- |
| 입력 데이터   | \\(x=(x_1,\ldots,x_n)\\) | 조회할 수 있는 비트들의 집합  |
| 양자 출력 확률 | \\(p(x)\\)               | YES가 나올 확률        |
| 고전적 근사   | \\(\widetilde p(x)\\)    | 일부 비트를 조회해 얻는 추정값 |

이 세 가지를 서로 다른 색상으로 고정하면, 시청자는 양자컴퓨터가 출력하는 것이 입력 데이터 자체가 아니라 입력에 따라 달라지는 확률이라는 사실을 이해하기 쉬워져.

특히 `p(x)`와 `p̃(x)`를 나란히 보여주는 장면을 많이 활용하되, 추측이 입증되기 전부터 예측값이 반드시 정확하게 일치한다고 보여주지 않는 것이 중요해.

## 6. 최종 구현 지침

# EP.03 — Manim 영상화 구현 지침

## 출력 설정

- 세로형 1080 × 1920, 9:16
- 60fps
- 전체 발화시간 155초
- 배경색 #0D1526
- 앞선 1\~2편과 동일한 색상 체계와 폰트 유지
- 나레이션에 없는 설명을 과도하게 추가하지 않음

## 타임라인

- 나레이션의 0\~155초를 기준으로 장면 구성
- 문장별 시간에 맞춰 애니메이션 시작과 종료 동기화
- 전체 장면을 하나의 영상으로 연결
- 쇼츠와 롱폼에서 동일한 애니메이션 재사용 가능하도록 제작

## 수학적 정확성

- 무작위 입력은 균등 무작위 비트열을 기본 모델로 사용
- 고전적 질의는 특정 입력 비트 하나의 값을 반환
- 양자 오라클은 중첩된 입력 위치에 선형적으로 작용
- 중첩된 조회 결과를 모두 개별적으로 읽어낼 수 있는 것처럼 표현하지 않음
- 양자 알고리즘의 YES 출력 확률을 p(x)로 표현
- 고전적 근사값은 p̃(x)로 구분
- 근사 예시의 확률은 설명용 값으로 명시
- 다항식 조회 횟수는 poly(T)로 표현
- 모든 입력에서의 정확한 재현과 대부분의 무작위 입력에 대한 근사를 구분
- 질의 복잡도와 전체 계산시간을 혼동하지 않음

## 시각화

- 복잡한 양자 회로보다 입력 데이터와 출력 확률의 관계를 우선
- BinaryGrid 컴포넌트로 비트 배열 구성
- QueryPointer로 선택된 입력 위치 강조
- ProbabilityBar로 양자 확률과 고전적 근사 비교
- ValueTracker로 확률과 오차 변화를 시각화
- 수식 변환에는 TransformMatchingTex 사용
- 텍스트보다 도형과 수치 변화 중심으로 연출
- 화면당 하나의 핵심 메시지 유지

## 최종 검증

- 모든 입력 예시에서 확률 합이 1인지 확인
- 근사 오차를 실제 표시된 수치와 일치시키기
- 무작위 입력 대부분이라는 조건을 오해 없이 표현
- poly(T)를 구체적인 증명되지 않은 상수 지수로 고정하지 않음
- 영상에서 등장하는 연구자 이름과 연도 검증
- 모든 수식이 모바일 세로 화면에서 읽히는지 확인
- 장면 경계에서 객체가 갑자기 사라지거나 중복되지 않도록 검사

## 7. 제작에서 가장 중요한 두 장면

이번 편은 특히 SCENE 08과 SCENE 12에 연출 역량을 집중하는 것을 추천해.

SCENE 08에서는 연구의 질문이 바뀌는 순간을 보여준다.

양자컴퓨터가 얼마나 빠른가? → 그 결과를 일반 컴퓨터도 예측할 수 있는가?

그리고 SCENE 12에서는 그 예측이 양자컴퓨터의 복잡한 내부 과정을 전부 재현한다는 뜻이 아니라, 우리가 필요로 하는 출력 확률만 근사하는 것이라는 차이를 전달해야 해.

이 두 장면이 명확해지면 4편에서 다룰 다항식과 입력 영향력의 개념도 자연스럽게 받아들일 수 있을 거야.

마지막으로 3편의 콘티에서는 실제 증명을 너무 일찍 보여주지 않는 편이 좋아. 3편은 무엇을 증명하려 했는지, 4편은 어떤 수학적 문제로 바꿨는지, 5편은 AI가 어떤 방법으로 해결했는지로 역할을 분리하면 시리즈 전체가 더 명확해져.
