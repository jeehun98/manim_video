# GPU 개론12 수정본 — 하나의 명령어를 여러 단계로 실행하려면?

사용자 확정34문장·161초. 음원 미제공.

0–6초
앞서 우리는 메모리에서 데이터를 가져오고, 계산한 결과를 다시 저장할 수 있는 프로세서를 만들었습니다.

6–9초
그렇다면 이 회로들은 어떤 순서로 동작해야 할까요?

9–14초
메모리 주소 100에 저장된 숫자 5를 첫 번째 레지스터로 가져온다고 생각해 보겠습니다.

14–17초
먼저 PC가 가리키는 위치에서 명령어를 가져옵니다.

17–24초
가져온 명령어를 해석하면, 메모리의 주소 100에서 값을 읽어 첫 번째 레지스터에 저장해야 한다는 사실을 알 수 있습니다.

24–27초
이제 데이터 메모리에 주소 100을 전달합니다.

27–31초
해당 위치의 값 5를 읽어 온 뒤, 첫 번째 레지스터에 기록하면 명령어 실행이 끝납니다.

31–37초
그런데 이 과정에서 모든 회로가 동시에 같은 일을 수행할 필요는 없습니다.

37–43초
명령어를 가져올 때는 명령어 메모리를 사용하고, 데이터를 읽을 때는 데이터 메모리를 사용합니다.

43–46초
마지막에는 레지스터에 새로운 값을 기록해야 합니다.

46–50초
그렇다면 이 과정들을 서로 다른 클럭에 나누어 수행하면 어떨까요?

50–53초
첫 번째 클럭에서는 명령어를 가져옵니다.

53–57초
다음 클럭에서는 명령어를 해석하고 필요한 주소를 결정합니다.

57–62초
그다음에는 메모리에서 값을 읽고, 마지막으로 레지스터에 결과를 기록합니다.

62–66초
하지만 이렇게 동작을 나누려면 새로운 정보가 필요합니다.

66–70초
프로세서는 지금 어느 과정을 실행하고 있는지 어떻게 알 수 있을까요?

70–74초
우리는 앞서 여러 비트의 값을 기억하는 레지스터를 만들었습니다.

74–77초
여기에 현재 실행 단계를 나타내는 값을 저장하면 어떨까요?

77–85초
예를 들어 00은 명령어 인출, 01은 주소 결정, 10은 데이터 읽기, 11은 결과 기록을 의미하도록 정하는 것입니다.

85–90초
이제 레지스터에 저장된 값만 확인해도 현재 어느 단계에 있는지 구분할 수 있습니다.

90–95초
그리고 이 값에 따라 필요한 제어 신호를 발생시키는 논리 회로를 추가합니다.

95–101초
상태가 00이면 명령어를 가져오도록 하고, 10이면 데이터 메모리를 읽도록 하는 것입니다.

101–105초
각 단계가 완료되면 다음 상태를 계산해 레지스터에 저장합니다.

105–114초
이처럼 현재 상태를 기억하고, 정해진 조건에 따라 다음 상태와 동작을 결정하는 구조를 유한 상태 기계, FSM이라고 합니다.

114–116초
그런데 한 가지가 더 필요합니다.

116–124초
명령어를 여러 클럭에 나누어 실행하더라도, 처음 가져온 명령어와 중간에 만들어진 값은 필요한 동안 유지되어야 합니다.

124–126초
이때도 앞서 만든 레지스터를 이용할 수 있습니다.

126–133초
가져온 명령어를 보관하는 레지스터와, 중간 결과를 보관하는 레지스터를 필요한 위치에 추가하는 것입니다.

133–138초
이제 각 회로는 정해진 순서에 따라 동작하고, 다음 단계에 필요한 정보도 유지할 수 있습니다.

138–143초
이처럼 하나의 명령어를 여러 클럭에 나누어 실행하도록 구성한 것을 다중 사이클 실행 구조라고 합니다.

143–147초
그런데 이 구조를 조금 다르게 활용할 수는 없을까요?

147–153초
첫 번째 명령어가 데이터 메모리를 사용하는 동안, 명령어를 가져오는 회로는 사용되지 않을 수도 있습니다.

153–157초
그렇다면 그 시간에 다음 명령어를 미리 가져올 수는 없을까요?

157–161초
다음에는 서로 다른 명령어의 실행 단계를 겹치는 구조를 살펴보겠습니다.
