# 회로는 어떤 순서로 동작할까?

주장: 현재 구조에 LOAD 실행 목표를 제시한다.

확정 구간: 0–14초 (14초).

0–6초: 앞서 우리는 메모리에서 데이터를 가져오고, 계산한 결과를 다시 저장할 수 있는 프로세서를 만들었습니다.
6–9초: 그렇다면 이 회로들은 어떤 순서로 동작해야 할까요?
9–14초: 메모리 주소 100에 저장된 숫자 5를 첫 번째 레지스터로 가져온다고 생각해 보겠습니다.

화면: scene_engine.py의 question에서 구현. 짙은 남색 배경, 기존 데이터 경로 파랑, 추가 저장회로 초록, 메모리 보라, 제어 주황. 기능이 필요한 시점에만 새 회로를 공개한다. FSM은 상태값·활성 장치·결과를 함께 보여준다. PC 주소와 실행 상태 번호를 구분한다. 하단 단일 자막 전용 영역. 9:16/16:9 각각 배치한다. 제어 비활성은 전원 차단을 뜻하지 않는다. 네 상태는 교육용 LOAD 예시이며 모든 명령·프로세서의 보편 구조가 아니다. 메모리 응답이 해당 읽기 단계 내 준비된 예시를 가정한다. 본편은 지연이 아니라 실행 순서에 집중한다. 원문·발화시간을 변경하거나 추가 엔드카드를 넣지 않는다.
