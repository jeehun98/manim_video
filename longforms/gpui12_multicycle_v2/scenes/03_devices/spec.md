# 단계마다 사용하는 장치가 다르다

주장: 인출·주소·읽기·기록에서 활성 경로를 구분한다.

확정 구간: 31–46초 (15초).

31–37초: 그런데 이 과정에서 모든 회로가 동시에 같은 일을 수행할 필요는 없습니다.
37–43초: 명령어를 가져올 때는 명령어 메모리를 사용하고, 데이터를 읽을 때는 데이터 메모리를 사용합니다.
43–46초: 마지막에는 레지스터에 새로운 값을 기록해야 합니다.

화면: scene_engine.py의 devices에서 구현. 짙은 남색 배경, 기존 데이터 경로 파랑, 추가 저장회로 초록, 메모리 보라, 제어 주황. 기능이 필요한 시점에만 새 회로를 공개한다. FSM은 상태값·활성 장치·결과를 함께 보여준다. PC 주소와 실행 상태 번호를 구분한다. 하단 단일 자막 전용 영역. 9:16/16:9 각각 배치한다. 제어 비활성은 전원 차단을 뜻하지 않는다. 네 상태는 교육용 LOAD 예시이며 모든 명령·프로세서의 보편 구조가 아니다. 메모리 응답이 해당 읽기 단계 내 준비된 예시를 가정한다. 본편은 지연이 아니라 실행 순서에 집중한다. 원문·발화시간을 변경하거나 추가 엔드카드를 넣지 않는다.
