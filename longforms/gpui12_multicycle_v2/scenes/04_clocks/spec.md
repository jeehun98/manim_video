# 서로 다른 클럭에 나누면?

주장: 기능적 네 동작을 교육용 네 클럭에 배치한다.

확정 구간: 46–62초 (16초).

46–50초: 그렇다면 이 과정들을 서로 다른 클럭에 나누어 수행하면 어떨까요?
50–53초: 첫 번째 클럭에서는 명령어를 가져옵니다.
53–57초: 다음 클럭에서는 명령어를 해석하고 필요한 주소를 결정합니다.
57–62초: 그다음에는 메모리에서 값을 읽고, 마지막으로 레지스터에 결과를 기록합니다.

화면: scene_engine.py의 clocks에서 구현. 짙은 남색 배경, 기존 데이터 경로 파랑, 추가 저장회로 초록, 메모리 보라, 제어 주황. 기능이 필요한 시점에만 새 회로를 공개한다. FSM은 상태값·활성 장치·결과를 함께 보여준다. PC 주소와 실행 상태 번호를 구분한다. 하단 단일 자막 전용 영역. 9:16/16:9 각각 배치한다. 제어 비활성은 전원 차단을 뜻하지 않는다. 네 상태는 교육용 LOAD 예시이며 모든 명령·프로세서의 보편 구조가 아니다. 메모리 응답이 해당 읽기 단계 내 준비된 예시를 가정한다. 본편은 지연이 아니라 실행 순서에 집중한다. 원문·발화시간을 변경하거나 추가 엔드카드를 넣지 않는다.
