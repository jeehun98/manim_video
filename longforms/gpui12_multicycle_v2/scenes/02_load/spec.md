# 하나의 LOAD를 따라가 본다

주장: PC=0에서 명령을 가져오고 주소100의5를R1에 기록한다.

확정 구간: 14–31초 (17초).

14–17초: 먼저 PC가 가리키는 위치에서 명령어를 가져옵니다.
17–24초: 가져온 명령어를 해석하면, 메모리의 주소 100에서 값을 읽어 첫 번째 레지스터에 저장해야 한다는 사실을 알 수 있습니다.
24–27초: 이제 데이터 메모리에 주소 100을 전달합니다.
27–31초: 해당 위치의 값 5를 읽어 온 뒤, 첫 번째 레지스터에 기록하면 명령어 실행이 끝납니다.

화면: scene_engine.py의 load에서 구현. 짙은 남색 배경, 기존 데이터 경로 파랑, 추가 저장회로 초록, 메모리 보라, 제어 주황. 기능이 필요한 시점에만 새 회로를 공개한다. FSM은 상태값·활성 장치·결과를 함께 보여준다. PC 주소와 실행 상태 번호를 구분한다. 하단 단일 자막 전용 영역. 9:16/16:9 각각 배치한다. 제어 비활성은 전원 차단을 뜻하지 않는다. 네 상태는 교육용 LOAD 예시이며 모든 명령·프로세서의 보편 구조가 아니다. 메모리 응답이 해당 읽기 단계 내 준비된 예시를 가정한다. 본편은 지연이 아니라 실행 순서에 집중한다. 원문·발화시간을 변경하거나 추가 엔드카드를 넣지 않는다.
