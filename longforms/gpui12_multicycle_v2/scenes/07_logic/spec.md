# 저장된 상태를 동작으로 바꾼다

주장: 상태출력→제어논리→장치,다음상태→클럭에지→상태저장의 피드백을 구성한다.

확정 구간: 90–105초 (15초).

90–95초: 그리고 이 값에 따라 필요한 제어 신호를 발생시키는 논리 회로를 추가합니다.
95–101초: 상태가 00이면 명령어를 가져오도록 하고, 10이면 데이터 메모리를 읽도록 하는 것입니다.
101–105초: 각 단계가 완료되면 다음 상태를 계산해 레지스터에 저장합니다.

화면: scene_engine.py의 logic에서 구현. 짙은 남색 배경, 기존 데이터 경로 파랑, 추가 저장회로 초록, 메모리 보라, 제어 주황. 기능이 필요한 시점에만 새 회로를 공개한다. FSM은 상태값·활성 장치·결과를 함께 보여준다. PC 주소와 실행 상태 번호를 구분한다. 하단 단일 자막 전용 영역. 9:16/16:9 각각 배치한다. 제어 비활성은 전원 차단을 뜻하지 않는다. 네 상태는 교육용 LOAD 예시이며 모든 명령·프로세서의 보편 구조가 아니다. 메모리 응답이 해당 읽기 단계 내 준비된 예시를 가정한다. 본편은 지연이 아니라 실행 순서에 집중한다. 원문·발화시간을 변경하거나 추가 엔드카드를 넣지 않는다.
