# GPU 개론 12 — 영상화 콘티 재구성

주제: 하나의 명령어를 여러 단계로 실행하려면 어떤 회로가 필요할까?

이번에는 시간과 초 단위 구분을 완전히 제외하고, 수정한 나레이션을 기준으로 화면에 무엇을 보여주고, 어떤 회로를 추가하고, 어떤 동작을 시연할지에 집중해서 구성할게.

핵심적인 변경은 기존 영상의 `Pending`, `Ready`, `RegWrite` 중심 연출을 버리는 거야.

대신 하나의 명령어를 실행하면서 필요한 회로가 차례대로 활성화되고, 그 순서를 기억하기 위한 저장 회로가 추가되는 과정을 보여주는 거지.

## 영상의 중심이 되는 구조

영상 전체에서 다음 명령어 하나만 사용해.

`LOAD R1, [100]`

초기 상태는 다음과 같이 고정해.

- 명령어 메모리: 주소 0에 `LOAD R1, [100]`
- 데이터 메모리: 주소 100에 숫자 `5`
- 레지스터 파일: `R1 = 0`
- PC: `0`
- 목표: `R1 = 5`

이번 편에서 새롭게 추가할 것은 ALU나 메모리가 아니야.

명령어를 기억하는 레지스터, 중간값을 보관하는 레지스터, 현재 실행 단계를 저장하는 레지스터와 제어 논리야.

# SCENE 1. 기존 프로세서에서 하나의 명령어를 실행한다

목적: 11편의 회로가 실제로 어떤 순서로 동작하는지 시각적으로 분해한다.

### 화면 구성

영상 시작에서는 11편의 최종 회로도를 재사용해.

화면 중앙의 전체 프로세서는 다음 영역으로 나뉘어 있어.

### 애니메이션

처음에는 전체 회로를 보여주고, 화면 상단에 `LOAD R1, [100]`을 표시해.

이후 모든 배선을 회색으로 낮추고 다음 동작만 하나씩 강조해.

동작 A — 명령어 가져오기

PC의 값 0이 명령어 메모리로 전달돼. 명령어 메모리에서 `LOAD R1, [100]`이 출력돼.

동작 B — 주소 결정

해독 회로가 명령어를 해석해 읽을 주소 100과 목적지 R1을 결정해.

동작 C — 데이터 읽기

데이터 메모리의 주소 100이 선택되고 숫자 5가 출력돼.

동작 D — 결과 기록

메모리에서 읽은 5가 Writeback MUX를 지나 레지스터 R1에 저장돼.

### 화면의 결론

네 동작을 모두 보여준 후 각각의 활성화 장면을 네 개의 작은 그림으로 압축해.

`명령어 인출 → 주소 결정 → 데이터 읽기 → 결과 기록`

중요: 이 장면에서는 실제 프로세서가 반드시 네 클럭을 사용한다고 설명하지 않아. 하나의 명령어를 구성하는 작업을 기능적으로 나누어 보여주는 것이 목적이야.

# SCENE 2. 네 동작을 서로 다른 클럭에 배치해 본다

목적: 하나의 명령어를 여러 클럭에 걸쳐 처리하도록 설계를 변경한다.

### 화면 구성

중앙에는 앞서 구분한 네 단계가 가로로 배치돼.

하단에는 하나의 클럭 파형을 배치해.

단계 1

명령어 인출

단계 2

주소 결정

단계 3

데이터 읽기

단계 4

결과 기록

설명용 클럭 배치. 각 단계의 완료와 상태 갱신을 경계에서 구분한다.

### 애니메이션

기존 네 단계 위에 클럭의 순서를 연결해.

- 첫 번째 단계에서 명령어 인출
- 두 번째 단계에서 주소 결정
- 세 번째 단계에서 데이터 읽기
- 네 번째 단계에서 결과 기록

화면에 다음 문구를 짧게 표시해.

`하나의 명령어, 여러 단계`

이때 각 단계가 끝났을 때 어떤 결과가 남는지를 보여줘.

명령어 인출 후에는 명령어가 남아 있어야 하고, 주소 결정 후에는 주소 100이 남아 있어야 하고, 메모리 읽기 후에는 데이터 5가 남아 있어야 해.

여기서는 아직 그 정보를 어떻게 저장할지 보여주지 않아.

다음 장면에서 필요한 저장 회로를 추가하기 위한 준비야.

# SCENE 3. 단계 사이에서 정보가 사라지지 않도록 한다

목적: 기존 플립플롭과 레지스터를 재사용해 중간 정보를 보관하는 구조를 추가한다.

### 장면 A — 가져온 명령어를 보관한다

처음에는 아래 두 블록만 확대해.

`Instruction Memory → Decoder`

명령어 메모리에서 `LOAD R1, [100]`이 출력돼.

그런데 다음 단계로 이동할 때에도 같은 명령어를 사용해야 해.

따라서 두 블록 사이에 레지스터 하나를 추가해.

새로운 레지스터가 클럭 에지에서 명령어를 받아 저장해.

그다음 명령어 메모리의 출력이 바뀌더라도 저장된 명령어는 유지돼.

이 동작을 먼저 보여준 뒤 Instruction Register라는 명칭을 붙여.

### 장면 B — 계산한 주소를 보관한다

이제 ALU의 출력에도 같은 원리를 적용해.

예를 들어 ALU가 어떤 명령어의 유효 주소 104를 계산한 경우, 이 값을 다음 메모리 접근 단계에서도 사용해야 해.

ALU의 출력선 사이에 작은 레지스터가 추가돼.

`ALU → 주소 저장 레지스터 → Data Memory`

ALU의 입력을 변경해도 주소 저장 레지스터에는 104가 유지돼.

이때는 별도 주소 계산 예시를 크게 전개하지 않아. 주소값 104를 저장하는 동작만 보여줘.

### 장면 C — 메모리에서 읽은 데이터도 보관한다

이번에는 데이터 메모리 출력에 숫자 5가 나타나.

다음 단계에서 레지스터 파일에 기록할 때까지 필요하다면 이 값도 저장해야 해.

`Data Memory → 데이터 보관 레지스터 → Writeback MUX`

마지막에는 세 가지 레지스터가 화면에 남아.

- 명령어 저장: `LOAD R1, [100]`
- 주소 저장: `100`
- 읽은 데이터 저장: `5`

각 저장 회로가 모두 초록색으로 표현되고, 기존에 배운 레지스터의 재사용임을 보여줘.

이 장면에서 주의할 점: 모든 레지스터가 반드시 모든 프로세서에 똑같이 필요하다는 식으로 표현하지 않아야 해. 이번 영상은 단계별로 실행하는 교육용 데이터 경로를 구성하는 과정이야.

# SCENE 4. 저장된 정보만으로는 실행 순서가 결정되지 않는다

목적: 실행 단계 자체를 기억하는 회로의 필요성을 제시한다.

### 화면 구성

프로세서 전체 회로도로 돌아와.

이제 앞서 추가한 명령어 레지스터와 중간값 저장 레지스터도 존재해.

그런데 모든 회로가 회색으로 비활성화된 상태야.

화면 중앙에 작은 질문을 표시해.

`다음에 어떤 동작을 해야 할까?`

### 애니메이션

화면 왼쪽에 네 가지 제어 신호를 배치해.

`명령어 저장`

`주소 선택`

`메모리 읽기`

`레지스터 기록`

각 신호를 차례대로 활성화해 보고, 활성화되는 회로가 바뀌는 모습을 보여줘.

한 번에 모든 신호를 활성화하면 안 되는 이유도 짧게 시각화해.

예를 들어 아직 읽은 데이터가 준비되지 않았는데 레지스터 쓰기 신호를 활성화하는 모습을 잘못된 순서의 예시로 보여줘.

R1의 값이 갱신되기 전에 경고 표시가 나타나고 동작을 중단해.

여기서는 실제 하드웨어가 반드시 잘못된 값을 저장한다고 단정하지 말고, 유효한 데이터가 준비되기 전에 기록을 허용해서는 안 된다는 설계 조건을 보여주면 돼.

### 해결 방향

기존 네 단계에 각각 번호를 부여해.

`00 → 01 → 10 → 11`

이 값이 현재 단계가 무엇인지 나타내도록 정의해.

아직 FSM이라는 이름은 등장시키지 않아.

# SCENE 5. 현재 단계도 레지스터에 저장한다

목적: 실행 순서를 관리하기 위해 상태 저장 레지스터를 추가한다.

### 화면 구성

기존 프로세서 왼쪽에 아주 작은 2비트 레지스터를 추가해.

그 안에는 현재 단계가 저장돼.

처음에는 `00`이야.

이 레지스터를 화면 중앙으로 확대해.

현재 단계에 부여한 값

| 저장값 | 수행할 동작 |
| --- | ------ |
| 00  | 명령어 인출 |
| 01  | 주소 결정  |
| 10  | 메모리 읽기 |
| 11  | 결과 기록  |

### 애니메이션

처음에는 00이 저장돼 있어.

클럭 에지에서 01, 10, 11로 차례대로 변경되는 모습을 보여줘.

중요한 것은 상태값만 바뀌는 것에서 끝나지 않는다는 점이야.

각 상태에 따라 기존 프로세서에서 활성화되는 장치도 달라져야 해.

- 00: 명령어 메모리와 명령어 저장 회로 강조
- 01: 주소 선택 경로 강조
- 10: 데이터 메모리 읽기 강조
- 11: 레지스터 기록 경로 강조

상태값이 11에서 다음 명령어의 00으로 바뀌면 프로그램 카운터가 가리키는 다음 명령어를 처리하도록 해.

이때 상태값은 명령어 주소가 아니라 실행 단계 번호라는 점이 시각적으로 분명해야 해.

# SCENE 6. 저장된 상태를 제어 신호로 변환한다

목적: 레지스터와 논리 회로를 조합해 제어기를 구성한다.

이번 편에서 가장 중요한 시각적 장면이야.

지금까지는 레지스터에 현재 상태만 저장했어.

하지만 레지스터의 값 자체가 메모리를 읽거나 레지스터에 데이터를 기록하는 것은 아니지.

상태값을 해석해 실제 제어 신호를 만들어야 해.

### 화면 구성

화면 가운데에 `State Register`를 배치해.

그 오른쪽에 빈 논리 회로 블록을 추가해.

상태 레지스터의 2비트 출력이 논리 회로로 연결돼.

### 애니메이션

처음에 상태 레지스터에는 `00`이 저장돼.

이 값이 제어 논리로 들어가면 명령어 저장 신호가 활성화돼.

상태가 `10`으로 변경되면 메모리 읽기 신호가 활성화돼.

상태가 `11`로 변경되면 레지스터 쓰기 신호가 활성화돼.

화면 하단에 한 문장만 표시해.

`현재 상태 → 필요한 동작 선택`

이제 제어 논리에서 다시 상태 레지스터의 입력으로 돌아가는 연결을 추가해.

이 경로에서는 다음 상태값이 계산돼.

`현재 상태 → 다음 상태 계산 → 레지스터 저장`

클럭 에지에서 상태 레지스터가 새로운 값으로 갱신돼.

이렇게 하면 기존 6편에서 설명했던 피드백과 7편의 클럭, 8편의 레지스터가 다시 연결되는 셈이야.

### 명칭 등장

레지스터와 제어 논리를 하나의 테두리로 묶어.

그다음 명칭을 보여줘.

Finite State Machine (FSM)

유한한 개수의 상태와 상태 전이 규칙으로 동작하는 제어 구조라는 짧은 설명을 화면에 남겨.

이름은 회로의 동작을 모두 보여준 뒤에 등장시켜.

# SCENE 7. 이제 명령어 하나를 여러 클럭에 나누어 실행한다

목적: 완성된 회로를 이용해 하나의 LOAD 명령어를 처음부터 끝까지 시연한다.

여기서는 더 이상 새 회로를 추가하지 않아.

앞에서 완성한 하드웨어가 실제로 동작하는 모습을 보여주는 장면이야.

### 화면 구성

상단에 현재 명령어를 표시해.

`LOAD R1, [100]`

중앙에 프로세서 구조를 유지해.

하단에는 `State Register`의 값과 현재 동작을 표시해.

### 실행 애니메이션

첫 번째 상태 — 00

명령어를 가져와 명령어 레지스터에 저장해.

두 번째 상태 — 01

명령어를 해석해 데이터 메모리의 주소 100을 선택해.

세 번째 상태 — 10

메모리 주소 100의 데이터 5를 읽어 임시 레지스터에 저장해.

네 번째 상태 — 11

읽은 값 5를 레지스터 R1에 기록해.

R1이 `0 → 5`로 변경되면 현재 명령어가 완료돼.

완료 직후에는 PC가 가리키는 다음 명령어를 처리하기 위한 초기 상태로 돌아가.

### 이 장면에서 반드시 보여줄 것

화면에는 다음 세 정보가 동시에 나타나야 해.

현재 상태 / 활성화되는 장치 / 저장된 결과

반대로 이전 영상에서 사용했던 `Ready=0`, `RegWrite=0`, `Pending` 같은 신호는 표시하지 않아도 돼.

제어 신호 자체보다 그 신호 때문에 실제로 어떤 장치가 동작하는지가 중요하기 때문이야.

### 최종 명칭

화면 전체 회로를 감싸는 외곽선이 등장해.

Multi-cycle Processor

아래에는 짧게 다음 문구를 표시해.

`하나의 명령어를 여러 클럭에 나누어 실행`

# SCENE 8. 아직 사용하지 않는 회로가 있다

목적: 13편 파이프라인 구조로 연결할 새로운 질문을 제시한다.

### 화면 구성

완성된 다중 사이클 프로세서를 그대로 유지해.

현재는 LOAD 명령어가 데이터 메모리를 읽는 단계야.

메모리 영역은 활성화되어 있고, 명령어 메모리 영역은 회색으로 표시돼.

화면에서는 두 영역을 동시에 확대해.

### 애니메이션

데이터 메모리에서는 다음 동작을 수행하고 있어.

`Memory[100] → 5`

그런데 명령어 인출 회로는 현재 명령어를 가져오는 데 사용되지 않고 있어.

그 옆에 두 번째 명령어가 나타나.

`ADD R3, R2, R4`

다음 명령어를 인출하는 경로에 파란색 신호가 흐르려다가 멈춰.

화면 중앙에 질문을 표시해.

`다른 명령어를 미리 가져오면?`

이후 화면이 넓어지면서 여러 명령어가 서로 다른 단계에 배치될 수 있는 공간이 나타나.

`명령어 A → 데이터 읽기`

`명령어 B → 명령어 인출`

하지만 아직 실제로 동시에 실행되지는 않아.

두 명령어의 색상만 구분하고 화면을 종료해.

다음 영상에서는 이 두 명령어가 서로의 정보를 덮어쓰지 않으면서 동시에 진행될 수 있는 구조를 만들어야 해.

## 영상 제작을 위한 핵심 구조 변화

| 장면 | 기존 회로에서 달라지는 요소    | 시청자가 이해할 내용           |
| -- | ------------------ | --------------------- |
| 1  | 변화 없음              | 하나의 명령어에는 여러 동작이 존재한다 |
| 2  | 동작을 클럭별로 분할        | 실행을 여러 단계로 나눌 수 있다    |
| 3  | 명령어·중간값 저장 레지스터 추가 | 다음 단계까지 정보를 유지한다      |
| 4  | 동작 순서 문제 제시        | 저장만으로는 순서가 정해지지 않는다   |
| 5  | 상태 레지스터 추가         | 현재 실행 단계를 기억한다        |
| 6  | 제어 논리와 상태 전이 경로 추가 | 상태에 따라 장치를 제어한다       |
| 7  | 완성된 회로 동작 시연       | 다중 사이클 실행 구조          |
| 8  | 사용하지 않는 회로 강조      | 서로 다른 명령어를 겹칠 가능성     |

## 기존 영상과 비교했을 때 반드시 제거해야 하는 연출

메모리 결과를 기다리는 화면을 길게 유지하는 것. 이번 편은 메모리 지연이 아니라 실행 순서를 결정하는 구조에 관한 영상이야.

처음부터 모든 레지스터와 제어 신호를 화면에 표시하는 것. 새롭게 필요한 순간에만 회로를 추가하고 명칭을 공개해.

회로의 상태를 설명하는 추상적인 텍스트를 계속 나열하는 것. 상태값에 따라 실제로 어떤 회로가 활성화되는지 보여주는 것으로 설명을 대체해.

### 영상화에서 가장 중요한 연출

이번 영상은 SCENE 5와 SCENE 6이 중심이 되어야 해.

앞에서 만든 레지스터는 숫자나 명령어를 저장했어.

그런데 이제 같은 저장 회로에 `00`, `01`, `10`, `11`이라는 값을 보관하고, 그 값으로 프로세서가 현재 어떤 동작을 해야 하는지 결정할 수 있게 된 거야.

여기에 논리 회로를 추가하면 현재 상태에 따라 필요한 제어 신호가 만들어지고, 다음 상태가 계산돼.

이것이 12편에서 반드시 전달해야 하는 새로운 구조적 개념이야.

기존에는 회로에 무엇을 계산할지 알려주는 명령어를 만들었다면, 이번에는 그 명령어를 실행하기 위해 회로들이 어떤 순서로 동작해야 하는지 결정하는 구조를 만드는 것.

이 차이가 시각적으로 명확해지면, 이전처럼 복잡한 블록도 안에서 값이 바뀌는 장면만 반복하지 않아도 영상의 흐름을 이해할 수 있을 거야.
