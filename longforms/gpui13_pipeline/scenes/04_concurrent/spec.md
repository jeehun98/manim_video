# 같은 시간, 서로 다른 명령어

주장: A는Memory100읽기,B는명령어인출을동시에진행한다.

확정시간39–51초(12초).

39–46: 첫 번째 명령어가 메모리에서 데이터를 읽고, 같은 시간에 두 번째 명령어는 명령어 메모리에서 가져오는 것입니다.
46–51: 이처럼 서로 다른 회로가 서로 다른 명령어를 동시에 처리할 수 있습니다.

화면: ../../storyboard_reference.md 해당부분, ../../scene_engine.py의 concurrent를따른다. 배경남색,A파랑,B보라,추가저장초록,주소/제어주황. 단계별동작→정보충돌→레지스터추가→동시진행 순서. A색은항상파랑,B색은항상보라로유지한다(첨부개별장면의반대색지시보다공통규칙우선). 메모리는독립접근자원,단계별하드웨어충돌없음,각단계1주기완료의교육용4단계예시. F주소는명령메모리0/1,D주소는데이터100/101로구분한다. 실제CPU모든단계구분을단정하지않는다. 빈파이프라인슬롯은무효이며쓰지않는다. 데이터와목적지/제어정보가함께전달된다. 에지이전A정보를사용한후에만같은경계레지스터를B정보로갱신한다. 주소/목적지정보는단일배선에서섞이는표현을쓰지않는다. 잘못된공유설계예시만경고,실제오류값을레지스터파일에확정하지않는다. 104ALU기능예시는LOAD100과별개임을명시한다. 성능비교는동일주기·충돌없음가정이며실제클럭단축이나항상성능향상단정없음. 마지막의존성은별도LOAD→ADD예시이며원문외예고/엔드카드없음. 하단단일자막과도식영역분리,두화면비별도배치.
