# 단계 사이에 저장 회로를 추가한다

주장: F/D에는명령어,D/M에는주소·목적지·읽기제어,M/W에는데이터·목적지·쓰기제어를보관한다.

확정시간75–87초(12초).

75–79: 그렇다면 각 명령어에 필요한 정보를 단계별로 따로 보관하면 어떨까요?
79–83: 우리는 앞서 여러 비트의 값을 저장하는 레지스터를 만들었습니다.
83–87: 이 저장 회로를 각 실행 단계 사이에 배치하는 것입니다.

화면: ../../storyboard_reference.md 해당부분, ../../scene_engine.py의 insert를따른다. 배경남색,A파랑,B보라,추가저장초록,주소/제어주황. 단계별동작→정보충돌→레지스터추가→동시진행 순서. A색은항상파랑,B색은항상보라로유지한다(첨부개별장면의반대색지시보다공통규칙우선). 메모리는독립접근자원,단계별하드웨어충돌없음,각단계1주기완료의교육용4단계예시. F주소는명령메모리0/1,D주소는데이터100/101로구분한다. 실제CPU모든단계구분을단정하지않는다. 빈파이프라인슬롯은무효이며쓰지않는다. 데이터와목적지/제어정보가함께전달된다. 에지이전A정보를사용한후에만같은경계레지스터를B정보로갱신한다. 주소/목적지정보는단일배선에서섞이는표현을쓰지않는다. 잘못된공유설계예시만경고,실제오류값을레지스터파일에확정하지않는다. 104ALU기능예시는LOAD100과별개임을명시한다. 성능비교는동일주기·충돌없음가정이며실제클럭단축이나항상성능향상단정없음. 마지막의존성은별도LOAD→ADD예시이며원문외예고/엔드카드없음. 하단단일자막과도식영역분리,두화면비별도배치.
