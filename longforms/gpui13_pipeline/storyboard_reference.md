GPU 개론 13 — 하나의 명령어가 끝나기 전에 다음 명령어를 실행할 수 있을까?
상세 영상화 콘티 · 9:16 세로 영상 · Manim 기반 모션그래픽 · 시간 및 초 단위 지정 제외

이번 영상은 하나의 프로세서 안에서 서로 다른 회로가 동시에 동작할 수 있다는 사실을 먼저 납득시키는 것이 가장 중요해.

기존에는 명령어 A가 끝나기 전에 명령어 B를 가져온다고 곧바로 설명했지만, 이번에는 그 이전 단계를 명확하게 보여주자.

하나의 프로세서 → 여러 물리적 회로 → 서로 다른 회로의 동시 동작 → 서로 다른 명령어의 동시 진행 → 정보 충돌 → 저장 회로 추가 → 파이프라인 완성

영상 전체에서 사용하는 명령어는 다음 두 개로 통일해.
LOAD R1, [100]
LOAD R2, [101]


데이터 메모리에는 Memory[100] = 5, Memory[101] = 3이 저장되어 있다고 가정해.

SCENE 1. 하나의 프로세서는 하나의 회로가 아니다
대응 나레이션
앞서 우리는 하나의 명령어를 여러 단계로 나누어 실행하는 프로세서 구조를 만들었습니다.

그런데 이 과정에서 각각의 회로가 언제 동작하는지 다시 살펴보겠습니다.

화면 연출
12편에서 완성했던 다중 사이클 프로세서 구조를 그대로 불러와.

처음에는 PC, 명령어 메모리, 명령어 레지스터, Decoder, ALU, 데이터 메모리, 레지스터 파일이 하나의 외곽선 안에 배치되어 있어.

영상 상단에는 하나의 프로세서라고 표시해.

이후 외곽선은 유지하면서 내부 장치들을 각각 별도 블록으로 시각적으로 분리해.
- 명령어를 가져오는 영역
- 명령어를 해석하고 주소를 결정하는 영역
- 데이터를 읽는 영역
- 결과를 기록하는 영역
이 장면에서 각 영역이 물리적으로 떨어져 나가는 애니메이션은 사용하지 않아. 실제 하드웨어의 연결을 끊는다는 뜻으로 보일 수 있기 때문이야.

대신 영역별 배경 강조와 얇은 구분선을 추가해.

이 장면의 목적: 프로세서라는 하나의 이름 아래 여러 장치가 존재하며, 각 장치의 역할이 다르다는 사실을 먼저 확인하는 것.

SCENE 2. 각 회로는 서로 다른 일을 한다
대응 나레이션
명령어를 가져올 때는 명령어 메모리를 사용합니다.

주소를 계산할 때는 ALU를 사용하고, 데이터를 읽을 때는 데이터 메모리를 사용합니다.

이들은 하나의 프로세서에 속하지만 서로 다른 회로입니다.

화면 연출

동작 B — ALU

기존에 사용하던 덧셈 예시를 간결하게 표시해.

SCENE 3. 서로 다른 회로는 동시에 동작할 수 있다
대응 나레이션
따라서 한 회로가 동작하고 있다고 해서 다른 모든 회로가 반드시 멈춰 있어야 하는 것은 아닙니다.

이제 같은 화면에서 두 장치가 동시에 동작하는 모습을 보여줘.

왼쪽 명령어 메모리에서는 파란색 신호가, 오른쪽 데이터 메모리에서는 보라색 신호가 흘러.

둘 중 하나가 끝나야 다른 하나가 시작된다는 식의 애니메이션을 사용하지 않아.
중요한 기술적 조건
두 회로가 같은 시간에 사용할 수 있으려면 명령어 인출과 데이터 읽기를 위한 메모리 접근 자원이 서로 충돌하지 않아야 해.

이번 교육용 구조에서는 명령어 메모리와 데이터 메모리에 독립적인 접근 경로가 있다고 가정해.

이 가정을 시각화하려면 두 메모리에 각각 별도의 주소 입력선을 그려 두면 충분해.

SCENE 4. 그렇다면 남는 회로로 다음 명령어를 가져오면?
대응 나레이션
예를 들어 첫 번째 명령어가 데이터 메모리에서 값을 읽는 동안, 명령어를 가져오는 회로는 사용되지 않을 수도 있습니다.

그렇다면 이 회로를 이용해 두 번째 명령어를 미리 가져오면 어떨까요?

첫 번째 명령어가 메모리에서 데이터를 읽고, 같은 시간에 두 번째 명령어는 명령어 메모리에서 가져오는 것입니다.

이처럼 서로 다른 회로가 서로 다른 명령어를 동시에 처리할 수 있습니다.

SCENE 5. 서로 다른 명령어의 정보가 함께 존재한다
대응 나레이션
하지만 여기서 새로운 문제가 생깁니다.

두 명령어가 동시에 진행된다면, 각각의 주소와 목적지 정보를 어떻게 구분해야 할까요?

첫째, 화면의 주인공은 프로세서 전체가 아니라 서로 독립적으로 동작하는 회로들이야. 기존 12편에서는 FSM의 상태 변화가 중심이었다면, 이번 13편에서는 같은 시간에 서로 다른 회로가 활성화되는 모습이 중심이 되어야 해.

둘째, 파이프라인 레지스터를 추가하는 장면은 반드시 앞선 충돌 예시와 직접 연결해야 해. 100이 101로 덮어써지는 문제를 보여준 바로 그 저장 위치를 구조적으로 분리해 해결해야 시청자가 필요성을 납득할 수 있어.

셋째, 파이프라인 레지스터를 추가하는 것만으로 동시 실행이 자동으로 완성되지는 않아. 여러 단계가 같은 시간에 서로 다른 명령어를 처리하도록 제어 구조도 바뀌어야 해. 다만 이번 영상에서 제어기의 모든 세부 구현을 설명할 필요는 없어. 각 단계가 자기 명령어에 해당하는 제어 정보를 함께 전달한다는 점까지 표현하면 충분해.

넷째, 기존 예시를 유지해야 해. LOAD R1, [100]과 LOAD R2, [101]은 화면 전체에서 A와 B로 고정하고, 마지막 데이터 의존성을 예고할 때만 LOAD → ADD를 새롭게 제시해.

이번 영상의 가장 중요한 장면은 SCENE 3과 SCENE 8이야.

SCENE 3에서 시청자는 하나의 프로세서 내부에서 서로 다른 회로가 동시에 동작할 수 있다는 사실을 이해하고, SCENE 8에서는 그 동작을 여러 명령어에 적용하려면 정보가 섞이지 않도록 저장 구조를 추가해야 한다는 사실을 이해하게 돼.

이 두 장면이 연결되면 파이프라인은 처음부터 외워야 할 새로운 용어가 아니라, 이미 만든 회로들의 동작을 확장하면서 자연스럽게 등장하는 구조가 될 거야.
