### SCENE 04 — 그로버보다 더 빠를 수 있을까?

00:26–00:37

대응 나레이션

> 그렇다면 이보다 더 빠른 양자 알고리즘을 만들 수도 있을까요? 흥미롭게도, 정답 여부만 확인할 수 있는 일반적인 검색 문제에서는 그로버 알고리즘보다 근본적으로 더 적은 조회 횟수로 해결할 수 없다는 사실이 증명되어 있습니다. 즉, 중첩과 간섭을 사용하더라도 이러한 검색에서는 제곱근 수준의 가속이 한계인 것입니다.

화면 구성

\\(\sqrt N\\)이 중앙에 등장하고, 그보다 작은 복잡도 후보를 나타내는 기호가 차례로 등장한다.

\\[ O(\sqrt N) \\]

\\[ O(\log N)\quad ? \\]

두 번째 수식 위에 작은 X를 표시한다.

이후 핵심 하한을 표시한다.

\\[ Q(N)=\Omega(\sqrt N) \\]

여기서 \\(Q(N)\\)은 일정한 성공 확률을 보장하는 데 필요한 양자 오라클 질의 횟수를 의미한다.

정확성 지침

이 결과는 정답 여부를 알려주는 블랙박스 오라클만 사용하는 비구조적 검색 모델에서 성립하는 하한이다. 모든 양자 계산 문제의 속도에 대한 하한처럼 표현하지 않는다.

장면 마지막에는 \\(\sqrt N\\)이 화면 좌측으로 이동하며 '쇼어 알고리즘'으로 전환한다.

주기도 직접 검증한다.

```
def multiplicative_order(a: int, N: int):    if __import__("math").gcd(a, N) != 1:        raise ValueError("a and N must be coprime")    value = 1    for r in range(1, N + 1):        value = (value * a) % N        if value == 1:            return r    raise RuntimeError("Order not found")assert multiplicative_order(2, 15) == 4
```

## B. 소인수 추출 검증

```
from math import gcdN = 15a = 2r = 4assert r % 2 == 0assert pow(a, r // 2, N) != N - 1p = gcd(pow(a, r // 2) - 1, N)q = gcd(pow(a, r // 2) + 1, N)assert (p, q) == (3, 5)
```

이번 2편에서 가장 중요한 장면은 SCENE 07\~11의 소인수분해 과정과 SCENE 13\~15의 양자 푸리에 변환 과정이야.

시청자가 영상을 보고 최소한 다음 두 가지는 이해할 수 있어야 해.

첫째, 주기를 알아내면 어떤 조건에서 소인수를 구할 수 있다는 것.

둘째, 양자컴퓨터는 그 주기를 찾는 과정에서 중첩과 간섭을 사용한다는 것.

이 두 연결이 명확해지면 마지막의 \*\*"문제의 수학적 구조가 양자 가속에 중요하다"\*\*라는 결론도 설득력을 얻어. 그리고 3편에서는 이 관점을 뒤집어, 특별한 구조가 없는 무작위 입력에 대한 양자컴퓨터의 계산 능력을 살펴보게 되는 거야.
