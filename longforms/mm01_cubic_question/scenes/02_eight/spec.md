# 씬 02 — 같은 출력을 만드는 8곱

## 목적과 주장·화면 구성

같은 출력을 만드는 여덟 번의 곱셈

주장: 고정된 2×2 행렬곱을 표준 방법으로 계산하면 곱셈 8번이 필요하다.

\\[ \begin{pmatrix}1&2\\\3&4\end{pmatrix} \begin{pmatrix}5&6\\\7&8\end{pmatrix} = \begin{pmatrix}19&22\\\43&50\end{pmatrix} \\]

| 첫째 칸 | \\(1(5)+2(7)=19\\) |
| ---- | ------------------ |
| 둘째 칸 | \\(1(6)+2(8)=22\\) |
| 셋째 칸 | \\(3(5)+4(7)=43\\) |
| 넷째 칸 | \\(3(6)+4(8)=50\\) |

화면 연출

두 입력 행렬의 숫자는 화면 상단에 고정한다. 선택된 행과 열에서 각각 두 개의 곱셈 노드가 생성된다. 합산 결과가 출력 칸으로 이동한다.

완성되면 계산 그래프를 아래로 펼쳐 여덟 개의 곱셈 노드를 동시에 보여준다.

장면 끝: 여덟 개의 곱셈 노드가 남은 상태에서 질문한다.

> 이 여덟 개를 반드시 따로 계산해야 할까요?



## TTS

조금 더 작은 2×2 행렬을 보겠습니다.

왼쪽에는 일, 이, 삼, 사. 오른쪽에는 오, 육, 칠, 팔을 놓겠습니다.

첫 번째 출력은 일 곱하기 오에 이 곱하기 칠을 더한 십구입니다.

같은 방법으로 나머지 세 칸을 계산하면 이십이, 사십삼, 오십이 나옵니다.

각 출력에 곱셈이 두 번씩 필요하므로, 모두 여덟 번입니다.

그런데 이 여덟 개의 곱을 꼭 따로 계산해야 할까요?

- 확정 길이: 미정. duration_seconds: null.
- 무음 콘티 임시 길이: 37초. 음성 실측 후 재동기화.

## 연결과 상태

앞 씬: 표준 방법의 27곱. 다음 씬: 입력을 재조합한 7개의 곱.
시작: 이 씬의 계산 대상 표시. 종료: 주장에 해당하는 계산 결과와 다음 질문 유지.

## 정확성

M₁=65. 스칼라 곱셈 수와 전체 연산량을 구분한다. 항의 순서를 바꾸지 않는다. 씬 4는 숫자 검산, 씬 5는 항등식 검증이다. 블록 재귀는 우선 n=2^k이며 다른 크기는 패딩으로 확장한다. 그래프는 실행시간이 아니다.

## 사용자 음성 시각 적용

전체 19–41초. 길이 22초. timing.json 참조. 기존 임시 길이를 대체한다.
