# GPU 개론 06 — 논리 게이트는 어떻게 값을 기억할까?

확정 원문29문장·종료 시각140초. 음원 미제공.

## 0–11초 · 여러 단계의 계산을 하려면?

0–6초: 앞서 우리는 여러 연산 기능을 하나의 ALU에 통합하고, 필요한 연산을 선택하는 방법을 살펴봤습니다.

6–11초: 그렇다면 이 장치로 여러 단계의 계산을 수행하려면 어떻게 해야 할까요?

## 11–31초 · 중간 결과는 다음 계산의 입력

11–16초: 예를 들어 5와 3을 더하고, 그 결과에 다시 2를 더한다고 생각해 보겠습니다.

16–20초: 가장 간단한 방법은 두 개의 덧셈 회로를 연속으로 연결하는 것입니다.

20–26초: 첫 번째 회로에서 나온 8이 두 번째 회로로 전달되면 최종 결과인 10을 얻을 수 있습니다.

26–31초: 하지만 계산 단계마다 새로운 회로를 추가해야 한다면, 회로의 규모도 계속 커지게 됩니다.

## 31–42초 · 하나의 ALU를 반복해서 쓰려면

31–36초: 그렇다면 이미 만들어 놓은 하나의 ALU를 반복해서 사용할 수는 없을까요?

36–42초: 이를 위해서는 첫 번째 계산의 결과인 8을 다음 계산에 사용할 때까지 보관해야 합니다.

## 42–56초 · 입력이 바뀌면 이전 결과는?

42–46초: 그런데 지금까지 살펴본 논리 회로에는 이러한 기능이 없습니다.

46–52초: 논리 게이트의 출력은 현재 입력에 따라 결정되기 때문에, 입력이 바뀌면 이전 결과도 달라집니다.

52–56초: 그렇다면 기존의 논리 게이트만으로 값을 기억하는 회로를 만들 수 있을까요?

## 56–71초 · 출력이 다시 입력으로 돌아간다면

56–59초: 여기서 회로의 연결 방식을 조금 바꿔보겠습니다.

59–63초: 지금까지는 입력에서 출력으로 신호가 전달되도록 회로를 구성했습니다.

63–68초: 하지만 출력된 신호를 다시 다른 게이트의 입력으로 연결하면 어떨까요?

68–71초: 이러한 구조를 되먹임, 즉 Feedback이라고 합니다.

## 71–79초 · 두 NOR 게이트를 교차 연결

71–75초: 대표적인 예로 두 개의 NOR 게이트를 생각해 보겠습니다.

75–79초: 각 게이트의 출력이 상대방 게이트의 입력에 영향을 주도록 연결하는 것입니다.

## 79–90초 · 입력을 내려도 상태가 유지된다

79–84초: 이때 한쪽 출력이 1이고 다른 쪽 출력이 0인 상태가 만들어졌다고 생각해 보겠습니다.

84–90초: 외부 입력을 모두 0으로 유지하면, 두 게이트는 서로의 출력을 통해 이 상태를 계속 유지할 수 있습니다.

## 90–95초 · 반대 상태 역시 유지된다

90–95초: 반대로 한쪽 출력을 0, 다른 쪽 출력을 1로 만든 상태 역시 유지할 수 있습니다.

## 95–102초 · 같은 입력, 다른 상태

95–102초: 즉, 같은 외부 입력이 주어져도 이전에 어떤 상태였는지에 따라 서로 다른 출력이 유지될 수 있는 것입니다.

## 102–106초 · 두 안정 상태로 1비트 저장

102–106초: 이렇게 두 가지 안정된 상태를 이용하면 0과 1을 기억할 수 있습니다.

## 106–114초 · Set · Hold · Reset

106–112초: 그리고 외부 입력을 통해 저장된 상태를 1로 설정하거나, 0으로 초기화할 수도 있습니다.

112–114초: 이것이 SR 래치의 기본적인 원리입니다.

## 114–122초 · 같은 게이트, 새로운 연결 구조

114–122초: 중요한 것은 새로운 종류의 계산 소자가 필요한 것이 아니라, 이미 알고 있던 논리 게이트를 서로 연결해 기억이라는 기능을 만들었다는 점입니다.

## 122–130초 · 새 값을 언제 기록할까?

122–125초: 하지만 아직 해결하지 못한 문제가 있습니다.

125–130초: 기억한 값을 새로운 값으로 바꾸려면, 그 변화는 언제 일어나야 할까요?

## 130–140초 · 여러 회로의 갱신 시점

130–135초: 여러 계산 회로가 서로 연결되어 있다면, 각 회로의 상태를 아무 때나 바꿔도 괜찮을까요?

135–140초: 다음에는 저장된 값을 갱신하는 시점을 어떻게 제어하는지 살펴보겠습니다.
