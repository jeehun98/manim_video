# 02 · 중간 결과는 다음 계산의 입력

## 목적·주장
두 가산기를 연결하면 (5+3)+2=10이지만 단계별 복제 비용이 있다.

## 시작·앞 장면
ALU의 결과를 다음 계산의 입력으로 사용한다.

## 확정 대본·길이
사용자 종료 시각 11–31초, 20초. 실제 제공 시각을 유지하며 길이를 추정하지 않는다.

예를 들어 5와 3을 더하고, 그 결과에 다시 2를 더한다고 생각해 보겠습니다.

가장 간단한 방법은 두 개의 덧셈 회로를 연속으로 연결하는 것입니다.

첫 번째 회로에서 나온 8이 두 번째 회로로 전달되면 최종 결과인 10을 얻을 수 있습니다.

하지만 계산 단계마다 새로운 회로를 추가해야 한다면, 회로의 규모도 계속 커지게 됩니다.

## 화면·타임라인
| 전체 초 | 화면 |
| --- | --- |
| 11–16 | (5+3)+2 수식 |
| 16–20 | ADDER1→ADDER2, n-bit 버스 |
| 20–23 | 첫 출력8 |
| 23–26 | 8+2→10 |
| 26–31 | 단계별 복제 설계의 소자·배선 증가 |

## 종료·연결
두 가산기를 연결하면 (5+3)+2=10이지만 단계별 복제 비용이 있다. 다음 씬은 하나의 ALU를 반복해서 쓰려면를 보여준다.

## 정확성·조건
ALU 재사용의 데이터 버스와 래치 내부 되먹임선을 혼동하지 않는다. 조합논리의 한계를 설명한다. 일반 되먹임만으로 기억을 보장하지 않는다. 위 NOR는 R·Qbar, 아래 NOR는 S·Q를 입력받는다. 교차선에는 접합점을 넣지 않고 브리지로 구분한다. S 설정은 Qbar0→Q1, R 초기화는 Q0→Qbar1 순서. 전파 중에는 지연 모형임을 표시하며 안정 상태에서 두 NOR 식을 모두 검증한다. S=R=1은 실제 시연하지 않고 사용안함으로만 표기한다. 초기 상태는 전원투입 자동 초기화가 아니라 가정된 상태이다. 전원 공급·정상 동작 조건의 휘발성 저장이다. 시간 개념도에 D입력이나 실제 클럭 제어가 이미 구현된 것으로 그리지 않는다. 사용자 도입·마지막 문장은 유지하되 GPU07 추가 예고는 넣지 않는다.
