# 15 — 좌표는 논리적인 위치

- 목적·주장: 최대 3차원 Thread 좌표는 논리 좌표다.
- 입력 상태: 전체 배열의 인덱스
- 확정 구간: 128–140초 (12초), 사용자 문장 종료 시각. 음원 미제공.
- TTS 원문: [script.txt](script.txt). 실제 음원 길이는 미측정.
- 화면·타임라인: 공통 visuals.py의 INDEX=14 분기. 문장 종료 시각에 따라 코드 강조·값·연결 변화.
- 화면 텍스트: 좌표는 논리적인 위치; 해당 CUDA 식과 실제 배열 값.
- 시작·종료 상태: 해당 주장 대상 등장 → 동작 시각화 → 주장이 드러난 상태 유지.
- 연결: Thread가 맡는 계산
- 정확성: 논리 실행 문맥과 물리 연산기를 구별. Register 배치는 개념도이며 기계 명령 trace가 아님. 세로·가로 레이아웃 공통 주장.

## 확정 화면 동작

128–134초 4×4 논리 좌표와 (2,1) 선택, x열/y행 대응. 134–140초 논리 좌표와 물리 위치의 차이 강조.

## 문장별 종료 시각과 원문

128–134초: 또한 CUDA에서는 스레드의 인덱스를 최대 3차원으로 표현할 수 있어, 행렬의 행과 열에도 대응시킬 수 있습니다.

134–140초: 단, 이 좌표는 실제 하드웨어의 물리적 위치가 아니라 프로그램에서 사용하는 논리적 좌표입니다.

## v3 구조 연결

기준 실행 배치도는 GPU·SM 0·Block·Thread 위치를 유지한다. 현재 Thread의 색과 선택 테두리를 상세 그림에 대응시키고, 선택 대상에서 상세 화면으로 확대한다. Register 장면은 같은 SM 안의 Block과 Thread 1을 남긴다. 두 Block 비교와 2D 설정은 지도에도 동시에 반영한다. 구체적인 화면 계약은 프로젝트의 continuity.md와 visuals.py를 따른다. 대본과 확정 구간은 변경하지 않는다.
