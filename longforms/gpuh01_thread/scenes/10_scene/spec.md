# 10 — SM의 Register File

- 목적·주장: Register File은 SM의 물리적 자원이다.
- 입력 상태: 읽기 · 계산 · 저장
- 확정 구간: 81–92초 (11초), 사용자 문장 종료 시각. 음원 미제공.
- TTS 원문: [script.txt](script.txt). 실제 음원 길이는 미측정.
- 화면·타임라인: 공통 visuals.py의 INDEX=9 분기. 문장 종료 시각에 따라 코드 강조·값·연결 변화.
- 화면 텍스트: SM의 Register File; 해당 CUDA 식과 실제 배열 값.
- 시작·종료 상태: 해당 주장 대상 등장 → 동작 시각화 → 주장이 드러난 상태 유지.
- 연결: 변수와 실제 자원
- 정확성: 논리 실행 문맥과 물리 연산기를 구별. Register 배치는 개념도이며 기계 명령 trace가 아님. 세로·가로 레이아웃 공통 주장.

## 확정 화면 동작

81–85초 Thread 문맥과 SM Register File 분리 표시. 85초 자원 강조. 89–92초 SM의 물리 자원이라는 결론.

## 문장별 종료 시각과 원문

81–85초: GPU에는 이러한 값을 빠르게 저장하기 위한 레지스터가 있습니다.

85–92초: 레지스터는 스레드마다 물리적으로 따로 설치된 것이 아니라, GPU의 실행 장치인 SM에 존재하는 자원입니다.

## v3 구조 연결

기준 실행 배치도는 GPU·SM 0·Block·Thread 위치를 유지한다. 현재 Thread의 색과 선택 테두리를 상세 그림에 대응시키고, 선택 대상에서 상세 화면으로 확대한다. Register 장면은 같은 SM 안의 Block과 Thread 1을 남긴다. 두 Block 비교와 2D 설정은 지도에도 동시에 반영한다. 구체적인 화면 계약은 프로젝트의 continuity.md와 visuals.py를 따른다. 대본과 확정 구간은 변경하지 않는다.
