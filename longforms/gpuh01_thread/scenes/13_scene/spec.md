# 13 — Block 내부의 위치

- 목적·주장: 서로 다른 Block에 같은 threadIdx가 있다.
- 입력 상태: 한 Thread, 여러 원소
- 확정 구간: 109–121초 (12초), 사용자 문장 종료 시각. 음원 미제공.
- TTS 원문: [script.txt](script.txt). 실제 음원 길이는 미측정.
- 화면·타임라인: 공통 visuals.py의 INDEX=12 분기. 문장 종료 시각에 따라 코드 강조·값·연결 변화.
- 화면 텍스트: Block 내부의 위치; 해당 CUDA 식과 실제 배열 값.
- 시작·종료 상태: 해당 주장 대상 등장 → 동작 시각화 → 주장이 드러난 상태 유지.
- 연결: 전체 배열의 인덱스
- 정확성: 논리 실행 문맥과 물리 연산기를 구별. Register 배치는 개념도이며 기계 명령 trace가 아님. 세로·가로 레이아웃 공통 주장.

## 확정 화면 동작

109–112초 두 Block에서 Thread 2 선택. 112–116초 Block별 논리 그룹 강조. 116–121초 동일 threadIdx.x=2, 서로 다른 Block.

## 문장별 종료 시각과 원문

109–112초: 마지막으로 스레드의 위치를 살펴보겠습니다.

112–116초: CUDA에서 스레드는 블록이라는 논리적인 그룹에 속합니다.

116–121초: threadIdx.x는 GPU 전체의 고유 번호가 아니라 블록 내부의 위치입니다.

## v3 구조 연결

기준 실행 배치도는 GPU·SM 0·Block·Thread 위치를 유지한다. 현재 Thread의 색과 선택 테두리를 상세 그림에 대응시키고, 선택 대상에서 상세 화면으로 확대한다. Register 장면은 같은 SM 안의 Block과 Thread 1을 남긴다. 두 Block 비교와 2D 설정은 지도에도 동시에 반영한다. 구체적인 화면 계약은 프로젝트의 continuity.md와 visuals.py를 따른다. 대본과 확정 구간은 변경하지 않는다.
