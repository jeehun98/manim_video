# v3 — 같은 GPU 안에서 대상을 따라가는 화면

사용자 피드백: 개별 설명 그림만 교체되어 Thread·SM의 대응과 구조가 기억에 남지 않았다. 대본·33개 문장 종료 시각·152초·코드 패널 v2는 유지하고 구조 표현을 수정한다.

## 고정 기준 화면

모든 씬에 같은 GPU 실행 배치도를 유지한다. GPU 외곽 안의 SM 0, 그 SM에 배치된 논리 그룹 Block 0의 네 Thread, SM의 저장 자원을 고정 위치에 놓는다. Block은 점선, GPU·SM은 실선으로 표시하고 ‘실행 배치 개념도’라고 명시한다. 논리 단위가 하드웨어 부품이라는 뜻이 아니다.

Thread 0은 파랑, Thread 1은 초록, Thread 2는 주황, Thread 3은 보라로 유지한다. 선택 테두리와 설명 화면의 대상 이름·계산을 같은 색으로 연결한다. 자세한 설명은 고정 지도에서 선택한 대상을 복사해 확대하는 애니메이션으로 등장한다. 씬이 바뀌어도 기준 지도와 Block·Thread 위치는 유지한다.

## 화면 흐름

- 0–16초: GPU와 Thread의 실행 문맥을 관찰한다. 고정 지도에서 선택한 Thread 0이 확대된 카드와 대응한다.
- 16–36초: 같은 지도 아래에서 배열 A/B/C를 표시한다. 배열을 계산하는 대상의 Thread 번호·색상이 지도와 일치한다.
- 36–70초: 코드의 인덱스를 강조하면 지도에서 해당 Thread를 선택한다. 배열 설명에서 별도의 Thread 네 개를 다시 만들지 않는다.
- 70–81초: 지도에서 초록색 Thread 1을 유지하고 읽기·계산·저장을 확대한다. `i=1`, `a=2`, `b=20`, `sum=22`, `C[1]=22`는 같은 문맥의 상태 변화다.
- 81–99초: 새로운 출처 없는 SM 그림으로 교체하지 않는다. 같은 지도 속 SM 0을 확대해 Block 0의 네 Thread와 Register File을 함께 보여준다. 초록색 Thread 1과 그에 할당된 Register 자원 예시를 연결한다. 실제 Register 번호·배치를 주장하지 않는다.
- 99–109초: 선택을 Thread 0으로 옮기고 같은 Thread가 `C[0]`, `C[4]`, `C[8]`을 처리하는 것을 보여준다.
- 109–128초: 기존 지도 속 다른 Block 자리에서 Block 1을 드러낸다. 두 Block의 주황색 Thread 2를 함께 선택하고 각각 전역 위치 2와 6으로 연결한다. 거대한 Block 그림 두 개를 설명 영역에 다시 복제하지 않는다.
- 128–140초: 다른 설정임을 ‘2D 설정 예시’로 표시하고 Block 0을 4×4 논리 좌표 보기로 바꾼다. 지도와 확대 보기에서 동일한 `(2,1)` 칸을 초록색으로 선택한다.
- 140–152초: 같은 GPU·SM·Block 기준 화면 위에서 Thread의 Index·State·Work를 정리한다. 새로운 후속편 예고는 넣지 않는다.

## 배치와 검증

세로는 위의 기준 지도 → 선택 대상 설명 → 코드 패널 → 자막 순서다. 가로는 왼쪽 위의 기준 지도·왼쪽 아래의 선택 대상 설명, 오른쪽 코드 패널, 하단 자막으로 배치한다. 코드 영역은 v2의 배경·테두리·큰 글자·발췌 방식을 유지한다.

지도·상세 그림·코드 패널의 경계를 geometry JSON에 기록한다. `verify.py`로 두 최종본의 화면 경계·4560프레임·30fps·152초를 확인하고, 실제 최종 프레임 시트에서 Thread 선택과 Register 연결을 확인한다.
