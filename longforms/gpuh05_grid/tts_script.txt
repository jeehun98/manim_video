GPU에서는 여러 스레드가 블록을 구성하고, 각 블록은 에스엠에 배치되어 실행됩니다.
그렇다면 수많은 블록을 GPU 전체에 실행하려면 어떻게 해야 할까요?
여기서 등장하는 것이 그리드입니다.
그리드는 하나의 쿠다 커널 실행에 속하는 모든 블록을 묶은 논리적인 작업 공간입니다.

하나의 그리드를 살펴보겠습니다.
이번에는 12개의 블록으로 구성된 그리드를 생각해 보겠습니다.
각 블록에는 128개의 스레드가 있으므로, 전체 그리드에는 1,536개의 스레드가 존재합니다.

하지만 이 스레드들이 모두 같은 순간에 실행된다는 뜻은 아닙니다.
그리드는 실행할 작업 전체를 정의하고, 실제 하드웨어는 사용 가능한 자원에 따라 블록들을 나누어 실행합니다.

실제 쿠다 코드를 살펴보겠습니다.
커널을 호출할 때 사용하는 세 개의 꺾쇠괄호 안에는 그리드의 크기와 블록의 크기를 지정할 수 있습니다.

블록 크기를 128로 설정하면, 하나의 블록에는 128개의 스레드가 배치됩니다.
그리고 그리드 크기를 12로 설정하면, 총 12개의 블록이 만들어집니다.

그렇다면 각 스레드는 전체 데이터에서 자신이 담당할 위치를 어떻게 알 수 있을까요?
여기서 사용하는 것이 블록 인덱스 엑스, 블록 디멘션 엑스, 그리고 스레드 인덱스 엑스입니다.

블록의 인덱스에 블록 크기를 곱하고, 블록 내부의 스레드 인덱스를 더하면 전체 데이터에서의 위치를 계산할 수 있습니다.

예를 들어 블록 0의 스레드 5는 5번 원소를 처리합니다.
반면 블록 1의 스레드 5는 128에 5를 더한 133번 원소를 처리합니다.

같은 스레드 인덱스를 가지더라도 블록이 다르면 담당하는 데이터가 달라지는 것입니다.

그렇다면 이렇게 정의된 블록들은 실제 GPU에서 어떻게 실행될까요?
GPU에는 여러 개의 에스엠이 존재합니다.
그리드에 포함된 블록들은 실행 가능한 에스엠에 배치됩니다.

에스엠의 자원이 허용하면 여러 블록이 동시에 상주할 수도 있습니다.
반대로 그리드에 포함된 블록이 많다면, 일부 블록은 앞선 블록의 실행이 끝나 자원이 확보될 때까지 기다려야 합니다.

여기서 중요한 점이 있습니다.
블록들은 반드시 인덱스 순서대로 실행되지 않습니다.
어떤 블록이 먼저 실행될지는 GPU의 하드웨어 스케줄링에 따라 달라질 수 있습니다.

따라서 일반적인 쿠다 커널에서는 서로 다른 블록이 특정한 순서로 실행된다고 가정해서는 안 됩니다.

그렇다면 그리드는 반드시 일차원으로 구성해야 할까요?
그렇지는 않습니다.
쿠다에서는 그리드를 최대 삼차원으로 구성할 수 있습니다.

예를 들어 이미지를 처리할 때는 그리드를 이차원 격자로 구성하고, 각 블록이 이미지의 서로 다른 영역을 담당하도록 만들 수 있습니다.
이때 블록 인덱스 엑스와 블록 인덱스 와이는 각 블록이 담당하는 논리적인 위치를 나타냅니다.

하지만 이 좌표가 실제 GPU 칩에서 블록이 실행되는 물리적 위치를 뜻하는 것은 아닙니다.

결국 스레드는 개별 명령을 실행하는 논리적인 단위이고, 블록은 스레드들이 협력하는 그룹이며, 그리드는 하나의 커널 실행에 속한 블록 전체를 정의하는 작업 공간입니다.

그리고 실제 GPU에서는 여러 에스엠이 이 블록들을 배치받아 실행합니다.
즉, 그리드는 우리가 정의한 병렬 작업의 구조이고, 에스엠은 그 작업을 실제로 수행하는 하드웨어입니다.
