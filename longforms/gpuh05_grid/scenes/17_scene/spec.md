# Thread · Block · Grid

## 목적과 핵심 주장
Thread·Block·Grid는 논리 실행 구조다

## 앞 장면에서 받은 내용
동일한 Block ID와 색상, Grid와 GPU의 분리된 영역을 유지한다. 첫 씬은 SM 0에서 시작한다.

## TTS와 확정 길이
사용자 문장 종료 시각 156–166초, 10초. 음원 미제공.

결국 스레드는 개별 명령을 실행하는 논리적인 단위이고, 블록은 스레드들이 협력하는 그룹이며, 그리드는 하나의 커널 실행에 속한 블록 전체를 정의하는 작업 공간입니다.

## 화면·애니메이션
- 156초: Thread 실행 문맥
- 159초: Block 협력 그룹
- 162초: Grid 작업 전체

## 화면 텍스트
Logical Grid / Physical GPU / Block 0–11 / SM 0–3. Block 5는 양쪽에서 초록색이다. 코드 패널은 배경·테두리·제목을 분리하고 줄 번호는 쓰지 않는다.

## 시작·종료 상태와 연결
Block의 논리적 위치는 실제 SM 위치와 분리한다. 확대된 객체는 원래 선택한 Block과 연결한다. 씬별 완료 영상으로 결합하며 복습·다음 편 예고는 없다.

## 정확성
물리 배치는4SM의 설명용 개념도이며 실측 trace가 아니다. Grid 12Block·128Thread·N1536을 고정한다. 2D 이미지 예시는 별도 kernel, block16×16, image80×64, grid5×4다. 실행 순서 무관성은 각 Block이 겹치지 않는 출력에 기록하는 이 예제의 조건이다. Block1 Thread5=133, Block0 Thread5=5. 출처는 brief.md 참조.
