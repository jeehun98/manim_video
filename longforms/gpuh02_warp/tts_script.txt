지피유에서는 수많은 스레드가 계산을 수행합니다. 그렇다면 이 스레드들은 실제 하드웨어에서 모두 독립적으로 실행될까요?

엔비디아 지피유에서는 32개의 스레드를 하나의 워프, 워프로 묶어 실행합니다. 워프는 지피유가 스레드들을 스케줄링하고 명령을 실행하는 기본 단위입니다.

하나의 워프를 살펴보겠습니다. 워프는 32개의 스레드로 구성됩니다. 그리고 각 스레드는 워프 안에서 0부터 31까지의 위치를 가집니다. 이 위치를 레인, 레인이라고 부릅니다.

즉, 스레드는 명령을 실행하는 논리적인 단위이고, 레인은 워프 안에서 해당 스레드를 구분하는 번호입니다. 이 스레드들은 각자 다른 데이터와 실행 상태를 가지지만, 워프 단위로 명령을 실행합니다.

이러한 실행 모델을 심트, 싱글 인스트럭션, 멀티플 스레즈라고 합니다. 실제 쿠다 코드를 살펴보겠습니다.

화면의 커널은 두 배열의 원소를 더하는 프로그램입니다. 각 스레드는 스레드 인덱스 점 엑스를 이용해 자신이 처리할 원소를 선택합니다.

스레드 0은 0번 원소를, 스레드 1은 1번 원소를 계산합니다. 이렇게 32개의 스레드가 같은 명령을 실행하면서 서로 다른 데이터를 처리합니다.

그런데 모든 스레드가 항상 같은 명령 경로를 따라야 할까요? 이번에는 코드에 조건문을 추가해 보겠습니다.

스레드의 인덱스가 16보다 작으면 값을 두 배로 만들고, 그렇지 않으면 1을 더하도록 작성합니다.

이제 워프 안의 스레드 0부터 15까지는 곱셈을, 16부터 31까지는 덧셈을 수행해야 합니다. 문제는 하나의 워프 안에서 서로 다른 명령 경로가 필요하다는 것입니다.

지피유는 각 경로를 실행할 때 해당 경로에 참여하는 스레드만 활성화할 수 있습니다.

먼저 곱셈 경로에서는 앞의 16개 스레드가 활성화되고, 나머지 스레드는 해당 경로에서 비활성화됩니다.

덧셈 경로에서는 반대로 뒤의 16개 스레드가 활성화됩니다.

이처럼 하나의 워프에 속한 스레드들이 서로 다른 실행 경로로 나뉘는 현상을 워프 다이버전스, 워프 분기 발산이라고 합니다. 분기 발산이 발생하면 여러 경로를 처리해야 하므로 실행 효율이 떨어질 수 있습니다.

그렇다면 조건문이 있다는 사실만으로 항상 분기 발산이 발생할까요? 그렇지는 않습니다.

워프 안의 모든 스레드가 같은 조건을 만족한다면 동일한 경로를 실행할 수 있습니다. 중요한 것은 조건문의 존재가 아니라, 같은 워프 안에서 서로 다른 경로가 선택되는지입니다.

또한 실제 엔비디아 지피유의 실행 방식은 세대에 따라 차이가 있으며, 볼타 이후의 아키텍처에서는 스레드별 실행 상태를 더욱 독립적으로 관리할 수 있습니다.

하지만 워프 단위의 명령 실행과 활성 스레드의 개념은 여전히 중요합니다.

결국 스레드는 각자의 데이터와 실행 상태를 가진 논리적인 실행 단위이고, 워프는 이러한 스레드 32개를 묶어 명령을 실행하는 하드웨어 단위입니다.

지피유의 병렬 계산을 이해하려면 스레드가 몇 개 있는지만이 아니라, 이 스레드들이 어떤 명령 경로를 함께 실행하는지도 살펴봐야 합니다.
