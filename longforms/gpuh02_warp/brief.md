# GPU 계층 구조 LEVEL 02 — Warp

- 사용자 확정 원문 34문장·문장 종료 시각을 그대로 적용한 167초. 20개 독립 씬. 음원 미제공으로 무음·자막 영상.
- 세로 1080×1920·가로 1920×1080, 30fps. 미리보기 360×640·640×360, 15fps.
- 1편 v3의 GPU·SM 0·Block 0 배치를 유지한다. 같은 Block 안의 32개 Thread를 한 Warp 외곽선으로 묶는다. Warp를 물리적 개별 core처럼 그리지 않는다.
- 확대된 Lane은 8열×4행, 번호 0–31과 좌표 고정. 0–15는 위 두 행, 16–31은 아래 두 행. 분기 중 하나의 Warp 외곽선 유지, 비활성 Lane은 삭제하지 않고 어둡게 표시.
- 코드 강조·현재 소스 경로·주 화면과 기준 지도의 마스크가 함께 바뀐다. 곱셈은 0x0000FFFF, 덧셈은 0xFFFF0000의 소스 경로 참여 집합 개념도.
- 모든 코드는 1D Block 한 개·32 Thread·길이 32 이상의 배열 조건. 이 예시에서는 threadIdx.x와 Lane이 같음. 일반적인 1D Block의 Lane은 threadIdx.x % 32. 다차원에서는 선형 Thread 순서 기준.
- 입력은 A[i]=i+1, B[i]=10(i+1). 벡터 덧셈 출력 C[i]=11(i+1). 조건문은 i<16이면 입력을 두 배, 나머지는 1을 더함. 균일 경로 비교에는 조건을 i<32로 바꾼 별도 kernel 사용.
- source if는 실제 compiler에서 predication·연산 대체로 바뀔 수 있다. 활성 마스크 연출은 소스 경로 개념도이며 실제 SASS trace·발행 순서·사이클·정확한 성능 배율이 아니다. 16/32는 예시 명령 경로의 참여량이지 성능이 절반이라는 측정값이 아니다.
- Volta 이후 Thread별 PC·상태 관리와 Warp 수준 명령 실행은 구별한다. 별도 명령 발행기 32개를 그리지 않음. 별도 세대별 benchmark 없음.
- 1편 복습·다음 편 예고 없이 이번 질문과 결론으로 완결. TTS 원고는 화면 변화별 빈 줄 구분, 읽지 않을 제목·시간 제외.
- 검증: 실제 CUDA 결과와 소스 경로 membership ballot을 별도로 검사. 자세한 compiler 확인은 compiler_notes.md. 렌더 후 verify.py로 정확한 길이·고정 Lane 좌표·마스크와 강조 코드의 일치를 검사.
