# 행렬곱의 계산량은 어디까지 줄일 수 있을까?

첨부 문서의 1~9번 대문단을 순서대로 따라가는 새 롱폼 구성이다. 기존 AI 수학 시리즈의 대본·콘티·영상은 사용하지 않는다. AI 연구 소개는 아래 여정을 이해한 뒤 별도로 검토한다.

## 제작 원칙

- 장은 원문의 대문단에 대응하고, 장 안에서는 주장 하나마다 씬을 나눈다. 장 하나를 반드시 쇼츠 하나로 맞추지 않는다.
- 매번 작은 계산을 직접 확인한 뒤, 그 계산으로 답할 수 없는 질문을 다음 장에 넘긴다.
- 숫자와 계산 대상을 유지하며 연결선·블록·항의 이동으로 변화를 추적한다. 수학적 이름은 그 표현이 필요한 순간에 붙인다.
- 실제 공식과 설명용 가정은 구분한다. 존재하지 않는 공동 계산 공식을 성과처럼 제시하지 않는다.
- 전체 대본 → 씬별 명세 → TTS 실측 → 화면 제작 순서로 진행한다. 현재는 구성 단계이며 길이를 확정하지 않는다.

## 1. 최초의 문제 — 행렬곱은 정말 n³번 계산해야 할까?

**질문:** 표준 방법의 계산량이 모든 방법의 최소 계산량일까?

3×3에서 한 칸의 3곱, 아홉 칸의 27곱을 세어 본다. 이어 2×2의 표준 8곱과 Strassen의 실제 7곱을 같은 입력·출력으로 비교한다. 중간 결과의 재사용과 불필요한 항의 소거를 확인한 뒤 블록으로 확장한다.

**씬 후보:** 한 출력 계산 / 전체 곱셈 수 / 7곱으로 같은 출력 복원 / 기호 항등식 / 블록 재귀와 성장률.

**직접 확인:** 숫자 예제의 동일 출력과 기호 항등식은 구분해서 확인한다. 블록에서는 곱셈 순서를 유지한다. 덧셈 비용도 포함하면 T(n)=7T(n/2)+O(n²)이다.

**다음 질문:** 세제곱이 최선이 아니라면, 최선의 성장률은 얼마일까?

## 2. 문제의 변화 — 최적의 알고리즘은 어디까지 가능한가?

**질문:** 작은 입력의 곱셈 횟수와 큰 입력의 성장률은 어떻게 다를까?

입력 크기를 두 배씩 키우며 n³과 n^(log₂7)의 증가를 비교한다. 알고리즘이 주는 상한과 모든 알고리즘에 적용되어야 하는 하한을 양쪽 경계로 표현한다. 그 사이에서 최적 지수 ω를 정의한다.

**직접 확인:** 표준적인 전체 출력·산술 계산 모델에서 이차의 기본 하한을 설명한다. ω=2는 정확한 O(n²) 알고리즘의 존재와 동일한 문장이 아니다. 모든 ε>0에 대한 Oε(n^(2+ε))라는 의미를 구분한다. 계수체와 비용 모델을 명시한다.

**다음 질문:** 더 좋은 작은 공식을 찾는 것으로 경계를 계속 낮출 수 있을까?

## 3. 첫 번째 접근 — 더 좋은 작은 행렬곱 공식을 찾는다

**질문:** 작은 공식이 좋아지면 큰 행렬에도 항상 더 유리할까?

블록에 적용할 수 있는 m×m의 r곱 공식을 재귀적으로 반복해 log_m r을 얻는다. Strassen의 log₂7과 Laderman의 log₃23을 비교한다. 3×3에서 표준 27곱보다 23곱이 적어도 성장 지수는 Strassen보다 높다는 점을 확인한다.

**직접 확인:** 약 2.807과 2.854를 비교한다. 23이 3×3의 최솟값이라고 주장하지 않는다. 공식을 실제로 작동시키려면 모든 입력에서 출력이 복원되는 항등식이 필요하다.

**다음 질문:** 수많은 공식을 하나의 수학적 대상으로 비교할 수 없을까?

## 4. 두 번째 접근 — 행렬곱을 텐서로 바꿔 본다

**질문:** 계산 공식의 어떤 관계를 보존해야 할까?

2×2의 네 출력식을 고정한다. A의 입력, B의 입력, 출력 위치를 연결한다. 입력 선형 조합 두 개를 한 번 곱해 여러 출력에 분배하는 중간 계산을 하나의 단순 텐서로 나타낸다. 표준식의 8항과 Strassen의 7항을 대응시킨다.

**직접 확인:** 출력 표지는 실제 세 번째 입력을 곱하는 연산이 아니다. 하나의 중간 곱이 출력 여러 곳에 기여하는 연결을 직접 따라간다. 이것을 최소 몇 개로 표현하는지가 랭크 질문임을 도입한다.

**다음 질문:** 정확히 일치하는 분해만 허용해야 할까?

## 5. 세 번째 접근 — 정확한 분해가 아니라 근사 분해를 이용한다

**질문:** 극한에서만 맞는 구조가 정확한 계산에 어떻게 도움이 될까?

작은 매개변수를 가진 분해에서 원하지 않는 항의 계수가 0으로 접근하는 모습을 보여준다. 랭크와 보더 랭크를 구분한 뒤, 보간을 통해 정확한 계산복잡도와 연결되는 별도 논증이 필요함을 설명한다.

**직접 확인:** 사용할 퇴화 예제와 보간 계산은 대본 전에 별도 검증한다. 부동소수점 근사 답을 허용한다는 뜻으로 표현하지 않는다. 극한에서 필요한 텐서를 얻는 대수적 구조를 설명한다.

**다음 질문:** 한 행렬곱의 분해만 찾는 대신, 여러 행렬곱을 담은 구조를 연구하면 어떨까?

## 6. 네 번째 접근 — 하나의 텐서 안에서 여러 행렬곱을 찾는다

**질문:** 여러 독립적인 문제의 비용이 왜 한 행렬곱의 지수와 연결될까?

먼저 작은 실제 텐서에서 독립적인 계산을 추출하는 변환을 확인한다. 입력·출력 세 그룹이 모두 분리되는 직합을 공유 구조와 비교한다. 원래 텐서의 비용, 추출한 문제들의 크기, 점근적 합 부등식의 역할을 순서대로 연결한다.

**직접 확인:** 관련 조건 아래 보더 랭크 상한 r에 대해 Σᵢ(mᵢnᵢpᵢ)^(ω/3)≤r을 사용한다. 묶음 비용을 문제 수로 나누어 단일 문제의 작은 공식을 얻었다고 설명하지 않는다. 실제로 확인한 관계와 별도 정리가 제공하는 결론을 구분한다.

**다음 질문:** 작은 텐서에 충분한 구조가 없다면 반복해서 결합할 수 있을까?

## 7. 다섯 번째 접근 — 텐서의 거듭제곱에서 구조를 증폭한다

**질문:** 반복 결합은 어떤 새로운 선택지를 만들어 낼까?

T, T⊗T에서 블록의 번호를 쌍으로 추적한다. 문제 수와 크기의 증가를 실제 격자로 확인한다. 이어 Coppersmith–Winograd 계열에서 많은 블록 중 독립적인 묶음을 선택하는 문제로 연결한다.

**직접 확인:** 텐서곱은 두 결과 행렬을 다시 곱하는 연산이 아니다. 반복 결합만으로 유용한 독립 직합이 자동으로 확보되지는 않는다. 레이저 방법과 조합적 선택 도구는 역할이 필요한 지점에서 소개한다.

**다음 질문:** 구조를 크게 만들 수 있는데도 왜 경계를 쉽게 낮추지 못할까?

## 8. 그렇다면 기존 접근은 어디에서 막혔는가?

**질문:** 유용한 블록을 많이 남기는 것과 독립성을 확보하는 것은 왜 충돌할까?

하나의 연결도에서 블록을 많이 남긴 경우와 공유 관계를 제거한 경우를 비교한다. 제거 전후의 블록 수와 크기를 함께 세어, 독립성 확보에 따른 손실이 최종 비용 비교를 바꾸는 모습을 보여준다.

**직접 확인:** 특정 텐서·특정 분석 방법의 한계와 모든 행렬곱 알고리즘의 하한을 구분한다. 특정 레이저 방법의 장벽을 ω 자체의 장벽처럼 말하지 않는다. 구체적인 장벽 수치는 원 논문을 확인한 뒤 채택한다.

**다음 질문:** 각각의 방법은 처음 질문을 어떻게 바꾸어 왔을까?

## 9. 전체 발전 과정을 하나로 정리하면

표준 계산 → Strassen의 재조합 → 작은 공식 탐색 → 텐서 랭크 → 보더 랭크 → 독립 직합과 점근적 합 부등식 → 텐서 거듭제곱과 구조 선택을 앞 장의 동일한 시각 요소로 연결한다.

**도달점:** 행렬곱의 답을 계산하는 문제에서, 같은 계산을 표현하는 구조의 효율과 한계를 증명하는 문제로 관점이 확장되었음을 이해한다.

그 뒤에야 AI가 무엇을 탐색하거나 증명했는지 질문한다. 최신 성과·형식 검증·독립적 검토 상태는 실제 원문을 확보한 별도 후속 작업에서 확인한다. 기존 시리즈의 9/4 주장을 새 구성의 전제로 사용하지 않는다.

## 다음 제작 단계

1장의 전체 대본을 먼저 작성하고 위의 다섯 씬 후보를 주장 단위로 확정한다. 2장 이후의 개념은 1장에 미리 넣지 않는다. 이후 장도 같은 방식으로 작은 예제를 검증한 뒤 대본·명세·TTS·영상 순서로 제작한다. 첨부 문서의 마지막 심화 제안은 6장의 검증 과제로 반영하되, 전체 장 순서를 바꾸지 않는다.
