# 서로 다른 위치에 쓰고 이웃 값 읽기

## 목적·핵심 주장
서로 다른 위치에 쓰고 이웃 값 읽기를지속되는메모리관계도의동작으로설명한다.

## 앞 장면과 연결
SM0·Block0·Thread5녹색·Thread6주황·Shared청록색식별을유지한다.

## TTS와 확정 길이
사용자문장종료시각 40–49초, 9초. 음원미제공.

예를 들어 스레드 5는 5번 위치에, 스레드 6은 6번 위치에 값을 저장합니다.
이때 스레드 5가 스레드 6이 저장한 값을 읽을 수도 있습니다.

## 화면과 타임라인
- 40초: T5에105,T6에106저장
- 45초: 동기화완료가정에서T5가s6을읽어106반환

## 화면 텍스트
SharedMemory / Block0 / T5 / T6 / s5 / s6 / __syncthreads(). 코드1–4줄,배경·테두리분리,줄번호없음. 상단도실제값이움직이고상태가변한다.

## 시작·종료 상태
같은메모리관계도에서값·접근경로·도착상태만갱신한다. 새그림을계속갈아끼우지않고동일객체변형으로이어간다. 다음영상예고없음.

## 정확성
neighborRead는1Block128Thread·입력A[t]=100+t. T5는s5에쓰고s6에서106을읽는다. 불안전예시는결과를특정하지않으며실제로경쟁커널을실행하지않음. 정상코드는128Thread가모두배리어에참여. GEMM은별도N4,T2·4Thread/Block의예제. 요청원소수32/16은선택4출력에대한소스수준수이며실측DRAM트랜잭션·속도배수가아님. Bank는32개중0–3과활성4Lane만표시,단어주소mod32,같은주소broadcast예외. 용량비교는별도가상SM모델.
