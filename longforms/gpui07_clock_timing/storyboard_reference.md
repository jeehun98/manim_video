# GPU 개론 07 — 회로는 언제 값을 갱신할까?

상세 영상화 콘티 · 총 135초 · 9:16 세로 영상 · Manim 2D 애니메이션

이번 영상의 핵심은 계산 결과가 만들어지는 순간과 그 결과를 기억하는 순간은 다르다는 사실이야.

6편에서는 Feedback을 이용해 이전 값을 유지하는 회로를 만들었어. 이번에는 그 저장 기능을 ALU 뒤에 연결하고, 계산에 시간이 걸리기 때문에 저장 시점을 별도로 설계해야 한다는 문제를 보여주는 거지.

영상 전체에서 새로운 회로를 계속 등장시키지 말고, 하나의 구조를 단계적으로 발전시키는 게 좋아.

# ACT 1. 계산 결과는 즉시 완성되지 않는다

### 00:00–00:05 — 이전 영상의 기억 회로

나레이션: 앞서 우리는 논리 게이트를 연결해 이전 값을 기억하는 회로를 만들었습니다.

화면

6편에서 사용했던 NOR 게이트 두 개의 SR 래치를 다시 보여줘.

- 중앙에 교차 연결된 NOR 게이트 두 개
- 오른쪽 위 출력 Q=1, 아래 출력 Q̅=0

### 00:12–00:15 — 우리가 예상하는 결과

나레이션: 우리는 결과가 8이라는 사실을 알고 있습니다.

화면

ALU 오른쪽에 `8`이 크게 등장해.

동시에 위쪽에는 `5 + 3 = 8`을 표시해.

이 장면에서는 결과가 곧바로 등장하는 수학적 표현을 먼저 보여주고, 바로 다음 장면에서 물리적 회로의 실제 시간 지연을 대비시키는 게 좋아.

### 00:15–00:20 — 실제 회로에서는 시간이 흐른다

나레이션: 하지만 실제 회로에서는 입력이 들어오는 순간 결과가 완성되는 것이 아닙니다.

화면

방금 등장했던 `8`을 잠시 흐리게 만들고, 회로 아래에 수평 시간축을 추가해.

왼쪽에는 `입력 변화`, 오른쪽에는 `출력 안정`을 표시하고, 둘 사이에 시간 간격을 둬.

위쪽의 ALU는 그대로 유지해.

중요한 건 입력과 출력이 동시에 변화하지 않을 수 있다는 점을 단순한 시간축 하나로 전달하는 거야.

### 00:20–00:24 — 논리 게이트의 전달 지연

나레이션: 전기 신호가 논리 게이트를 통과하는 데는 시간이 필요하기 때문입니다.

화면

ALU 블록 내부를 확대해 논리 게이트 세 개가 연결된 간단한 경로를 보여줘.

입력 변화가 첫 번째 게이트에 반영되고, 잠시 뒤 두 번째, 세 번째 게이트 출력에 반영되는 과정을 순차적으로 표현해.

각 게이트 아래에 작은 시간 표시를 배치할 수 있어.

`입력 변화 → 게이트 1 → 게이트 2 → 출력`

여기서는 빛이 물체처럼 이동하는 것보다 각 노드의 전압 상태가 시간차를 두고 바뀌는 방식이 정확해.

### 00:24–00:29 — 올림수 전파 지연 복습

나레이션: 앞서 살펴본 덧셈 회로에서도 올림수가 다음 자리로 전달되는 데 시간이 걸렸습니다.

화면

4편의 가산기 장면을 짧게 재현해.

4비트 Ripple Carry Adder를 가로로 배치하고, 하위 비트부터 발생한 올림수가 다음 자리의 Carry In으로 순차 전달되는 과정을 강조해.

예시는 다음과 같이 선택해.

\\[ 0111_2+0001_2=1000_2 \\]

올림수 경로만 주황색으로 강조하고, 나머지 회로는 회색으로 낮춰.

이후 다시 전체 ALU 화면으로 복귀해.

### 00:29–00:33 — 다른 경로, 다른 도착 시점

나레이션: 또한 서로 다른 경로를 거치는 신호는 도착하는 시간이 다를 수 있습니다.

화면

입력 A에서 출력까지 이어지는 두 개의 논리 경로를 나란히 표시해.

- 위쪽 경로: 게이트 1개
- 아래쪽 경로: 게이트 3개

입력 신호가 동시에 변해도 두 경로의 마지막 출력이 서로 다른 시점에 바뀌는 모습을 보여줘.

경로 길이와 게이트 수를 달리하는 것은 예시일 뿐, 실제 지연은 게이트 종류와 부하 등의 조건에도 영향을 받으므로 `짧은 경로/긴 경로`보다는 `빠른 경로/느린 경로`로 표시하는 편이 정확해.

### 00:33–00:38 — 안정되지 않은 출력

나레이션: 따라서 입력이 바뀐 직후에는 출력이 아직 안정되지 않았을 수도 있습니다.

화면

ALU 출력 오른쪽에 시간에 따른 신호 변화를 확대해 보여줘.

처음에는 이전 값, 그다음에는 잠깐의 중간 상태, 마지막에는 안정된 결과 8이 나타나도록 해.

다만 출력 전체 숫자가 반드시 특정 순서로 변한다고 단정하지 않고, 가능한 일시적 변화의 한 예라는 것을 표현해.

마지막에는 출력이 `8`로 안정되면서 초록색 테두리로 강조돼.

# ACT 2. 결과는 어느 순간에 저장해야 할까?

00:38–00:56 · ALU 뒤에 저장 회로를 추가하고 저장 시점을 문제로 제시

### 00:38–00:42 — ALU와 저장 회로 연결

나레이션: 그런데 ALU의 출력에 저장 회로를 연결했다고 생각해 보겠습니다.

화면

앞 장면의 ALU를 화면 왼쪽으로 이동시켜.

오른쪽에는 6편에서 만들었던 저장 블록을 다시 등장시키고, ALU의 출력선을 저장 블록의 입력까지 연결해.

중앙에는 다음 구도가 완성돼.

`ALU → 계산 결과 → 저장 회로`

저장 회로는 아직 특정 순간에 데이터를 받아들이는 방식으로 설정하지 않아. 입력 신호를 받는 추상적인 저장 기능 블록으로만 표현해.

### 00:42–00:45 — 너무 이른 저장

나레이션: 계산이 끝나기도 전에 값을 저장한다면 어떻게 될까요?

화면

시간축과 회로를 동시에 보여줘.

시간축에서 ALU 출력이 안정되기 전의 한 지점에 주황색 세로선을 그어.

이 세로선 위에 `저장`이라는 문구를 표시하고, 해당 순간의 출력 상태를 저장 블록에 받아들이는 장면을 만들어.

예를 들어 ALU가 최종적으로 8을 출력해야 하지만, 해당 시점에 출력 버스에 나타난 값이 0이라면 저장 블록에 `0`이 기록되는 식이야.

이 `0`은 가상 타이밍 예시에서 선택한 실제 중간 버스값으로 처리해. 언제나 0이 먼저 나타나는 것처럼 묘사하지는 않아야 해.

### 00:45–00:50 — 잘못된 결과를 기억한다

나레이션: 우리가 원했던 8이 아니라, 아직 완성되지 않은 중간 상태를 기억할 수도 있습니다.

화면

ALU 출력은 시간이 지나면서 최종 결과 `8`로 바뀌어.

하지만 저장 블록에는 앞서 기록한 `0`이 그대로 남아 있어.

ALU의 최종 출력

# 8

계산 완료

너무 일찍 저장한 값

# 0

기록된 값은 그대로

이 대비를 2초 정도 유지하면서, 계산이 나중에 완료되더라도 이미 잘못 저장한 값이 자동으로 수정되는 것은 아니라는 사실을 보여줘.

### 00:50–00:56 — 저장 시점을 뒤로 옮긴다

나레이션: 그렇다면 계산 결과가 안정될 시간을 확보하고, 정해진 순간에만 값을 저장하도록 만들면 어떨까요?

화면

이전 장면의 시간축을 그대로 재사용해.

주황색 저장 시점 표시를 ALU 출력이 안정된 구간으로 이동시켜.

그 순간 저장 블록의 숫자가 `8`로 바뀌어 초록색으로 강조돼.

시점의 차이를 비교해.

- 출력 안정 전: 잘못된 값이 기록될 가능성
- 출력 안정 후: 의도한 결과를 기록할 수 있는 조건

연출 핵심: 새로운 회로를 소개하기 전에, 저장 시점을 변경하는 것만으로 문제가 해결될 수 있음을 직관적으로 보여줘.

# ACT 3. 플립플롭과 클럭

00:56–01:28 · 저장할 순간을 제어하는 방법 소개

### 00:56–00:59 — 새로운 저장 방식

나레이션: 여기서 새로운 저장 방식이 등장합니다.

화면

시간축은 아래로 이동시키고 저장 블록만 중앙에 크게 확대해.

입력선 D와 출력선 Q를 추가해.

저장 블록 테두리에 아직 이름을 적지 말고, 중앙에 `?`를 표시해.

상단에는 `특정 순간의 값을 기억한다면?`을 짧게 표시해.

### 00:59–01:05 — 입력을 따라가는 것과 순간을 저장하는 것

나레이션: 입력 신호를 계속 따라가는 대신, 특정한 신호 변화 순간의 값을 받아들이고 유지하는 것입니다.

화면

화면을 상하 두 부분으로 나눠.

위쪽은 데이터 입력 D, 아래쪽은 저장된 출력 Q야.

D는 시간에 따라 `0 → 1 → 0 → 1`로 변해.

하지만 Q는 데이터 변화에 계속 따라가지 않고, 화면 중앙의 주황색 세로선으로 표시된 특정 순간에만 값을 갱신해.

이때 Q가 바뀐 뒤에는 D가 다시 변해도 Q가 그대로 유지되는 것을 보여줘.

다만 이 비교는 기존 SR 래치가 데이터를 계속 따라간다는 의미가 아니야. 이번 장면의 대비는 시간에 따라 변하는 데이터 신호와, 특정 순간의 데이터를 보존하는 저장 동작 사이에 있어.

### 01:05–01:07 — 플립플롭

나레이션: 이러한 저장 회로를 플립플롭이라고 합니다.

화면

저장 블록에 `D Flip-Flop`이라는 이름을 붙여.

왼쪽 입력 `D`, 오른쪽 출력 `Q`, 아래쪽에 작은 삼각형으로 표시한 클럭 입력을 배치해.

기존 저장 블록이 새 물리 소자로 변신하는 느낌보다는, 지금부터 사용할 저장 회로를 구체화하는 화면이야.

### 01:07–01:13 — 클럭 상승 에지에서 저장

나레이션: 대표적인 D 플립플롭은 클럭 신호가 0에서 1로 바뀌는 순간 입력값을 저장합니다.

화면

플립플롭 아래에 클럭 파형을 그려.

사각파가 낮은 전압 상태에서 높은 전압 상태로 바뀌는 순간을 주황색 세로 점선으로 표시해.

그 순간 데이터 입력 D=1이라면 Q가 1로 갱신되는 모습을 보여줘.

클럭 상승 에지에서 저장

개념적 파형. 첫 상승 에지에서는 D=1을 기록하고, 두 번째 상승 에지에서는 D=0을 기록한다. 그림은 클럭-출력 지연을 생략했다.

중요: Q가 상승 에지보다 먼저 변하면 안 돼. 실제 회로에서는 클럭 에지 이후 짧은 전파 지연이 존재하므로, 애니메이션에서도 상승 에지 직후 Q가 바뀌도록 표현하면 더 정확해.

### 01:13–01:17 — 다음 시점까지 유지

나레이션: 그리고 다음 저장 시점이 올 때까지 이전 값을 유지합니다.

화면

데이터 D가 1에서 0으로 바뀌는 순간을 보여줘.

클럭은 아직 다음 상승 에지에 도달하지 않았고, Q는 여전히 1이야.

다음 상승 에지가 발생하면 그 순간의 D=0을 받아들여 Q가 0으로 바뀌어.

상단에는 `입력이 바뀌어도 저장값은 유지`를 표시해.

### 01:17–01:19 — 클럭이란?

나레이션: 그렇다면 클럭은 무엇일까요?

화면

플립플롭을 축소한 뒤 클럭 파형을 화면 중앙에 크게 확대해.

파형만 남기고 배경의 회로는 흐리게 처리해.

주황색 파형 아래에 `Clock`을 표시해.

### 01:19–01:22 — 주기적으로 변화하는 전기 신호

나레이션: 클럭은 일정한 주기로 0과 1을 반복하는 전기 신호입니다.

화면

클럭 파형이 왼쪽에서 오른쪽으로 여러 주기 그려져.

높은 상태는 `1`, 낮은 상태는 `0`으로 표시해.

두 연속 상승 에지 사이를 괄호로 묶고 `주기 T`라고 표시해.

이때 중요한 것은 전압이 갑자기 사라졌다 나타나는 것이 아니라, 높고 낮은 전압 수준 사이를 주기적으로 전환한다는 점이야.

### 01:22–01:28 — 공통된 저장 기준

나레이션: 이 신호의 특정 변화 순간을 저장 시점으로 사용하면, 회로가 값을 갱신하는 시점을 정할 수 있습니다.

화면

화면에 플립플롭 세 개를 가로로 배치해.

각 플립플롭 아래쪽 클럭 입력으로 동일한 주황색 배선이 분기돼 들어가.

하단의 클럭 파형에서 상승 에지가 발생하면 세 플립플롭의 테두리가 동시에 밝아져.

각 플립플롭이 자신의 입력값을 받아들이는 동작을 보여주는 것이지, 세 플립플롭이 모두 같은 데이터를 저장한다는 의미는 아니야.

# ACT 4. 클럭에는 속도 제한이 있다

01:28–01:45 · 계산에 필요한 시간과 클럭 주기의 관계

### 01:28–01:32 — 빠르면 무조건 좋을까?

나레이션: 그렇다면 클럭이 빠를수록 컴퓨터도 무조건 빨라질까요?

화면

앞 장면의 클럭 파형을 크게 보여줘.

처음에는 넓은 간격으로 반복되던 상승 에지가 점점 촘촘해져.

그 아래에는 ALU가 입력을 받은 후 최종 결과에 도달하는 시간을 하나의 수평 막대로 표시해.

클럭 주기가 짧아지면서 결과 안정 구간보다 다음 상승 에지가 앞서 나타나는 상황을 준비해.

### 01:32–01:33 — 그렇지 않다

나레이션: 그렇지는 않습니다.

화면

클럭이 지나치게 촘촘해진 순간 애니메이션을 정지시켜.

다음 상승 에지와 아직 계산이 끝나지 않은 ALU 출력을 주황색으로 강조해.

중앙에 아주 짧게 `계산 미완료`라고 표시해.

### 01:33–01:38 — 너무 이른 클럭

나레이션: 다음 클럭이 너무 일찍 도착하면 계산 결과가 충분히 안정되지 않았을 수 있기 때문입니다.

화면

ALU의 출력이 최종값 `8`로 안정되기 전, 플립플롭에 클럭 상승 에지가 도착하는 장면이야.

이때 출력에 `8`을 확정적으로 저장하지 말고, 저장 회로의 Q에 `?` 또는 `잘못된 값 가능`을 표시해.

이 장면에서는 두 가지 현상을 구분해야 해.

- 계산 결과가 아직 잘못된 논리값일 수 있음
- 플립플롭 입력이 클럭 에지 전후에 변하면 안정적인 샘플링 조건을 만족하지 못할 수 있음

둘 다 클럭을 무작정 빠르게 할 수 없는 이유지만, 영상에서는 출력이 안정되기 전에 저장하려 한다는 하나의 직관적인 문제로 보여주면 충분해.

### 01:38–01:45 — 계산 시간을 확보한다

나레이션: 따라서 클럭 주기는 회로에서 신호가 전달되고 계산이 완료되는 데 필요한 시간을 고려해 결정해야 합니다.

화면

두 파형을 나란히 비교해.

너무 짧은 주기

계산 완료 전에 저장 시점 도착

충분한 주기

결과가 안정된 뒤 저장

다음 상승 에지가 출력 안정 이후에 도착하는 오른쪽 구조를 강조하며 장면을 마무리해.

이때 단지 논리값이 맞아 보이는 것뿐 아니라 플립플롭이 요구하는 최소 안정 시간도 확보되어야 하지만, 별도의 타이밍 수식은 이번 영상에서 생략해.

# ACT 5. 클럭은 계산하지 않는다

01:45–02:15 · 클럭의 역할 정리와 동기식 회로의 도입

### 01:45–01:50 — 계산과 저장은 다른 동작

나레이션: 여기서 중요한 것은 클럭이 직접 계산을 수행하는 것이 아니라는 점입니다.

화면

기존에 사용한 ALU와 플립플롭 구조를 다시 중앙에 배치해.

이번에는 각 블록의 역할을 명확히 구분해.

ALU

계산 수행

Flip-Flop

결과 저장

Clock: 저장 시점 제어

ALU에는 클럭 배선을 연결하지 않아. 클럭은 플립플롭의 클럭 입력에만 연결해.

### 01:50–01:56 — 계산 경로와 클럭 경로

나레이션: 계산은 여전히 논리 게이트에서 이루어지고, 클럭은 저장된 값을 언제 갱신할지 정하는 기준을 제공합니다.

화면

같은 회로를 유지한 상태에서 두 동작을 연속해서 보여줘.

첫 번째: ALU의 입력이 바뀌고, 내부 계산 경로가 순차적으로 반응해 출력이 안정돼. 이 과정에서는 클럭 신호를 강조하지 않아.

두 번째: 계산 결과가 안정된 후 클럭 상승 에지가 발생하면, 플립플롭이 그 결과를 저장해.

이 장면은 화면을 두 개로 나누는 것보다 하나의 회로에서 시간에 따라 두 현상이 발생하는 방식이 더 좋아.

하단에는 `계산 → 결과 안정 → 저장`만 표시해.

### 01:56–02:02 — 여러 저장 회로로 확장

나레이션: 이제 이러한 저장 회로가 여러 개 있다면, 동일한 클럭을 이용해 상태 갱신 시점을 조정할 수도 있습니다.

화면

기존 플립플롭 하나를 화면 오른쪽으로 작게 옮겨.

그 옆에 두 번째와 세 번째 플립플롭이 등장해.

각 플립플롭은 서로 다른 데이터 입력 D를 가지고, 아래쪽에서는 하나의 공통 클럭선이 세 갈래로 분기돼 연결돼.

하나의 클럭, 여러 저장 회로

세 플립플롭은 동일한 기준 클럭을 사용하지만 각자 자신의 입력 데이터를 저장한다. 도식의 점선은 데이터 경로의 가능성을 암시할 뿐, 실제로 세 저장 요소를 직렬 연결한다는 의미는 아니다.

상승 에지가 발생하면 세 저장 회로가 동일한 시간 기준으로 값을 받아들이는 모습을 보여줘.

실제 회로에는 클럭 스큐와 전파 지연이 있으므로 완전히 동일한 물리적 순간에 Q가 바뀐다고 단정하지 않아야 해.

### 02:02–02:05 — 동기식 회로

나레이션: 이것이 동기식 회로의 기본적인 아이디어입니다.

화면

세 개의 플립플롭과 공통 클럭선 전체를 하나의 얇은 테두리로 묶어.

상단에 `Synchronous Circuit`을 표시하고, 아래에 작게 `동기식 회로`를 표시해.

클럭 신호의 상승 에지들이 주황색으로 강조되면서, 상태 갱신이 공통된 시간 기준 아래 이루어진다는 느낌을 줘.

### 02:05–02:10 — 이제 기억과 갱신이 가능하다

나레이션: 우리는 이제 계산 결과를 기억하고, 정해진 시점에 새로운 값으로 갱신할 수 있게 되었습니다.

화면

다시 단일 ALU와 저장 회로 하나로 돌아와.

앞에서 사용한 예시인 `5 + 3 = 8`을 마지막으로 재현해.

1. ALU에 5와 3 입력
2. 결과 8이 안정됨
3. 클럭 상승 에지 발생
4. 플립플롭에 8 저장

여기서 단일 플립플롭은 1비트만 저장할 수 있으므로, 8이라는 숫자를 저장하는 부분은 여러 비트의 플립플롭으로 구성된 레지스터 형태로 표현해야 해.

이번 영상에서는 여러 개의 플립플롭이 묶인 블록에 `8`을 저장하는 것으로 간단히 나타내면 충분해.

### 02:10–02:15 — 다음 편을 위한 질문

나레이션: 그렇다면 여러 저장 회로에 보관된 값들 중 어떤 것을 다음 계산에 사용해야 할까요?

화면

중앙에 ALU를 배치하고, 왼쪽에 서로 다른 값을 저장한 세 개의 레지스터 블록을 보여줘.

- R1 = 5
- R2 = 3
- R3 = 8

각 블록에서 ALU 방향으로 연결할 수 있는 경로를 희미하게 그려.

이때 어느 두 값을 ALU의 입력으로 선택할지 결정되지 않은 상태로 남겨둬.

마지막에는 상단에 다음 문구를 배치해.

`다음 계산에는 어떤 값을 사용할까?`

영상이 끝나기 직전, R1과 R3에서 ALU로 향하는 경로가 살짝 밝아지지만 실제 선택은 완료하지 않고 종료해.

다음 편인 \*\*「연산할 데이터는 어떻게 선택할까? — 레지스터와 데이터 경로」\*\*로 자연스럽게 연결되는 장면이야.

## Manim 구현에서 우선할 사항

이번 영상은 객체를 많이 만드는 것보다 같은 객체가 시간에 따라 어떻게 바뀌는지를 설계하는 것이 중요해.

구현은 크게 네 가지 재사용 객체로 나누는 걸 추천해.

- `ALUBlock`: 입력 A/B, ADD 연산, 출력 버스, 결과값 표시
- `SignalTimeline`: 시간축, 입력 변화, 출력 안정 구간, 저장 시점
- `DFlipFlopBlock`: D 입력, Q 출력, 클럭 입력, 내부 저장 상태
- `ClockWaveform`: 상승·하강 에지, 주기 변화, 샘플링 표시

특히 `SignalTimeline`은 15\~56초와 88\~105초에서 동일한 좌표와 표현 방식을 사용하면 좋아. 앞부분에서 이해한 계산 지연을 뒷부분에서 클럭 주기의 제한으로 다시 연결하는 효과가 생기기 때문이야.

최종적으로 가장 중요한 장면은 00:42–00:56과 01:28–01:45의 대응 관계야. 앞에서는 너무 이른 저장 때문에 잘못된 결과를 기억하는 상황을 보여주고, 뒤에서는 클럭을 지나치게 빠르게 설정해 같은 문제가 발생하는 상황을 보여주는 거지.

두 장면을 동일한 ALU, 동일한 시간축, 동일한 색상으로 표현하면 별도의 긴 설명 없이도 왜 클럭 주기에 물리적인 한계가 생기는지 이해할 수 있을 거야.
