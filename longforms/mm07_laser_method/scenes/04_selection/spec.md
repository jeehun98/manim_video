# 왜 계산을 버리는가?

## 목적과 주장
두 번째 A/B/C 예제는 사용하지 않는다. 얽힌 블록 묶음 → 유용한 블록도 소실 → 남은 행렬곱의 가치 → 왜 버리는가라는 질문.

## 앞 장면
일부를 버려 독립성을 얻는다

## TTS
실제 텐서 거듭제곱에서는 수많은 계산 블록이 서로 얽혀 있습니다.

어떤 변수를 제거하면 원하지 않는 블록뿐 아니라 유용한 블록까지 함께 사라질 수 있습니다.

따라서 중요한 것은 얼마나 많이 제거했는지가 아니라, 무엇을 남겼는지입니다.

그런데 왜 굳이 계산을 버리면서까지 독립적인 행렬곱을 얻으려는 걸까요?

사용자 제공 발화 길이: 20초. 전체 누적 62–82초. 음성 파일은 미제공.

## 화면과 전환
두 번째 A/B/C 예제는 사용하지 않는다. 얽힌 블록 묶음 → 유용한 블록도 소실 → 남은 행렬곱의 가치 → 왜 버리는가라는 질문.

narration_timing.json의 사용자 제공 종료 시각을 적용한다.

## 시작·종료와 다음 연결
시작: 일부를 버려 독립성을 얻는다
종료: 왜 계산을 버리는가?
다음: 확보한 비용 상한은 그대로 넘겨받는다

## 수학적 조건
복소수 위. 작은 세 항 예제는 행렬곱 알고리즘이 아닌 독립성 모형이며 Z는 출력 좌표다. 변수 제거는 관련 항 전체를 제거한다. 실제 잔여 구조가 정확한 행렬곱 직합인지 별도 확인한다. 보더 랭크는 극한 분해의 대수적 비용 지표이며 실행 시간이 아니다. q>=1, n>=2인 같은 크기의 정사각 행렬곱을 표시한다. 좋은 추출이나 상한 개선을 일반 텐서에서 보장하지 않는다.

## 적용한 발화 구간
- 62–67초: 실제 텐서 거듭제곱에서는 수많은 계산 블록이 서로 얽혀 있습니다.
- 67–73초: 어떤 변수를 제거하면 원하지 않는 블록뿐 아니라 유용한 블록까지 함께 사라질 수 있습니다.
- 73–77초: 따라서 중요한 것은 얼마나 많이 제거했는지가 아니라, 무엇을 남겼는지입니다.
- 77–82초: 그런데 왜 굳이 계산을 버리면서까지 독립적인 행렬곱을 얻으려는 걸까요?
