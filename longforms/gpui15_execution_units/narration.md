# GPU 개론15 — 계산 회로를 여러 개 만들면 더 빨라질까?

확정26문장·141초·음원미제공

0–6초
앞서 우리는 여러 명령어를 겹쳐 실행하면서, 필요한 데이터가 준비되지 않았을 때 발생하는 문제를 살펴봤습니다.

6–11초
그런데 서로의 계산 결과를 필요로 하지 않는 두 명령어라면 어떨까요?

11–17초
예를 들어 첫 번째 명령어는 두 숫자를 더하고, 두 번째 명령어는 다른 두 숫자를 뺀다고 생각해 보겠습니다.

17–24초
두 계산은 서로의 결과를 사용하지 않으므로, 어느 쪽이 먼저 끝나더라도 다른 계산에는 영향을 주지 않습니다.

24–28초
하지만 지금까지 만든 프로세서에는 ALU가 하나뿐입니다.

28–35초
따라서 두 명령어가 동시에 계산할 준비를 마쳤더라도, 하나의 ALU에서는 같은 순간에 두 연산을 수행할 수 없습니다.

35–38초
그렇다면 계산 회로를 하나 더 추가하면 어떨까요?

38–43초
우리는 앞서 덧셈과 뺄셈을 수행할 수 있는 ALU를 만들었습니다.

43–48초
이 회로를 하나 더 배치하면, 각각의 ALU가 서로 다른 명령어를 처리할 수 있습니다.

48–54초
첫 번째 ALU에서는 덧셈을 수행하고, 두 번째 ALU에서는 뺄셈을 수행하는 것입니다.

54–58초
그런데 ALU를 두 개 배치하는 것만으로는 충분하지 않습니다.

58–64초
각 ALU에는 자신이 계산할 숫자와 어떤 연산을 수행할지 나타내는 제어 정보가 전달되어야 합니다.

64–71초
따라서 레지스터 파일에서 읽은 값과 명령어의 제어 정보를 각 ALU에 전달할 수 있도록 입력 경로를 확장합니다.

71–78초
그리고 두 ALU가 만든 결과를 각각 보관하고, 올바른 목적지 레지스터에 기록할 수 있는 경로도 필요합니다.

78–83초
이제 서로 독립적인 두 명령어를 동시에 계산할 수 있는 구조가 만들어졌습니다.

83–89초
이처럼 하나의 프로세서 안에 여러 실행 회로를 배치한 구조를 다중 실행 유닛 구조라고 합니다.

89–93초
그렇다면 실행 회로를 두 개로 늘리면 계산 속도도 두 배가 될까요?

93–95초
반드시 그렇지는 않습니다.

95–100초
두 명령어가 같은 데이터에 의존한다면, 여전히 앞선 결과를 기다려야 할 수 있습니다.

100–107초
또한 두 명령어에 필요한 데이터를 동시에 읽거나, 계산 결과를 기록할 수 있는 하드웨어 자원도 충분해야 합니다.

107–114초
따라서 실행 회로를 추가하는 것뿐 아니라, 여러 회로가 동시에 동작할 수 있도록 데이터 경로와 제어 구조도 함께 확장해야 합니다.

114–123초
지금까지 우리는 하나의 명령어를 실행하는 회로에서 출발해, 여러 명령어를 겹쳐 처리하고, 서로 다른 계산을 동시에 수행하는 구조까지 만들었습니다.

123–126초
그런데 여기서 새로운 질문이 생깁니다.

126–130초
실행 회로가 여러 개라면, 어떤 명령어를 어느 회로에 전달해야 할까요?

130–136초
그리고 필요한 데이터가 준비되지 않은 명령어가 있다면, 다른 명령어를 먼저 실행하도록 선택할 수도 있을까요?

136–141초
다음에는 여러 실행 회로에 명령어를 배정하는 구조를 살펴보겠습니다.
