# GPU 개론 05 — 하나의 회로로 여러 연산을 수행하는 방법

총 175초(2분 55초) · 세로 9:16 · Manim / Codex 제작용 상세 영상 콘티

이번 영상의 핵심은 단순히 ALU라는 장치를 소개하는 것이 아니야.

새로운 연산이 필요할 때마다 회로를 추가하는 대신, 기존의 계산 구조를 재사용하고, 서로 다른 기능을 하나의 장치에 통합해 필요한 결과를 선택하는 과정을 시각적으로 보여주는 것이 중요해.

따라서 영상은 처음부터 ALU를 등장시키지 않고 다음 두 가지 설계 변화를 발견하는 과정으로 진행하는 게 좋아.

## 공통 시각 디자인

- 배경: 짙은 남색 `#0B1020`
- 입력 A: 파란색 `#60A5FA`
- 입력 B: 보라색 `#A78BFA`
- 선택 및 제어 신호: 주황색 `#F59E0B`
- 활성 결과: 초록색 `#34D399`
- 비활성 회로: 회색 `#64748B`
- 주요 텍스트: 흰색 `#F8FAFC`

기본 화면은 상단 15%에 핵심 개념, 중앙 65%에 회로 애니메이션, 하단 20%에 자막을 배치해.

한 번 등장한 ADDER 회로는 영상 마지막까지 동일한 객체로 유지하는 방식을 추천해. 가산기를 없앴다가 다시 등장시키면 회로를 재사용한다는 메시지가 약해지기 때문이야.

# 장면별 상세 콘티

## SCENE 01. 새로운 연산이 필요하면 새로운 회로를 만들어야 할까?

00:00–00:14

내레이션

> 앞서 우리는 논리 게이트를 연결해 실제 숫자의 덧셈을 구현하는 방법을 살펴봤습니다.
>
> 그렇다면 뺄셈이나 비교처럼 다른 연산이 필요할 때는 어떻게 해야 할까요?
>
> 가장 단순한 방법은 연산마다 새로운 회로를 만드는 것입니다.

화면 연출

00–05초: 이전 4편의 전가산기 네 개로 구성된 4비트 가산기가 화면 중앙에 등장한다. 각 전가산기의 내부에는 XOR, AND, OR 게이트가 희미하게 보인다.

가산기의 내부 구조가 축소되며 하나의 직사각형 블록으로 정리된다. 블록에는 `ADDER`라는 명칭을 표시한다.

05–10초: ADDER 블록이 화면 왼쪽으로 이동한다. 오른쪽에는 `SUBTRACT?`와 `COMPARE?`라는 빈 블록이 차례로 나타난다.

10–14초: 각각의 빈 블록에 독립적인 논리 게이트 회로들이 채워진다. 세 블록 모두 독립적인 배선과 입력선을 가지게 된다.

핵심 화면 문구: `One Operation → One Circuit?`

여기서는 아직 재사용 방법을 보여주지 않아. 각각 새로운 회로를 만들어야 한다는 초기 가정을 시각적으로 제시하는 단계야.

## SCENE 02. 회로를 계속 추가하면 발생하는 비용

00:14–00:23

내레이션

> 하지만 연산의 종류가 늘어날수록 더 많은 트랜지스터와 배선이 필요하게 됩니다.
>
> 그렇다면 이미 만들어 놓은 회로를 다른 연산에도 활용할 수는 없을까요?

화면 연출

14–19초: ADD, SUB, COMPARE 블록이 하나의 칩 영역 안에 배치되어 있다.

각 블록의 내부 게이트 수와 배선이 나타나며 칩 영역이 점차 넓어진다. 오른쪽에 면적 표시 막대 `AREA`를 추가하고 막대가 증가하도록 한다.

19–23초: 카메라가 ADDER 블록 하나에 초점을 맞춘다. 나머지 블록은 투명도를 낮춘다.

ADDER에만 밝은 테두리를 만들고 화면 중앙에 다음 문구를 표시한다.

`Reuse Existing Hardware`

기존 ADDER를 그대로 유지하면서 SUBTRACT 회로를 재구성할 가능성을 보여주는 전환이야.

## SCENE 03. 뺄셈을 덧셈으로 바꾸는 발상

00:23–00:41

내레이션

> 먼저 뺄셈을 생각해 보겠습니다.
>
> 우리는 두 숫자의 차이를 구할 때, 덧셈과는 다른 연산이라고 생각합니다.
>
> 그런데 이진수에서는 뺄셈을 덧셈의 형태로 바꿀 수 있습니다.
>
> 일정한 비트 수를 정하고, 빼려는 숫자의 각 비트를 반전한 다음 1을 더하는 것입니다.
>
> 이것을 2의 보수라고 합니다.

상세 화면 구성

23–25초: 중앙에 `A − B`라는 수식이 나타난다.

그 아래에 기존 ADDER 블록을 배치하고, 덧셈 기호와 뺄셈 기호가 서로 다른 색으로 표시되도록 한다.

25–30초: `A − B`에서 B를 강조한다. 수식이 `A + (−B)`로 변형된다.

30–33초: `−B`에 해당하는 값을 이진수의 비트 반전과 +1을 통해 표현할 수 있다는 것을 예고한다.

33–39초: 화면 중앙에 4개의 비트 상자를 가로로 나란히 배치한다. 각 상자에는 0 또는 1이 들어 있다.

각 비트가 `0 ↔ 1`로 반전되는 동작을 보여준다.

39–41초: 반전된 비트열 오른쪽에 `+1`이 추가된다. 상단에 `Two's Complement`라는 명칭이 처음 나타난다.

핵심 수식

\\[ A-B=A+\overline{B}+1\pmod{2^n} \\]

고정된 n비트 연산에서 성립하는 관계라는 점을 반영해야 해.

## SCENE 04. 실제 계산: 5−3을 덧셈으로 수행한다

00:41–00:57

내레이션

> 예를 들어 4비트에서 5에서 3을 빼보겠습니다.
>
> 5는 0101, 3은 0011입니다.
>
> 3의 비트를 반전하면 1100이고, 여기에 1을 더하면 1101이 됩니다.
>
> 이 값을 0101에 더하고 하위 4비트만 남기면 0010, 즉 2가 됩니다.

상세 화면 구성

41–44초: 화면 중앙에 `5 − 3`을 크게 표시하고, 바로 아래 두 숫자를 각각 네 개의 비트 상자로 변환한다.

A는 파란색, B는 보라색으로 표시한다.

44–47초: 두 숫자를 다음과 같이 배치한다.

4비트 계산을 위한 비트 배치

## 0

## 1

## 0

## 1

## 0

## 0

## 1

## 1

위쪽은 A=0101, 아래쪽은 B=0011.

47–51초: B의 각 비트를 차례로 뒤집는다.

`0011 → 1100`

이어서 작은 `+1`이 오른쪽에 추가되고 값이 `1101`로 바뀐다.

51–57초: 기존 ADDER 블록이 화면 아래에서 올라온다.

파란색 A=0101과 변환된 B=1101을 가산기에 입력한다.

결과는 전체 5비트 `10010`이 된다. 맨 앞의 자리올림 `1`을 표시하고, 하위 4비트 `0010`을 강조한다.

마지막에는 `0010₂ = 2`라는 결과를 보여준다.

중요한 연출: 맨 앞자리의 올림 비트를 버리는 이유를 단순한 애니메이션 삭제 효과로 처리하지 말고, 4비트 가산기의 결과 출력은 하위 4비트이며 바깥쪽 캐리는 별도 신호로 나온다는 구조를 보여줘.

## SCENE 05. 두 연산에 하나의 가산기를 재사용한다

00:57–01:09

내레이션

> 결국 별도의 뺄셈 회로 없이도 기존 덧셈 회로를 활용할 수 있는 것입니다.
>
> 더 나아가 입력 비트를 반전할지 결정하는 제어 신호를 추가하면, 하나의 가산기로 덧셈과 뺄셈을 모두 수행할 수 있습니다.

상세 화면 구성

57–61초: 기존 ADDER 블록을 화면 중앙에 고정한다.

왼쪽에서 A와 B 두 입력선이 들어오고, 오른쪽에는 결과가 출력된다.

61–65초: B의 입력선 위에 XOR 게이트 네 개를 추가한다. 각 XOR의 다른 입력에는 공통 제어 신호 `SUB`를 연결한다.

또한 동일한 SUB 신호를 ADDER의 최초 Carry-In에 연결한다.

65–69초: 제어 신호가 0과 1 사이에서 바뀐다.

ADD/SUB 공용 가산기 동작

SUB = 0 · 덧셈SUB = 1 · 뺄셈

B를 그대로 전달하고 Cin=0으로 설정한다.

여기서 화면의 XOR 하나는 개념도이고, 실제 구현에서는 B의 각 비트마다 XOR가 하나씩 필요하다는 점을 시각적으로 표시해.

가장 중요한 것은 ADDER 블록을 전혀 교체하지 않는 것이야.

ADD/SUB 제어선만 바뀌어도 동일한 가산기가 서로 다른 연산을 수행할 수 있게 되는 장면이지.

## SCENE 06. 비교 연산도 기존 회로를 활용할 수 있을까?

01:09–01:23

내레이션

> 그렇다면 비교 연산도 기존 회로를 활용할 수 있을까요?
>
> 두 숫자가 같은지 확인하려면, 두 숫자를 뺀 결과가 0인지 살펴보면 됩니다.
>
> 크기 비교 역시 뺄셈에서 발생하는 결과와 상태 신호를 활용해 구현할 수 있습니다.

상세 화면 구성

69–73초: 앞 장면의 ADD/SUB 가산기 구조를 유지한다. 제어 신호는 SUB=1로 설정한다.

가산기 오른쪽에 새로운 비교 결과 영역을 만든다. 이 영역은 아직 회색으로 표시하고 `COMPARE?`라는 이름을 붙인다.

73–78초: 입력 A와 B에 각각 `0101`을 넣는다. 가산기의 뺄셈 결과가 `0000`이 된다.

출력 비트 네 개가 모두 0이라는 것을 확인하는 작은 검출 회로를 추가한다.

결과가 모두 0이면 `ZERO = 1`이라고 표시한다.

78–83초: 입력 B를 `0110`으로 변경한다. 뺄셈 결과와 함께 비교에 필요한 상태 신호가 변경된다.

작은 회로 블록에 `ZERO`, `SIGN`, `OVERFLOW`, `CARRY`라는 라벨이 등장한다. 이 상태 신호를 활용해 비교 결과를 만들 수 있다는 사실을 보여준다.

비교 기능의 재사용 구조

ADD/SUB 공유 회로

A − B

결과 비트 + 상태 플래그

A = B

A < B

A > B

정확성 지침

크기 비교를 모두 단순히 뺄셈 결과의 부호 비트만으로 처리하는 것으로 그리면 안 돼.

부호 있는 정수 비교에서는 오버플로 여부도 중요하고, 부호 없는 비교에서는 캐리 또는 빌림 관련 정보를 활용할 수 있어. 실제 회로는 비교 결과를 만드는 추가 논리도 필요해.

따라서 이 장면에서는 뺄셈 회로를 재사용하되, 비교 결과를 판단하는 논리는 별도로 존재한다는 점을 드러내야 해.

## SCENE 07. 새로운 연산이 반드시 새로운 계산 회로를 의미하지는 않는다

01:23–01:33

내레이션

> 이처럼 새로운 연산이 필요하다고 해서 언제나 완전히 독립적인 계산 회로를 추가할 필요는 없습니다.
>
> 이미 구현한 연산을 다른 방식으로 활용할 수 있는 것입니다.

상세 화면 구성

83–89초: 영상 초반에 등장했던 독립적인 `ADD`, `SUB`, `COMPARE` 회로 세 개를 화면 왼쪽에 배치한다.

오른쪽에는 기존의 하나뿐인 ADDER와 작은 입력 변환 및 비교 회로를 배치한다.

이때 왼쪽의 세 독립 회로를 반투명하게 표시하고 오른쪽의 공용 가산기를 강조한다.

89–93초: 오른쪽 구성에서 하나의 ADDER로부터 ADD, SUB, COMPARE라는 세 개의 기능 라벨이 분기되어 나타난다.

화면 문구

`Reuse Instead of Duplication`

이 장면에서는 출력 기능의 수가 늘어났지만 중심이 되는 산술 계산 회로는 공유된다는 점을 강조해.

회로의 실제 면적 절감량은 구현에 따라 다르므로 구체적인 비율은 표시하지 않아야 해.

## SCENE 08. 모든 연산을 가산기로 처리할 수 있을까?

01:33–01:41

내레이션

> 하지만 모든 연산을 하나의 덧셈 회로로 처리할 수 있는 것은 아닙니다.
>
> AND나 OR 같은 논리 연산에는 다른 논리 구조를 사용할 수 있습니다.

상세 화면 구성

93–97초: 화면 중앙에 ADD/SUB 공유 회로가 나타나 있고, 오른쪽에 여러 연산 이름이 순서대로 추가된다.

`ADD`, `SUB`, `COMPARE`, `AND`, `OR`

ADD, SUB, COMPARE는 이미 만들어진 가산기 기반의 계산 경로에 연결한다.

97–101초: AND와 OR는 기존 가산기에 억지로 연결하지 않고, 별도의 작은 논리 회로 블록으로 배치한다.

해당 블록 내부에 AND와 OR 게이트 기호를 각각 그린다.

시각적으로 두 영역을 나누어 표시한다.

`SHARED ARITHMETIC`

`LOGIC FUNCTIONS`

중요한 메시지: 모든 기능을 같은 회로로 구현해야 한다는 이야기가 아니야. 공유할 수 있는 계산 구조를 공유하고, 다른 기능이 필요하면 그에 적합한 논리 구조를 함께 사용하는 것이 핵심이야.

## SCENE 09. 여러 연산 기능을 하나의 장치에 통합한다

01:41–01:51

내레이션

> 그렇다면 이런 여러 연산 기능을 하나의 장치 안에 모아두면 어떨까요?
>
> 덧셈과 뺄셈을 수행하는 회로, 논리 연산을 수행하는 회로를 미리 구성하는 것입니다.

상세 화면 구성

101–106초: 화면 중앙에 큰 빈 직사각형 테두리를 만든다.

왼쪽에 ADD/SUB 회로와 AND/OR 회로를 배치한다.

106–111초: 두 회로가 큰 테두리 안으로 들어간다.

두 회로는 서로 다른 기능을 가지고 있지만 입력 A와 B를 공유한다.

큰 테두리 왼쪽에는 A와 B 입력선이 각각 하나씩 존재하고, 내부에서 각 연산 회로로 분기된다.

이 장면의 핵심 연출

외부에서 보면 입력이 두 개뿐인 하나의 장치지만, 내부를 확대하면 여러 논리 계산 경로가 동시에 존재하는 모습이야.

이후 큰 테두리는 계속 유지하고, 내부에 결과 선택 회로를 추가하자.

## SCENE 10. 여러 결과 중 하나만 선택한다

01:51–02:00

내레이션

> 그리고 어떤 연산의 결과를 사용할지 선택하는 회로를 추가합니다.
>
> 이때 여러 입력 중 하나를 선택해 출력하는 회로를 멀티플렉서, 줄여서 MUX라고 합니다.

상세 화면 구성

111–115초: 두 연산 블록에서 각각 결과선이 오른쪽으로 뻗는다.

그러나 최종 출력은 하나뿐이므로, 두 결과선을 곧바로 합치지 않고 작은 선택 장치에 연결한다.

115–120초: 두 결과선이 연결되는 위치에 사다리꼴 모양의 MUX가 생성된다.

MUX 아래쪽에는 작은 주황색 선택 신호선을 추가한다.

이 선택 신호에 따라 MUX 내부의 강조된 경로가 위쪽 또는 아래쪽으로 변경된다.

화면 문구

`MULTIPLEXER (MUX)`

결과 신호 두 개를 직접 전기적으로 합치는 모습으로 그리지 않아야 해. MUX는 입력 중 선택된 값을 출력하도록 구현된 별도의 논리 회로야.

## SCENE 11. 제어 신호로 서로 다른 결과를 선택한다

02:00–02:09

내레이션

> 예를 들어 제어 신호가 00이면 덧셈, 01이면 뺄셈, 10이면 AND, 11이면 OR의 결과를 선택하도록 설계할 수 있습니다.

상세 화면 구성

120–123초: 중앙에 네 개의 기능을 세로로 배치한다.

`ADD`, `SUB`, `AND`, `OR`

각 기능은 이미 존재하는 공유 회로 또는 논리 회로에 대응된다.

123–129초: 왼쪽의 A와 B 입력은 고정한다.

제어 신호 `00 → 01 → 10 → 11`을 바꾸면서 해당 연산 결과가 MUX를 통해 하나의 출력선으로 전달되는 모습을 보여준다.

이때 다음 예시를 사용하면 모든 결과가 명확해져.

4비트 입력 A=0101(5), B=0011(3)

| 제어   | 연산  | 출력         |
| ---- | --- | ---------- |
| `00` | ADD | `1000` (8) |
| `01` | SUB | `0010` (2) |
| `10` | AND | `0001`     |
| `11` | OR  | `0111`     |

위 코드는 영상 설명을 위해 임의로 정의한 연산 선택 코드다.

핵심 연출: 입력 A와 B, 회로의 배선 구조는 그대로 유지하고 주황색 제어 신호만 변경해야 해.

그에 따라 최종 출력이 `1000 → 0010 → 0001 → 0111`로 바뀌는 모습이 가장 중요해.

## SCENE 12. 이 통합된 장치가 ALU다

02:09–02:15

내레이션

> 이러한 산술 연산과 논리 연산을 수행하는 장치를 ALU, 산술논리장치라고 합니다.

상세 화면 구성

129–132초: 여러 연산 경로와 MUX를 포함한 커다란 테두리가 밝아진다.

132–135초: 내부 회로가 조금씩 단순화되어 외부에서는 하나의 블록으로 보이게 된다.

중앙에 `ALU`라는 명칭을 크게 표시하고, 아래쪽에 작은 글씨로 `Arithmetic Logic Unit`을 표시한다.

이때 블록을 완전히 닫기 전에 내부에 ADD/SUB, AND/OR, MUX가 존재한다는 모습을 1초 정도 유지해.

## SCENE 13. 제어 신호가 바뀌어도 회로의 배선은 그대로다

02:15–02:28

내레이션

> 여기서 중요한 것은 제어 신호가 바뀐다고 트랜지스터의 물리적인 연결이 바뀌는 것은 아니라는 점입니다.
>
> 연산에 필요한 회로들은 미리 설계되어 있고, 입력 신호에 따라 그 회로들의 동작이나 결과 선택이 달라지는 것입니다.

상세 화면 구성

135–141초: ALU 블록을 다시 확대해 내부 회로를 보여준다.

각 게이트와 배선의 위치를 고정하고 선택 신호만 변경한다.

선택에 따라 활성화되는 신호 경로가 달라지지만, 게이트의 위치와 배선은 전혀 움직이지 않는다.

141–148초: 화면을 두 개의 레이어로 나누어 보여준다.

첫 번째 레이어는 변경되지 않는 물리적 배선이고, 두 번째 레이어는 시시각각 변하는 신호값이다.

구조와 상태의 차이

고정되는 것

트랜지스터, 논리 게이트, 배선 연결

변경되는 것

입력 비트, 제어 신호, 내부 신호, 출력값

추천 화면 문구

`Fixed Hardware, Variable Control`

이 구간은 이번 영상에서 가장 중요한 장면 중 하나야.

제어가 곧 물리적인 재배선을 의미하지 않는다는 차이를 보여줘야 하거든.

## SCENE 14. 회로를 재사용하고 통합하는 설계

02:28–02:36

내레이션

> 이렇게 하면 매번 새로운 계산 장치를 만드는 대신, 기존의 회로를 재사용하고 여러 연산 기능을 하나의 장치에서 활용할 수 있습니다.

상세 화면 구성

148–152초: 앞에서 만든 ADD/SUB 공용 가산기, 비교 판단 회로, AND/OR 회로가 한 화면에 정리된다.

152–156초: 공통 입력 A와 B가 분기되고, 각 기능의 필요한 결과가 MUX를 통해 출력되는 전체 구조를 보여준다.

화면 중앙의 ALU 테두리를 강조한다.

화면 문구

`Hardware Reuse + Functional Integration`

복잡한 논리 회로들이 하나의 연산 장치 안에 정돈되어 있다는 모습을 보여주면 돼.

## SCENE 15. 물리적으로 지원하는 기능에는 한계가 있다

02:36–02:41

내레이션

> 물론 지원할 수 있는 연산과 성능은 실제로 구현된 회로 구조에 따라 제한됩니다.

상세 화면 구성

156–161초: ALU 주변에 여러 연산 명칭이 나타난다.

ADD, SUB, AND, OR는 이미 설계된 기능이므로 정상적으로 연결된다.

별도로 구현하지 않은 연산인 `DIV`를 등장시키고, 해당 연산을 선택하려는 신호가 지원되지 않는다는 모습을 나타낸다.

다만 영상에 표시하는 메시지는 `DIVISION IMPOSSIBLE`이 아니라 `NOT IMPLEMENTED IN THIS ALU`로 만들어야 해.

나눗셈 자체가 불가능한 것이 아니라, 현재 예시 ALU에 직접 구현되어 있지 않다는 의미이기 때문이야.

## SCENE 16. 회로를 무작정 추가하지 않는 이유

02:41–02:55

내레이션

> 결국 컴퓨터의 연산 장치를 설계한다는 것은 가능한 모든 회로를 무작정 추가하는 일이 아닙니다.
>
> 어떤 연산을 공통된 회로로 처리하고, 어떤 기능을 별도로 구현하며, 그중 필요한 결과를 어떻게 선택할지 결정하는 과정입니다.

상세 화면 구성

161–167초: 왼쪽에는 각각 독립된 ADD, SUB, COMPARE, AND, OR 회로를 단순 나열한 초기 설계를 나타낸다.

오른쪽에는 공유 가산기와 별도 논리 회로를 MUX로 통합한 ALU 구조를 보여준다.

167–171초: 오른쪽에서 공통 계산 경로를 초록색으로 강조한다.

171–175초: 전체 회로를 간소화한 후 세 가지 핵심 동작을 순서대로 표시한다.

`REUSE → INTEGRATE → SELECT`

마지막 2초는 ALU 블록과 세 단어를 유지하는 것으로 마무리한다.

이후 영상에서는 여기서 만들어진 ALU를 누가 제어하는지, 연산에 사용할 데이터는 어디에 보관하는지 설명하는 단계로 넘어가면 좋아.

## 영상 제작 시 특히 주의할 기술적 정확성

이 영상에서는 다음 네 가지 사항을 반드시 유지하는 게 좋아.

1. 2의 보수 연산은 고정 비트 폭에서 설명한다. 5−3 계산에서 최상위 자리올림을 버린 하위 4비트가 결과임을 명확하게 보여줘.
2. ADD/SUB 공유 가산기에서 제어 신호는 B 비트마다 연결된 XOR와 초기 Carry-In 모두에 전달한다. 비트 반전만 수행하고 +1을 빠뜨리면 뺄셈이 잘못돼.
3. 비교에는 추가 상태 판단 논리가 필요하다. 뺄셈 회로를 재사용한다는 점과 비교를 아무 추가 회로 없이 수행한다는 주장은 달라.
4. MUX로 기능을 선택한다고 배선이 바뀌는 것은 아니다. 내부 회로 일부는 동시에 신호가 변할 수도 있지만, 외부로 전달할 결과가 선택되는 거야.

## Codex에 전달할 제작용 공통 프롬프트

# GPU 개론 05 — Manim 제작 지침

175초 분량의 1080×1920, 세로 9:16 과학 교육 애니메이션을 제작한다.

**영상의 핵심 목표**

새로운 연산이 필요할 때마다 완전히 독립된 계산 회로를 만드는 대신, 이미 존재하는 회로를 재사용하고 여러 연산 기능을 통합해 필요한 결과를 선택하는 하드웨어 설계 원리를 설명한다.

## 핵심 연출 흐름

1. 이전 영상에서 구현한 4비트 ADDER를 등장시킨다.
2. SUBTRACT, COMPARE 같은 연산을 각각 독립된 회로로 추가하는 가상 설계를 보여준다.
3. 새로운 회로가 늘어나면 트랜지스터와 배선, 면적 등의 비용이 증가할 수 있음을 보여준다.
4. 기존 ADDER를 재사용하는 방안을 탐색한다.
5. 4비트 예시 5−3을 이용해 2의 보수를 설명한다.
6. 3의 비트 표현 0011을 반전해 1100을 만들고, 1을 더해 1101로 변환한다.
7. 0101 + 1101 = 10010을 계산하고, 4비트 결과 0010을 강조한다.
8. 기존 ADDER의 B 입력선에 XOR 게이트를 추가하고 동일한 SUB 제어 신호를 초기 Carry-In에 연결한다.
9. 제어 신호 SUB=0이면 A+B, SUB=1이면 A+\~B+1을 수행하도록 한다.
10. 기존 뺄셈 회로의 결과와 상태 플래그를 활용해 동등 비교와 크기 비교의 원리를 보여준다.
11. AND와 OR 연산을 위한 별도 논리 회로를 추가한다.
12. 공용 산술 회로와 논리 연산 회로를 하나의 장치 내부에 배치한다.
13. MUX를 추가하고 제어 신호로 어떤 결과를 외부 출력으로 전달할지 선택한다.
14. A=0101, B=0011을 고정한 상태에서 선택 신호를 00, 01, 10, 11로 변화시키며 ADD, SUB, AND, OR 결과를 표시한다.
15. 전체 통합 장치에 ALU(Arithmetic Logic Unit)라는 이름을 붙인다.
16. 선택 신호가 달라져도 트랜지스터의 실제 배선은 바뀌지 않음을 강조한다.
17. 물리적으로 구현되지 않은 기능은 현재 ALU에서 직접 지원되지 않는다는 점을 보여준다.
18. 마지막에는 REUSE, INTEGRATE, SELECT를 강조하며 종료한다.

## 애니메이션 원칙

모든 회로는 2D 벡터 도형으로 구현한다.

짙은 남색 배경과 파란색 입력 A, 보라색 입력 B, 주황색 제어 신호, 초록색 활성 결과를 사용한다.

이전 장면에 등장한 ADDER를 삭제하고 새로운 ADDER로 교체하는 연출을 피한다. 재사용의 의미를 전달하기 위해 동일한 회로 객체를 유지한다.

회로가 추가되면 배선이 연결되는 과정이 보이게 한다. 기존 회로를 활용하는 경우에는 입력 변환 또는 출력 선택만 변경되도록 한다.

MUX는 단순히 여러 출력을 하나로 전기적으로 합치는 장치가 아니라, 제어 신호에 따라 선택된 입력을 출력하는 논리 회로로 구현한다.

계산 결과는 모두 정확하게 검증한다. 특히 5−3의 4비트 연산과 ADD, SUB, AND, OR의 네 가지 출력값을 정확히 표시한다.

명령어 또는 소프트웨어가 회로의 물리적 배선을 직접 변경하는 모습으로 묘사하지 않는다.

모든 장면은 제공된 175초 내레이션 타임코드와 일치하도록 동기화한다.

이번 편은 57\~69초의 공용 가산기 장면과 120\~148초의 MUX·ALU 장면이 가장 중요해.

앞부분은 하나의 계산 회로를 여러 연산에 재사용한다는 사실을, 뒷부분은 여러 계산 기능을 하나의 장치에 통합하되 제어 신호로 필요한 결과를 선택한다는 사실을 보여주거든.

이 두 장면이 명확하다면 ALU가 단순히 여러 연산을 하는 블랙박스가 아니라, 물리적으로 미리 설계된 회로를 효율적으로 구성하고 사용하는 장치라는 점을 전달할 수 있어.
