# 12 · 계산할 수 있는 데이터의 범위가 넓어진다

목적: 기존 프로세서의 계산 경로를 유지하며 외부 데이터의 왕복 경로를 완성한다.

시작: 읽기 → 더하기 → 다시 저장

확정 길이: 143–153초(10초). 사용자 제공 발화시간을 변경하지 않는다.

## 원문 및 주요 화면 변화 시각
- 143–148초: 기존에는 계산할 숫자가 레지스터에 미리 저장되어 있어야 했습니다.
- 148–153초: 하지만 이제는 별도의 메모리에서 데이터를 가져오고, 계산한 뒤 다시 저장할 수 있게 된 것입니다.

## 화면·연결
상세 콘티 ../../storyboard_reference.md, 구현 ../../scene_engine.py의expanded. 기존 회로를 유지하고 중반에는 확대된 데이터 경로와 쓰기 MUX를 중심에 둔다. 가로1920×1080/세로1080×1920 별도배치·30fps. 주소·제어주황,레지스터초록,ALU파랑,데이터메모리보라. 주소100과데이터5는색·역할이구분된다. 도식과단일자막전용영역을분리한다. 종료: 기존 프로세서의 계산 경로를 유지하며 외부 데이터의 왕복 경로를 완성한다.

## 기술 조건
LOAD R1,[100]·LOAD R2,[101]·ADD R3,R1,R2·STORE R3,[102]는교육용사람표기다. 기존8비트인코딩을부여하지않는다. 주소경로는100/101/102를표현할폭을가정하며데이터예시와별개다. 이편에서는주소계산회로를추가설명하지않고주소지정을추상화한다. 읽기는메모리를변경하지않는다. 주소만바꿔도쓰기되지않는다. Load는응답유효·목적지·RegWE·갱신에지가갖춰졌을때레지스터를갱신한다. Store는레지스터에서WD입력으로전달하며MemWE와유효갱신시점에서주소102만바꾼다.RegWE=0으로일반레지스터쓰기없음. ALU와메모리출력은MUX의서로다른입력이다. MUX선택은즉시저장이나목적지선택과다르다. 두LOAD는동시에수행하지않는다. ADD피연산자5/3은결과R3과달라피드백오해가없다. 지연은특정사이클수·나노초로단정하지않고Ready=0중에는미완성데이터를기록하지않는다. PC·명령어메모리와DataMemory는역할구분용이며반드시물리적으로분리된다는뜻이아니다. 사용자원문도입·마지막문장은유지하되추가GPU12예고제목·엔드카드는넣지않는다.
