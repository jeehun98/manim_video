# 07 · 쓰기 입력에 MUX를 추가한다

목적: 데이터 출처 선택과 목적지·RegWE·저장에지는 별도다.

시작: 레지스터로 돌아오는 두 결과

확정 길이: 80–93초(13초). 사용자 제공 발화시간을 변경하지 않는다.

## 원문 및 주요 화면 변화 시각
- 80–84초: 그리고 두 경로 중 하나를 선택해 레지스터에 기록하도록 만드는 것입니다.
- 84–88초: 여기서 앞서 살펴본 MUX를 다시 사용할 수 있습니다.
- 88–93초: 이제 레지스터에는 ALU의 결과뿐 아니라 메모리에서 가져온 값도 저장할 수 있게 되었습니다.

## 화면·연결
상세 콘티 ../../storyboard_reference.md, 구현 ../../scene_engine.py의writeback. 기존 회로를 유지하고 중반에는 확대된 데이터 경로와 쓰기 MUX를 중심에 둔다. 가로1920×1080/세로1080×1920 별도배치·30fps. 주소·제어주황,레지스터초록,ALU파랑,데이터메모리보라. 주소100과데이터5는색·역할이구분된다. 도식과단일자막전용영역을분리한다. 종료: 데이터 출처 선택과 목적지·RegWE·저장에지는 별도다.

## 기술 조건
LOAD R1,[100]·LOAD R2,[101]·ADD R3,R1,R2·STORE R3,[102]는교육용사람표기다. 기존8비트인코딩을부여하지않는다. 주소경로는100/101/102를표현할폭을가정하며데이터예시와별개다. 이편에서는주소계산회로를추가설명하지않고주소지정을추상화한다. 읽기는메모리를변경하지않는다. 주소만바꿔도쓰기되지않는다. Load는응답유효·목적지·RegWE·갱신에지가갖춰졌을때레지스터를갱신한다. Store는레지스터에서WD입력으로전달하며MemWE와유효갱신시점에서주소102만바꾼다.RegWE=0으로일반레지스터쓰기없음. ALU와메모리출력은MUX의서로다른입력이다. MUX선택은즉시저장이나목적지선택과다르다. 두LOAD는동시에수행하지않는다. ADD피연산자5/3은결과R3과달라피드백오해가없다. 지연은특정사이클수·나노초로단정하지않고Ready=0중에는미완성데이터를기록하지않는다. PC·명령어메모리와DataMemory는역할구분용이며반드시물리적으로분리된다는뜻이아니다. 사용자원문도입·마지막문장은유지하되추가GPU12예고제목·엔드카드는넣지않는다.
