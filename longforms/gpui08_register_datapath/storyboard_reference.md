# GPU 개론 08 — 저장된 값은 어떻게 다시 계산에 사용될까?

상세 영상화 콘티 · 총 153초 · 9:16 세로 영상 · Manim 기반 2D 애니메이션

이번 영상의 시각적 핵심은 이전에 만들었던 회로들이 하나의 계산 시스템으로 연결되는 과정이야.

6편에서는 1비트를 기억하는 회로를, 7편에서는 저장 시점을 제어하는 방법을 살펴봤지. 8편에서는 그 저장 회로들을 여러 개로 묶어 레지스터를 만들고, 저장한 값을 MUX를 통해 다시 ALU의 입력으로 전달하는 구조를 완성해.

가장 중요한 것은 기술 용어를 먼저 보여주지 않는 것이야.

1비트를 기억한다 → 여러 비트를 하나의 숫자로 저장한다 → 저장한 값을 다시 계산에 사용한다 → 여러 저장 장소 중 필요한 것을 선택한다.

이 순서대로 회로를 직접 확장하는 모습을 보여주면 자연스러워.

# ACT 1. 하나의 비트에서 여러 비트로

00:00–00:45 · 저장 회로 하나가 여러 비트의 값을 보관하는 레지스터로 발전하는 과정

### 00:00–00:06 — 앞선 영상의 저장 회로

나레이션: 앞서 우리는 논리 게이트로 값을 기억하는 회로를 만들고, 클럭을 이용해 저장 시점을 제어하는 방법을 살펴봤습니다.

화면 연출

화면 중앙에 6편의 SR 래치 회로가 나타나.

두 NOR 게이트 사이의 교차 연결이 주황색으로 강조되고, 오른쪽 출력 Q에는 `1`이 표시돼.

이후 회로 내부가 간소화되면서 7편에서 소개한 D 플립플롭 블록으로 전환돼.

플립플롭은 다음 세 요소만 남겨.

- 왼쪽: 데이터 입력 D
- 아래: 클럭 입력 CLK
- 오른쪽: 저장된 출력 Q

하단 클럭 파형에서 상승 에지가 발생하면 Q가 0에서 1로 바뀌는 모습을 짧게 보여줘.

### 00:06–00:11 — 저장값을 실제 계산에 사용한다면?

나레이션: 그렇다면 저장한 값을 실제 계산에 다시 사용하려면 어떻게 해야 할까요?

화면 연출

저장 회로를 화면 왼쪽에 배치하고, 오른쪽에 ALU를 등장시켜.

저장 회로의 Q 출력에서 ALU 입력 쪽으로 파란색 점선이 뻗어나가.

아직 두 회로를 완전히 연결하지 않고, ALU 입력에 `?`를 표시해.

상단 질문:

`저장한 값을 다시 계산하려면?`

이 장면에서는 데이터 재사용 가능성만 암시하고, 구체적인 연결은 후반부로 미뤄.

### 00:11–00:14 — 다시 하나의 저장 회로

나레이션: 먼저 우리가 만들었던 저장 회로를 생각해 보겠습니다.

화면 연출

ALU는 자연스럽게 사라지고 저장 회로 하나만 중앙에 확대돼.

블록의 Q 출력에 `1`을 표시해.

클럭 입력에는 짧은 펄스가 나타났다가 사라지고, Q 출력은 그대로 유지돼.

저장 회로의 기능을 다시 확인하는 3초야.

### 00:14–00:18 — 하나의 비트만 저장할 수 있다

나레이션: 하나의 저장 회로는 0 또는 1, 즉 하나의 비트를 기억할 수 있습니다.

화면 연출

화면 중앙에 플립플롭 블록 하나를 표시해.

출력 Q=0으로 시작하고, 클럭 상승 에지 이후 Q=1로 바뀌어.

블록 아래에는 `1 bit`라는 문구를 표시해.

숫자 0과 1이 동시에 저장되는 것처럼 보이지 않게, 한 시점에는 둘 중 하나의 상태만 유지한다는 점을 표현해.

### 00:18–00:24 — ALU는 여러 비트의 숫자를 다룬다

나레이션: 그런데 ALU가 계산하는 숫자는 하나의 비트로 표현되지 않을 수도 있습니다.

화면 연출

왼쪽에 1비트 저장 회로 하나, 오른쪽에 이전 편에서 사용했던 ALU 블록을 배치해.

ALU 입력에는 숫자 `5`와 `3`, 출력에는 `8`을 보여줘.

이후 숫자들이 이진수로 바뀌어.

### 00:24–00:27 — 5를 이진수로 표현

나레이션: 예를 들어 숫자 5를 이진수로 나타내면 0101입니다.

화면 연출

화면 중앙에 `5`가 크게 나타나고, 그 아래에 `0101₂`가 나타나.

이후 0101의 네 자리 숫자를 각각 독립된 네 개의 칸으로 분리해.

각 칸을 왼쪽부터 0, 1, 0, 1로 채워.

상단에는 `숫자 5 = 0101₂`를 유지해.

### 00:27–00:31 — 네 개의 비트가 필요하다

나레이션: 이 값을 저장하려면 네 개의 비트를 각각 기억해야 합니다.

화면 연출

0101을 구성하는 네 칸 아래에 각각 비어 있는 저장 회로를 배치해.

위쪽 숫자 비트와 아래쪽 저장 회로를 수직 연결해.

각 저장 회로는 하나의 비트만 담당하도록 구성해.

왼쪽부터 `D₃`, `D₂`, `D₁`, `D₀`라는 입력 표기를 사용해도 좋아. 다만 초반에 불필요한 기술 용어가 늘어나지 않도록, 화면에는 우선 네 개의 숫자만 크게 보여주는 걸 추천해.

### 00:31–00:35 — 저장 회로 네 개로 확장

나레이션: 그렇다면 하나의 비트를 저장하는 회로 네 개를 나란히 배치하면 어떨까요?

화면 연출

기존 저장 회로 하나가 옆으로 이동하면서 총 네 개의 독립된 저장 회로가 나란히 배치돼.

이때 단순히 하나가 복제되는 연출보다, 하나씩 새롭게 추가되는 느낌이 좋아.

### 00:35–00:41 — 하나의 숫자로 함께 저장

나레이션: 각 회로가 하나의 비트를 담당하고, 공통된 클럭을 이용해 값을 갱신하도록 만드는 것입니다.

화면 연출

네 개의 저장 회로 아래에 하나의 주황색 클럭선을 연결해.

클럭선은 각 회로의 CLK 입력으로 분기돼.

그다음 네 입력 D에 0, 1, 0, 1을 각각 제공하고 클럭 상승 에지를 발생시켜.

네 회로가 각자의 비트를 저장하면서 오른쪽 출력에 `0101`이 만들어져.

기술적 주의: 공통 클럭은 네 회로에 같은 비트를 저장하게 하는 것이 아니라, 각각의 입력을 같은 클럭 기준으로 받아들이도록 만드는 거야.

### 00:41–00:45 — 레지스터라는 개념의 등장

나레이션: 이렇게 여러 비트를 하나의 값으로 묶어 저장하는 회로를 레지스터라고 합니다.

화면 연출

네 개의 저장 회로 바깥에 하나의 직사각형 테두리가 그려져.

중앙 하단에 `Register`라는 명칭이 등장하고, 그 아래에 `4-bit`를 표시해.

네 개의 출력값 `0101`이 하나의 숫자 `5`로 표시되면서 저장 구조의 의미를 확인시켜 줘.

여기서는 네 개의 플립플롭을 하나의 기능 단위로 묶는 것이지, 네 비트가 하나의 플립플롭으로 합쳐지는 것은 아니야.

# ACT 2. 계산 결과를 저장하고 다시 사용한다

00:45–01:17 · 레지스터가 중간 계산 결과를 보관하는 과정을 실제로 보여준다.

### 00:45–00:50 — 숫자 8을 저장한다

나레이션: 이제 우리는 계산 결과인 숫자 8도 레지스터에 보관할 수 있습니다.

화면 연출

앞 장면의 4비트 레지스터를 그대로 유지해.

입력값을 `1000₂`로 변경하고, 클럭 상승 에지가 발생하는 순간 레지스터 출력이 `0101`에서 `1000`으로 바뀌어.

레지스터 오른쪽에 `8`이라는 십진수 값도 함께 표시해.

이 장면에서 이전 데이터가 새로운 데이터로 갱신되는 모습을 한 번 확실하게 보여주는 것이 중요해.

### 00:50–00:52 — 새로운 문제

나레이션: 그런데 여기서 새로운 문제가 생깁니다.

화면 연출

레지스터에 저장된 `8`은 그대로 유지해.

레지스터의 오른쪽 출력선만 밝게 강조해.

화면 상단에는 `저장한 값을 어디로 보낼까?`가 나타나.

### 00:52–01:00 — 레지스터에서 ALU로

나레이션: 앞서 살펴본 것처럼 하나의 ALU로 여러 단계의 계산을 수행하려면, 저장된 값을 다시 ALU의 입력으로 가져와야 합니다.

화면 연출

레지스터를 왼쪽에, ALU를 오른쪽에 배치해.

레지스터의 출력 `1000₂`에서 ALU 입력 A까지 파란색 데이터 버스를 연결해.

이때 아직 연산을 수행하지 않고, 저장값이 ALU 입력에 도달하는 경로만 보여줘.

하단에는 다음 문구를 표시해.

`저장된 결과 → 다음 계산의 입력`

이 장면에서는 레지스터 출력이 임의로 이동한다는 표현보다, 미리 연결된 데이터 경로를 통해 출력값이 전달된다는 느낌으로 표현해.

### 01:00–01:05 — 연속 계산 예시

나레이션: 예를 들어 5와 3을 더한 다음, 그 결과에 다시 2를 더한다고 생각해 보겠습니다.

화면 연출

기존 회로를 잠시 축소하고 중앙에 수식을 크게 표시해.

\\[ (5+3)+2=10 \\]

첫 번째 계산인 `5+3`을 파란색으로, 두 번째 계산인 `8+2`를 초록색으로 강조해.

수식 아래에는 `1차 계산`, `2차 계산`이라는 작은 구분을 넣어.

### 01:05–01:09 — 첫 계산 수행

나레이션: 먼저 ALU가 5와 3을 계산하면 결과인 8이 나옵니다.

화면 연출

ALU를 중앙에 크게 배치하고 두 입력 5와 3을 연결해.

ALU 내부에서 ADD 경로가 활성화되며 출력에 8이 나타나.

출력선에는 `1000₂`를 작게 병기해.

중요한 것은 나중에 이 결과를 저장하기 때문에, ALU 출력선이 오른쪽 레지스터 입력 D와 연결될 예정임을 미리 보여주는 거야.

### 01:09–01:12 — 계산 결과 저장

나레이션: 이 값을 레지스터에 저장합니다.

화면 연출

ALU 출력에서 레지스터 D 입력으로 `1000`이 전달돼.

하단 클럭선에서 상승 에지가 발생하면 레지스터의 Q 출력이 `1000`으로 갱신돼.

이후 ALU의 입력 숫자 5와 3을 흐리게 처리하고, 레지스터에 저장된 8만 선명하게 유지해.

### 01:12–01:17 — 두 번째 계산의 입력 변경

나레이션: 이제 두 번째 계산에서는 처음 입력했던 5 대신, 레지스터에 저장된 8을 사용해야 합니다.

화면 연출

ALU 입력 A에 연결되어 있던 숫자 5를 흐리게 처리해.

그다음 레지스터 출력 Q=8에서 ALU 입력 A로 이어지는 별도 경로를 강조해.

두 번째 입력 B는 3에서 2로 변경돼.

화면에는 다음 두 계산을 연속적으로 보여줘.

첫 번째 계산

# 5 + 3

\= 8

두 번째 계산

# 8 + 2

\= 10

이때 실제 구현에서는 새로운 입력을 선택하는 방법이 아직 설명되지 않았으므로, 다음 장면에서 그 문제를 해결하도록 ALU 입력 A의 두 후보 경로를 동시에 보여준 상태로 끝내.

# ACT 3. 여러 입력 중 하나를 선택하는 방법

01:17–01:42 · MUX를 재사용해 ALU의 입력 경로를 선택한다.

### 01:17–01:21 — 어떤 값을 ALU에 연결할까?

나레이션: 그렇다면 ALU의 입력에 연결할 값을 어떻게 바꿀 수 있을까요?

화면 연출

화면 중앙에 ALU를 배치하고 왼쪽에 두 개의 입력 후보를 보여줘.

- 위쪽: 처음 사용하는 숫자 `5`
- 아래쪽: 레지스터에 저장된 숫자 `8`

각 입력에서 ALU의 A 입력 방향으로 두 배선이 뻗어 있지만, 실제 연결 지점 앞에서 멈춰 있어.

ALU의 B 입력에는 숫자 `2`가 연결되어 있고, 입력 A가 결정되지 않아 계산 결과는 아직 표시하지 않아.

화면 상단:

`5와 8 중 무엇을 입력할까?`

### 01:21–01:26 — MUX의 재등장

나레이션: 여기서 앞서 살펴본 멀티플렉서, 즉 MUX를 다시 사용할 수 있습니다.

화면 연출

두 입력선과 ALU 사이의 빈 공간에 MUX 블록이 등장해.

MUX 위쪽 입력에는 5, 아래쪽 입력에는 8을 연결해.

오른쪽의 하나뿐인 출력선을 ALU의 A 입력에 연결해.

5편에서 사용했던 사다리꼴 MUX 기호를 다시 활용하면 시리즈의 연속성이 살아나.

### 01:26–01:31 — 제어 신호가 선택을 결정한다

나레이션: MUX는 여러 입력 중 제어 신호로 지정한 하나를 선택해 출력으로 전달하는 회로입니다.

화면 연출

MUX 아래쪽에 주황색 `Select` 제어선을 추가해.

설명용으로 다음 선택 규칙을 화면에 짧게 표시해.

`Select = 0 → 5`

`Select = 1 → 8`

선택되지 않은 경로는 회색, 선택된 경로는 초록색으로 강조해.

MUX 선택 동작

5 선택8 선택

선택 신호의 값에 따라 출력으로 연결되는 입력이 달라지는 개념도.

### 01:31–01:37 — 첫 계산과 두 번째 계산 비교

나레이션: 처음에는 숫자 5를 선택하고, 다음 계산에서는 레지스터에 저장된 8을 선택하는 것입니다.

화면 연출

MUX와 ALU를 같은 위치에 고정한 채 두 단계의 계산을 재현해.

첫 번째 단계

- Select=0
- MUX 출력=5
- ALU 입력=5, 3
- ALU 결과=8
- 클럭 에지에서 레지스터에 8 저장

두 번째 단계

- Select=1
- MUX 출력=8
- ALU 입력=8, 2
- ALU 결과=10

첫 번째 계산에서 8을 저장하는 동안 레지스터의 이전 출력이 무엇이었는지와 관계없이, MUX는 초기 입력 5를 선택한 상태로 두면 돼.

그다음 레지스터에 8이 저장된 것을 확인한 후에 Select를 1로 변경해.

장면의 핵심은 ALU가 전혀 바뀌지 않았다는 것이야. 데이터가 지나가는 경로만 달라졌어.

### 01:37–01:42 — 하나의 ALU로 여러 계산

나레이션: 이렇게 하면 ALU 자체를 변경하지 않고도 서로 다른 데이터를 이용해 계산할 수 있습니다.

화면 연출

ALU 블록만 밝은 파란색 테두리로 유지하고, 입력 주변의 MUX 선택 상태를 빠르게 전환해.

`5+3=8`

`8+2=10`

두 계산을 순서대로 보여준 뒤, ALU 아래에 다음 문구를 표시해.

`같은 연산 회로, 다른 데이터`

여기서는 여러 연산을 동시에 수행하는 것처럼 보이지 않게 하고, 서로 다른 시점에 동일한 회로를 재사용한다는 점을 표현해.

# ACT 4. 여러 값을 저장하고 선택하는 구조

01:42–02:07 · 저장 장소가 여러 개 필요하다는 사실을 발견하고 읽기와 쓰기를 구분한다.

### 01:42–01:47 — 저장 공간 하나로 충분할까?

나레이션: 하지만 실제 계산에서는 하나의 값만 저장하는 것으로 충분하지 않을 수 있습니다.

화면 연출

앞 장면의 ALU와 MUX를 축소하고, 중앙에 하나의 레지스터를 크게 표시해.

레지스터 안에는 8이 저장되어 있어.

위쪽에는 5, 3, 8이라는 세 숫자가 나타나.

세 숫자가 하나의 레지스터로 들어가려고 하지만, 한 시점에 한 값만 보관하는 현재 구조에서는 세 값을 모두 동시에 보관할 수 없어.

이 문제를 표현할 때는 저장 블록 안의 값이 5→3→8로 차례대로 바뀌고 이전 값이 사라지는 장면을 사용하면 좋아.

### 01:47–01:52 — 여러 레지스터가 필요하다

나레이션: 5와 3, 그리고 계산 결과인 8을 동시에 보관하려면 여러 레지스터가 필요합니다.

화면 연출

하나의 레지스터 옆에 두 개의 레지스터를 더 배치해.

각 레지스터에 서로 다른 값을 저장해.

서로 다른 값을 보관하는 레지스터

R1

# 5

0101

R2

# 3

0011

R3

# 8

1000

각 레지스터는 내부적으로 여러 비트의 저장 요소를 포함한다는 점을 간단하게 암시해.

### 01:52–01:58 — 어디서 읽고 어디에 쓸까?

나레이션: 이때 어느 레지스터의 값을 읽고, 계산 결과를 어느 레지스터에 기록할지도 결정해야 합니다.

화면 연출

화면 왼쪽에 R1, R2, R3를 세로로 배치하고 오른쪽에 ALU를 배치해.

먼저 R1과 R2의 출력 경로를 강조해 ALU로 전달해.

그다음 ALU의 출력 8에서 R3 방향으로 돌아가는 쓰기 경로를 강조해.

하단에는 다음 두 개의 단어가 차례로 등장해.

`Read — 저장된 값 가져오기`

`Write — 계산 결과 기록하기`

여기서는 읽기 동작이 레지스터의 값을 지우거나 이동시키는 것처럼 표현하면 안 돼.

읽기는 저장된 값을 외부 회로에서 이용하는 것이며, 원래 레지스터 값은 그대로 유지돼.

### 01:58–02:07 — 데이터 경로의 완성

나레이션: 이처럼 저장된 데이터를 선택해 연산 회로로 전달하고, 계산 결과를 다시 저장하는 연결 구조를 데이터 경로, 즉 Datapath라고 합니다.

화면 연출

지금까지 만든 여러 레지스터, 입력 선택용 MUX, ALU, 결과 저장 경로를 하나의 화면으로 통합해.

두 입력을 사용하는 ALU이므로, A와 B에 각각 값을 공급할 수 있는 선택 경로 두 개를 명확하게 구성해.

읽기 → 연산 → 쓰기 구조

기능 관계를 보여주는 단순화된 데이터 경로. 실제 구현은 레지스터 파일의 읽기 포트, 쓰기 주소 선택, 쓰기 허용 신호 등에 따라 달라진다.

데이터 경로 전체에 얇은 외곽선이 등장하고 아래에 `Datapath`라는 명칭을 보여줘.

여기서 중요한 것은 계산 장치와 저장 장치가 단순히 나열된 것이 아니라, 실제 데이터가 지나가는 배선과 선택 회로로 연결되어 있다는 점이야.

# ACT 5. 계산·저장·전달의 역할 정리

02:07–02:33 · 전체 회로를 하나의 구조로 완성하고 다음 편의 제어 문제를 제시한다.

### 02:07–02:14 — ALU, 레지스터, 데이터 경로

나레이션: 여기서 중요한 것은 ALU가 계산을 담당하고, 레지스터가 값을 보관하며, 데이터 경로가 이들을 연결한다는 점입니다.

화면 연출

직전의 데이터 경로 도식을 유지한 채 각 부분을 차례대로 강조해.

먼저 ALU가 파란색으로 강조되면서 `계산`이라는 단어가 나타나.

다음에는 레지스터들이 초록색으로 강조되면서 `저장`이 나타나.

마지막으로 MUX와 배선, 쓰기 경로가 주황색으로 강조되면서 `선택과 전달`이 나타나.

세 역할을 설명할 때 전체 회로를 따로 분해하지 말고, 같은 구조 안에서 각 부분이 담당하는 기능을 순서대로 보여줘.

### 02:14–02:19 — 계산 회로와 저장 회로의 통합

나레이션: 이제 우리는 계산하는 회로와 기억하는 회로를 하나의 구조로 연결할 수 있게 되었습니다.

화면 연출

데이터 경로 전체를 화면 중앙에 정렬해.

다음 동작을 짧게 재생해.

1. R1의 5와 R2의 3을 선택
2. ALU에서 5+3=8 계산
3. 쓰기 경로를 통해 R3에 8 저장

이 과정이 끝나면 레지스터 R1=5, R2=3, R3=8을 모두 표시해.

세 레지스터의 저장 상태가 유지되는 모습을 보여주면서, 하나의 계산 시스템이 완성됐다는 느낌을 줘.

### 02:19–02:22 — 아직 해결되지 않은 문제

나레이션: 하지만 아직 한 가지 문제가 남아 있습니다.

화면 연출

완성된 데이터 경로의 각 블록은 그대로 유지해.

다만 지금까지 화면 밖에 있었던 제어 신호들의 입력단을 점선으로 표시해.

MUX의 Select, ALU의 Operation, 레지스터의 Write Enable을 주황색으로 강조해.

그 입력선 끝에는 아직 신호를 공급하는 회로가 없다는 것을 보여줘.

### 02:22–02:28 — 누가 동작을 결정할까?

나레이션: 어떤 값을 선택하고, 어떤 연산을 수행하며, 결과를 어디에 저장할지는 누가 결정하는 걸까요?

화면 연출

화면에 세 가지 제어 지점을 하나씩 크게 보여줘.

| 제어 대상 | 결정할 내용               |
| ----- | -------------------- |
| MUX   | 어떤 데이터를 ALU에 전달할까?   |
| ALU   | ADD, SUB 등 무엇을 수행할까? |
| 레지스터  | 결과를 어디에 기록할까?        |

각 부분에서 `?`가 나타나고, 마지막에는 세 입력선이 하나의 빈 제어 블록 방향으로 모여.

이때 실제 배선이 제어 블록으로 합쳐지는 것이 아니라, 각 제어 신호가 아직 결정되지 않았다는 사실을 보여주는 설명용 구성으로 표현해.

### 02:28–02:33 — 다음 편, 명령어

나레이션: 다음에는 명령어가 실제 회로의 동작을 어떻게 제어하는지 살펴보겠습니다.

화면 연출

## 구현할 때 꼭 지켜야 하는 세 가지

1\. 4비트 표현을 끝까지 일관되게 유지하기

영상에서 사용할 값은 모두 4비트로 표현할 수 있어.

| 십진수 | 4비트 이진수 |
| --- | ------- |
| 2   | `0010`  |
| 3   | `0011`  |
| 5   | `0101`  |
| 8   | `1000`  |
| 10  | `1010`  |

따라서 4비트 레지스터와 4비트 ALU를 계속 사용해도 모든 예시를 표현할 수 있어.

2\. MUX를 연결할 때 입력선이 물리적으로 바뀌는 것처럼 보이지 않기

MUX의 두 입력선은 처음부터 모두 연결되어 있어. Select 신호에 따라 어느 입력이 출력에 반영되는지가 달라지는 거야.

따라서 5의 배선을 제거하고 8의 배선을 새로 만드는 애니메이션보다는, 두 배선은 유지하고 선택된 경로의 색상만 바꾸는 방식이 정확해.

3\. 레지스터의 읽기와 쓰기를 구분하기

레지스터에서 값을 읽는다고 저장된 값이 사라지지는 않아.

반면 값을 쓰려면 해당 레지스터의 저장 상태를 갱신해야 해. 이번 영상에서는 7편에서 배운 클럭과 저장 시점 개념을 간단하게 재사용하면 돼.
