지금까지 GPU의 레지스터, 공유 메모리, 전역 메모리를 살펴봤습니다.
그런데 여기에 엘원 캐시와 엘투 캐시까지 등장한다면, 이들은 어느 메모리에 속하는 것일까요?
이 질문에 답하려면 먼저 두 가지 개념을 구분해야 합니다.
하나는 프로그램이 데이터를 저장하고 접근하는 메모리 공간이고, 다른 하나는 데이터 접근을 효율적으로 처리하는 하드웨어 캐시입니다.

레지스터는 개별 스레드의 계산값을 보관하고, 공유 메모리는 같은 블록의 스레드들이 데이터를 공유하는 공간입니다.
전역 메모리는 GPU의 여러 에스엠과 블록에서 접근할 수 있는 대용량 메모리 공간입니다.

그렇다면 엘원과 엘투 캐시는 무엇일까요?
이들은 전역 메모리에 포함되는 별도의 주소 공간이 아니라, 메모리 접근 과정에서 데이터를 임시로 보관하고 재사용하는 하드웨어 캐시입니다.

먼저 GPU의 전체 구조를 살펴보겠습니다.
일반적인 엔비디아 GPU에서는 각 에스엠에 가까운 위치에 엘원 캐시가 존재합니다.
반면 엘투 캐시는 여러 에스엠이 함께 사용하는 공유 캐시입니다.

실제 쿠다 코드를 살펴보겠습니다.
스레드가 전역 메모리의 배열 A에서 하나의 값을 읽는다고 생각해 보겠습니다.

이 데이터가 엘원 캐시에 존재한다면, 더 먼 메모리까지 접근하지 않고 값을 가져올 수 있습니다.
이를 캐시 히트라고 합니다.

반대로 데이터가 없다면 캐시 미스가 발생하고, 요청은 다음 메모리 계층으로 전달될 수 있습니다.
엘투 캐시에 데이터가 있다면 그곳에서 가져오고, 엘투에도 없다면 디바이스 디램에 접근해야 할 수 있습니다.

다만 모든 전역 메모리 요청이 반드시 엘원 캐시를 거치는 것은 아닙니다.
실제 접근 경로는 명령과 캐시 정책에 따라 달라질 수 있습니다.

그렇다면 공유 메모리와 엘원 캐시는 어떤 관계일까요?
여기서 흥미로운 하드웨어 구조가 등장합니다.
일부 엔비디아 GPU에서는 공유 메모리와 엘원 캐시가 같은 온칩 메모리 자원을 나누어 사용합니다.

하지만 물리적 자원을 공유한다고 해서 같은 메모리 공간인 것은 아닙니다.
공유 메모리는 쿠다 코드에서 데이터를 명시적으로 저장하고 관리하며, 같은 블록의 스레드들이 함께 사용합니다.

반면 엘원 캐시는 일반적으로 하드웨어가 데이터의 보관과 교체를 관리합니다.
즉, 공유 메모리와 엘원 캐시는 물리적으로 가까이 있거나 자원을 공유할 수 있지만, 데이터에 접근하고 관리하는 방식은 서로 다릅니다.

엘투 캐시도 마찬가지로 공유 메모리나 전역 메모리의 일부 주소 공간이 아닙니다.
여러 에스엠에서 발생하는 메모리 요청을 처리하고, 데이터를 재사용하도록 지원하는 별도의 하드웨어 계층입니다.

결국 레지스터, 공유 메모리, 전역 메모리는 데이터가 어떤 공간에 저장되고 누가 접근할 수 있는지를 설명합니다.
반면 엘원과 엘투 캐시는 메모리의 데이터를 실제로 어디에서 가져오고 재사용할 수 있는지를 설명합니다.

GPU의 메모리 계층을 이해하려면 단순히 저장 공간을 크기순으로 나열하는 것이 아니라, 논리적인 메모리 공간과 실제 하드웨어의 데이터 접근 경로를 함께 살펴봐야 합니다.
